# ImageWorkbench · 生图工作台

Windows x64 便携桌面应用，采用 Wails v2、React、Go、SQLite。Base URL、API Key 和模型均在应用内配置；幻灵只是调研样例，不是固定供应商。

## 使用

1. 完整解压 `release/ImageWorkbench-portable-x64-0.7.9.zip`，保留 EXE 同级的 `runtime`、`agent` 目录和 `product-browser.exe`。
2. 双击 `ImageWorkbench.exe`，打开“连接与设置”，分别添加生图连接与 LLM 连接。
3. 填写 API 前缀地址（例如 `https://example.com/v1`）、API Key 和默认模型 ID。测试连接只查询模型，不提交付费生成。
4. 在工作台选择连接，填写提示词。添加参考图后使用图生图；批量模式每行是一条提示词。
5. 生成结果自动保存在素材库，通过“导出原图”选择保存位置。点“批量管理”可多选图片，一次导出为 ZIP 或从素材库移除。
6. “中转站监控”和“LLM 监控”分别统计每次生图请求发往的中转站、每次 LLM 请求的用时、tokens 和连接中断，调用记录可导出 CSV 核对计费。
7. 给客户交付时使用管理员工具（`scripts\build-admin.ps1` 生成 `release\admin\ImageWorkbenchAdmin.exe`，只在提供方电脑上运行）：管理客户、软件标识、激活码和 Key 池，一键生成带签名 `customer.dat` 的客户交付包，并记录交付、换 Key 和续费。每位客户必须为图片线路 1、至少一条备用图片线路（2–6 任选）和 LLM 线路 1 分配 Key，其余线路可选，留空的线路不写入交付包，主线路不可用时只切换到已分配的备用线路。每条线路可以选用任何空闲的同类 Key（主用、备用只是 Key 池里的标签）。客户可以删除：未交付的 Key 回到 Key 池，已交付的 Key 自动停用、不再分给别人；确定交付包没有发出去时，可以在 Key 池点“重新启用”（会提示风险，并标记“曾交付”）。Key 池可以勾选多个 Key 批量停用，或批量删除从未交付过的 Key。请务必在“设置与签名密钥”中导出签名密钥备份。

支持 OpenAI Images 兼容协议：模型查询、JSON 文生图、multipart 图生图，URL/base64 图片结果。中转站必须支持对应协议；自定义专有协议需要单独适配器。模型 ID 可手动填写，尺寸和质量按站点能力填写，`auto` 不发送。首版每批最多 200 个子任务，每条 1–20 张，最多 4 张参考图，每张不超过 32 MB。

数据初始保存在 EXE 同级 `data`，可以在“连接与设置 → 更改保存位置”中选择独立的空文件夹，确认后迁移图片、任务、模板和本机加密密钥。原目录保留，新位置立即生效并记住；“打开数据位置”打开当前目录的资源管理器。任务空闲时才可更改；非空目录不会覆盖。应用目录需可写，以保存目录偏好。

界面缓存位于 `cache`。开发用环境变量 `IMAGEWORKBENCH_DATA_DIR` 优先于保存的目录偏好，普通启动不需要它。目录不可写时应用提供原生目录选择；推荐将整个便携包放在可写本地目录。

密钥使用当前 Windows 用户 DPAPI 加密。复制整个包到不同电脑或用户后，需要重新输入 Key。备份排除密钥、缓存与临时结果链接；恢复前保留旧数据目录。尚未提交的恢复任务需要补充密钥并手动恢复。素材“移除”是隐藏，保留文件和任务引用。

关闭时有活动任务会提示；最小化继续执行。超时或服务 5xx 时，生成可能已经计费，任务标记结果未知并自动重新生成一次（优先用备用中转站，可能产生两次费用，每张最多一次）；应用在提交中退出造成的结果未知不会自动重发。已返回但没保存成功的图片在 30 秒、2 分钟、5 分钟后自动补下载，不会再次生成。生图模型的内容审核拒绝某张图时，先原样自动重发一次，仍被拒再由 LLM 改写这张图的措辞（画面文字逐字保留）后重发一次；被拒的请求没有生成，一般不计费。

首版支持 Windows 10/11 x64 本地目录，完整包随附固定 WebView2（解压后运行时超过 250 MB）。未对网络共享路径提供支持。应用及运行时以完整包更新，保留 data；运行时不在后台自动更新。

## 智能生图与 Skills

内置Claude Code 2.1.296。设置中分别配置生图连接与LLM供应商（Anthropic Messages兼容接口），验证必要能力。智能生图输入完整制作指令、商品链接和参考素材，默认12张、1:1；连接、模型与参数在“更多设置”中记住选择。点击“开始生成套图”即授权本次LLM和生图请求，可能产生费用。

商品分析与套图提示词由后台处理，客户仅查看制作进度、必要的补充资料、图片及下载。缺少商品原图、尺寸、色卡、名字或P004等必要资料时集中补充，全部齐全后自动生成整套，无需编辑或确认方案。商品网站拦截直接请求时，应用用随包浏览器（`product-browser.exe`）在后台读取页面；遇到无法自动通过的人机验证会弹出窗口，请手动完成一次。浏览器 Cookie 保存在数据目录的 `product-browser` 文件夹，不进入备份，可在设置中清除。仍读取不到时可上传参考图或粘贴商品描述，完整错误在日志中。套图图片可点开原图大图逐张检视（键盘 ← → 切换、实际大小查看细节）；已完成的套图可逐张“优化”：填写调整说明后，先由 LLM 把这张图原来的制作要求改成与修改一致，再以该图为底图重新生成（新的计费请求），旧版本保留，整套下载只含当前版本；智能生图的套图不出现在生图工作台的“最近生成”。“更多设置 → 同时生成张数”控制并行生成的请求数（1–4，默认3），生成中可随时调整，对生图工作台同样生效。“连接与设置”可把一个生图中转站设为主用、其他设为备用：应用免费检查健康状态（只读模型列表），主用变慢或不可用时把未发送的图片转到模型相同的备用（不额外计费）；结果未知的图片自动重新生成一次，可能重复计费。仅实际需要的资料必须补充，可选字体参考不会强制索取。智能生图页“新建需求”旁可切换“手动 / 自动”：手动模式按上面的方式提问补充；自动模式同样找出缺的资料，但由制作助手按指令、原链接、可选范围和你最近 10 个手动回答的习惯逐题自己回答，推不出的标“需核对”，页面列出每题的判断依据，直接生成整套。

Skills在设置中启停、导入和编辑，运行冻结启用的版本，只支持指令和素材。内置“生图提示词写法”（英文技能，界面仍为中文）规定每张提示词分行写用途、参考图作用和逐字文字，与其他技能冲突时让位；备份保留资料与内部方案，排除密钥和Claude缓存。取消、异常退出或恢复后不自动重新分析/发起计费请求，尚未提交的自动套图图片需要明确恢复；结果未知自动重新生成一次，补下载不再次生图。旧未提交需求点击“继续制作”才进入新流程，已有批次不重复创建。详见[更新记录](docs/CHANGELOG.md)（0.3.1 起累加记录）与[0.3.0更新说明](docs/changelog-0.3.0.md)。

升级先关闭旧版并备份；完整解压升级包覆盖程序与运行组件时保留data、data-location.txt和自选数据目录。

### 本机开发版本保留连接配置

截至 2026-10-15，用户已在 Portable 0.3.0 配置好生图中转站与 LLM 供应商。**后续开发和交付的本机版本必须沿用这两个连接及其模型设置、加密 API Key，无需用户每次升级重新配置。** 当前已完成配置位置登记与本机快照保存：

| 内容 | 本工作区位置 |
|---|---|
| 已配置的应用目录 | `release/ImageWorkbench-0.3.0` |
| 当前实际数据目录 | `release/ImageWorkbench-0.3.0/data` |
| 数据库与加密密钥 | 数据目录内的 `app.db` 与 `secrets/`，须一起保留 |
| 后续构建使用的本机记录 | `.local/profile-source.txt` |
| 初始配置快照 | `.local/profile-backups/20261015-172343/` |

初始快照已校验数据库完整性和两个加密密钥文件的副本一致性，仅用于本机连接配置应急保留，不是包含图片、参考素材和 Skills 文件的完整备份。后续配置修改以实际数据目录为准。在同一台电脑、同一 Windows 用户下，新版复用原有加密凭证；换电脑或 Windows 用户仍需重新输入 Key。密钥明文不得写入 README、源码或发布包。

此工作区可通过 `scripts/remember-profile.ps1 -ApplicationDirectory 'release\ImageWorkbench-0.3.0'` 记住已配置的应用目录。记录只写入被 Git 忽略的 `.local/profile-source.txt`，不保存明文密钥。随后 `scripts/build.ps1 -Version '新版本号'` 自动创建对应版本目录，并在本机构建目录写入 `data-location.txt`，沿用原有数据库和 Windows 加密密钥。两个连接、模型、能力验证、Skills 与后续配置修改一起保留；无需每个版本重新填写。

构建会跟随上一次构建目录中的数据位置偏好，因此在应用内“更改保存位置”后，下次构建也沿用迁移后的目录。原数据目录必须保留；如果要删除旧程序文件夹，先在应用内把数据迁移到独立目录。新旧版本共用数据，应关闭旧版再打开新版；未来数据库升级后不要用旧版回写同一份数据。目标版本已有另一份数据时，构建会停止，避免切错配置。

发布 ZIP 始终只包含程序、运行组件和说明，不包含 `.local`、数据库、密钥及本机 `data-location.txt`。直接解压 ZIP 到全新位置仍是干净版本；本机使用脚本构建后的 `release\ImageWorkbench-版本号\ImageWorkbench.exe` 即可继承配置，手动升级则覆盖原程序目录并保留数据。`-NoLocalProfile` 可关闭本次构建的自动关联（不清除目标目录已有配置）。普通应用备份仍排除密钥，不能用于跨用户免输入密钥。

后续修改此流程时运行 `scripts/test-local-profile.ps1`，验证跨版本沿用配置、跟随数据目录迁移、保护已有配置，以及发布 ZIP 排除个人数据。桌面 QA 使用隔离数据目录，不能回写用户实际配置。更多维护约定见[本机配置保留说明](docs/local-development-profile.md)。

## 开发与构建

开发机需 Node、pnpm、Go 和 Wails CLI。构建脚本优先使用 PATH 工具，亦支持此工作区 `.tools/go` 和 `.tools/bin/wails.exe`。Windows 用户端不需要这些工具。

```powershell
pnpm --dir frontend install --frozen-lockfile
pnpm --dir frontend run build
wails dev
# 固定版本 Claude 原生包下载与哈希校验：
.\scripts\prepare-claude.ps1
# 获取并解压微软官方 Fixed Version x64 运行时后：
.\scripts\build.ps1 -RuntimeSource '完整运行时目录'
```

源码中的正式程序通过 Wails 桥接调用 Go；Agent 的连接桥和 MCP 仅监听带临时认证的本机回环地址，无对外业务 HTTP 服务。用于开发调试的 `IMAGEWORKBENCH_ALLOW_SYSTEM_RUNTIME=1` 可使用系统 WebView2；正式便携包不依赖该设置。

验证命令：

```powershell
go test ./...
pnpm --dir frontend run typecheck
pnpm --dir frontend exec prettier --check src
```

`scripts/test-product-browser.ps1` 构建浏览器辅助程序，用本地模拟页面（脚本渲染、重定向、验证页、空白页）测试真实 WebView2 读取，期间会短暂弹出验证窗口；默认的 `go test ./...` 只使用模拟辅助程序。

`scripts/desktop-qa.ps1` 是单独的测试构建：在 `.tools` 内复制 WebView2 Go 依赖，并仅在该构建中添加本机调试端口 9223；正式 go.mod 与发布包不包含此修改。QA 构建同时生成浏览器辅助程序，并允许读取本机模拟商品页。该测试实例与发布版使用独立单实例标识，启动此脚本，再执行 `pnpm --dir frontend run test:e2e`。测试使用本机模拟服务与隔离数据目录，不调用真实中转站。

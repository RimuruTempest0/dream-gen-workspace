## 0.7.1 · 商品页打不开时自动重试并沿用上次读取；去掉“制作详情显示”设置

### 商品页读取
11/03 17:08 那次 Etsy 制作（链接 4572492836）没读到商品页，要求上传参考图；同一链接当天 14:06 却读成功了。原因是那一刻网络（或代理）连不上 Etsy：直连请求失败，浏览器也打不开，只显示了自己的“无法访问此页面”。应用把这个错误页当成商品页交了回来，又因为它不是 http/https 地址，报成了“页面跳转到不受支持的地址”。
- 浏览器打不开商品页（没有收到网站任何响应）时，自动在 3 秒、6 秒后重新打开，最多 3 次，日志里记“第 N 次重新打开”。网站返回的 403 验证页不算打不开，照旧等验证通过。
- 浏览器的错误页不再当成商品页。完全连不上时约 10 秒就报“浏览器也打不开商品页（网络连接失败，已重试 3 次）”，以前要干等 3 分钟才超时。
- 仍读不到时，沿用 7 天内其他制作读到的同一链接商品资料和仍在素材库里的商品图，不再要求上传参考图；运行详情里会写明沿用了哪次读取。
- 失败说明的措辞修正：以前是“直连直连请求失败”，现在是“直连请求失败”“直连返回 HTTP 403”。

### 运行详情
- 去掉“连接与设置 → 制作详情显示”（详细 / 简洁）。运行详情一直显示在制作进度里，明细默认收起，点“运行详情”才展开。

### 验证
- 真实 WebView2 浏览器测试：连接被断开 2.5 秒后自动重新打开并读到商品；403 验证页不重新打开；完全连不上的地址约 9 秒报网络连接失败；原有的脚本渲染、验证窗口、空白页超时照常通过。
- Go 测试：浏览器错误页报为网络连接失败；读不到时沿用 7 天内同一链接的读取结果，只保留仍存在的商品图，不沿用超过 7 天、读取失败或其他链接的结果。
- 桌面测试：设置页不再有“制作详情显示”；制作中运行详情默认收起、点开显示记录，重新进入后仍在且收起。用本地模拟中转站和隔离数据，没有调用真实付费接口。

## 0.6.28 · 内容审核拒绝后自动重发、自动改写措辞

生图模型（如 gpt-image-2.5）的内容审核偶尔会拒绝正常的电商图（HTTP 400，“该提示可能违反了我们的内容政策”）。以前卡片只显示“这张图片尚未完成”，要手动重新生成。现在自动处理。

### 自动处理流程
- 识别内容审核拒绝：HTTP 4xx，且错误里有内容政策、安全系统、moderation、safety system 等字样。API Key 无效、余额不足、限流照旧按原来的方式处理。
- 第一次被拒：原样自动重发一次。内容审核有一定随机性，同样的内容常常重发就能通过。
- 再次被拒：用这次制作的 LLM 线路只改写这张图的措辞（身体、儿童场景、武器或血等颜色名、真实人物、品牌和知名角色等容易误判的说法），商品设计、尺寸数字、参考图作用不变，引号里的画面文字必须逐字保留，否则不发送。改写期间这张图显示“改写提示词”，尚未发送、不计费。
- 改写后仍被拒：不再自动重发，卡片说明原因，提示修改提示词或换掉可能被误判的参考图。手动“重新生成”会重新开始这套自动处理。
- 没有可用的 LLM 线路时，只做原样重发。
- 被拒的请求没有生成图片，一般不计费；改写会用少量 LLM tokens，记在“LLM 监控”的“改写被拒提示词”里。
- 被拒的图片只代表这张图的内容问题，不会把中转站标成不可用，也不会暂停同批其他图片。
- 被自动重发的原图只显示一行灰字“内容审核拒绝了这张图，已自动重发（未生成，一般不计费）”。

### 预防
- “生图提示词写法”技能新增一条：用中性说法，避免容易误判的身体、儿童场景、武器或血等颜色名、真实人物和品牌说法，设计文字照样逐字保留。没改过这个技能的用户会自动升级。

### 验证
- Go 测试：识别各种内容审核拒绝而不误判其他 400/401/429/5xx；原样重发一次后改写再发一次并成功；改写后仍被拒就停止；改写丢了引号里的画面文字时不发送、不计费；没有 LLM 时只原样重发；改写中途退出，重启后继续改写；被拒不计入中转站故障。
- 桌面测试：智能生图里一张图连续两次被拒，自动改写后成功，卡片不出现警告，也不出现“重新生成全部失败图片”。用本地模拟中转站和隔离数据，没有调用真实付费接口。

## 0.6.27 · 下载失败自动补下载，结果未知自动重新生成

以前这两种情况都在图片卡片上显示提醒，要手动点“补下载”或“重新生成”。现在都自动处理，不再提醒。

### 下载失败：自动补下载
- 已收到图片结果但没保存成功时，分别在 30 秒、2 分钟、5 分钟后自动补下载。等待时卡片只显示“下载未完成，N 秒后自动补下载（不会重新生图）”。
- 补下载只重新取回已返回的图片，不会重新生图，也不产生费用。
- 三次都失败才显示“下载失败”，此时仍可点“补下载”或“补下载全部失败图片”。
- 应用启动时，24 小时内没保存成功的图片也会自动补下载。

### 结果未知：自动重新生成一次
- 中转站超时（HTTP 524 等）、断线或 5xx 导致结果未知时，自动重新生成一次，优先转到健康、模型完全相同的备用中转站。没有备用中转站时，在原中转站重新生成；原中转站变慢或不可用时，等它恢复后再发。
- **可能产生两次费用**：原请求可能已在中转站生成并计费。每张最多自动重新生成一次，自动重新生成的图片如果结果仍未知，不会再重发。
- 原来的“524 后自动换中转站重新生成”开关和“每批最多 3 张”的上限已去掉，改为一律自动处理。设置页只保留说明。
- 智能生图卡片直接显示新的一次；生图工作台里原来那张只显示一行“结果未知，已自动重新生成（原请求可能已计费）”。
- 应用在提交过程中退出造成的结果未知，仍不会在启动时自动重发。
- 试用期间同样自动重新生成；原请求计 1 张，重新生成成功再计 1 张。

### 验证
- Go 测试：下载失败后排上自动补下载、等待期间不会提前开始、成功后不重新生图；自动补下载用完后显示下载失败，手动补下载仍可用；重启后只恢复 24 小时内的失败下载；结果未知自动重新生成正好一次，并优先转到备用中转站，原中转站变慢时等它恢复。
- 桌面测试用本地模拟中转站和隔离数据，没有调用真实付费接口。

## 0.6.26 · 精简技能和发给模型的内容，减少 tokens

11/02 那次 Etsy 制作的上下文最高到 106,056 tokens。其中任务上下文发了两遍，约占 30%，技能之间也有大量重复。思考相关的逻辑这次不变。

### 技能
- **每条规则只留一处**：五个内置技能总字数从 22,175 降到 14,190，少了 36%。仍是五个技能，因为 P004 能单独关闭，后台也要靠它的完整内容判断是否附加固定规则。
- **P004 加了姿势表**：站姿、坐姿、多人同框、平铺、袖口特写、背面各有现成写法，模型直接选用，不用每张重新推导。“多人同框时其他人默认站在主角画面左侧”是这次新加的默认做法。
- **检查清单合成一份**：放在“电商套图规划”里，只过一遍，并恢复了“想清楚后直接保存，保存前不要再写长篇分析”。250 字的硬限制没有恢复，以免挤掉必要细节。
- 没有改过的内置技能会自动升级；改过的技能和已开始的制作保持原样。

### 发给模型的内容
- **上下文只发一份**：`get_run_context` 和 `fetch_product` 现在只返回简短状态，不再重复完整内容。
- **去掉用不上的内容**：事件记录、连接信息、商品图片网址和更早的旧方案不再发送。
- **商品资料进入首条提示词**：商品页在 Agent 启动前读好，也修复了首次尝试的提示词里没有商品资料、要靠工具再取一次的问题。
- **技能放在上下文前面**：继续制作时，没有变化的部分更容易命中服务商的缓存。
- **关闭 Claude Code 的内置技能和 Skill 工具**：过去 70 次尝试里 Skill 工具一次都没被调用；关闭后每次请求少发约 6,000 字（code-review、dataviz 这类和做图无关的说明）。

### 预计效果（还没有真实运行数据）
- 同样那次任务，每次请求里的上下文和技能从约 74,700 字降到约 21,400 字，上下文峰值预计从约 10.6 万降到约 8 万 tokens。
- 思考量能否下降要看真实制作：用同样的商品规划一次，在运行详情里比较输出 tokens。

### 验证
- 用真实 Claude Code 配合本地模拟接口确认：Skill 工具和内置技能说明已消失，业务工具调用正常，提示词里每个技能只有一份。
- 全部测试使用隔离数据和模拟接口，没有发起付费调用。

## 0.6.25 · 修复读取商品页超时；模型思考用完上限时自动处理；放宽时间和网络限制

11/02 一次 DeepSeek 官方的制作（Etsy，16 张商品图）中，运行详情显示工具调用失败和 LLM 反复中断。查 Claude Code 自己的记录后确认是下面几个不同的原因。

### “工具调用没有成功”（两种原因）
- **读取商品页超时**：错误内容是 “The operation timed out”，正好 60 秒。Claude Code 给每次工具调用的时间有限，而读取商品页要走浏览器并保存全部图片，这次超过了 60 秒。修复：在 Agent 启动前先读好商品页，工具直接返回已读取的结果，省去一次超时和一次 LLM 请求。
- **方案被截断**：错误内容是 “could not be parsed as JSON”。模型思考用了 93,942 字，只剩很少额度写方案，保存方案的内容写到一半被输出上限截断。Agent 随后改成每批 4 张并成功保存，但白白多等了 3 分 16 秒。修复见下面第 1 点。
- 其他工具失败时，运行详情显示具体原因。

### LLM 反复中断（一连串原因）
1. **模型把输出上限用在思考上**：一次请求输出了 32,768 tokens，全是思考内容（104,574 字），没有写出任何方案，用了 3 分 50 秒。10/27 同类请求的思考最多约 46,000 字。这次的商品图更多（16 张），0.6.21 的新技能也可能有影响，还无法区分。
   - **修复**：单次回复用完输出上限时，本次制作接下来的请求关闭思考，直接写方案；服务方不接受这个设置时自动改回默认再发。规划指令也要求不在思考里逐张起草提示词。商品页图片超过 8 张时只看前 8 张，用户上传的都看。
2. **网络中断**：下一次请求回复到一半被切断（unexpected EOF），接着连续 4 次 “TLS handshake timeout”。这些是本机到服务方之间的网络问题，当时走的是本机代理 127.0.0.1:10808，无法判断是代理还是对方。
   - **修复**：连接握手的等待从 10 秒放宽到 30 秒，运行详情直接写出原因（网络握手超时、连接被切断等）。
3. **10 分钟上限**：网络恢复后的请求本来正常，又被 10 分钟上限切断。
   - **修复**：每次制作的上限放宽到 20 分钟。卡住的请求已有 2 分钟的检测，不会因此多等。

运行详情的回复提示现在区分“模型正在思考”和“模型正在回复”。

### 验证范围
Go 测试：思考用完上限后下一次请求关闭思考，服务方拒绝时去掉该设置重发并记住；第一次请求不改动；商品页在 Agent 启动前读取，工具不再重复读取；失败原因的文字。桌面端到端测试（模拟 LLM、隔离数据）。没有调用真实付费接口。关闭思考的设置没有在真实 DeepSeek 或 PackyCode 上试过，关闭后方案质量是否受影响也未验证，需要实际运行确认；网络中断本身没有解决。

## 0.6.24 · LLM 没有回复时自动改用备用线路；运行详情；可选择显示详细或简洁

### LLM 卡住时不再白等
- **现象**：11/01 晚上多次，LLM 中转站在“写方案”这一步一个字节都没有返回（最长等了 7 分 53 秒），直到 10 分钟上限才中断。同一商品、同样 7 张图片在 10/27 能正常完成，所以不是图片或请求大小的问题。具体原因在中转站一侧、这个 Key 或新版技能与中转站的配合，应用无法判断。
- **修复**：流式请求 2 分钟没有收到任何内容时，停止等待，把这次请求改发到 LLM 线路 2，本次分析剩下的请求都走备用线路；下次继续制作时重新从主线路开始。卡住的请求可能仍被原线路计费，改发会再发送一次输入内容。
- **没有备用线路时**（试用期只用主线路，或没有配置 LLM 线路 2，或它没有通过图片能力验证）：重试一次，仍没有回复就停止，并提示“模型一直没有回复，本次分析已停止。资料已保存，点‘继续制作’即可再试。”
- **中断提示更准确**：区分取消、超过 10 分钟和模型没有回复；只有真的有方案时才说“资料和方案已保存”。之前总是说“已保存资料与方案”。
- **步骤修复**：继续制作时不会重新读取商品页，之前读取商品页、保存商品图显示为未开始，现在显示已完成和张数。

### 运行详情
- 智能生图的进度区新增深色的“运行详情”：Claude Code 的版本和模型、加载的技能、调用的工具（查看参考图、保存方案第几批等）、Agent 的简短说明、每次 LLM 请求的输入输出 tokens、首字时间和用时、重试和线路切换。中断后仍可查看。
- **不显示**提示词、锁定项和技能内容。Agent 自己写的说明会显示，可能偶尔提到规则的名称或片段。这些记录不发给模型，也不含 Key。
- **连接与设置 → 制作详情显示**：详细（默认）或简洁。简洁时只显示制作步骤。

### 验证范围
Go 测试：主线路没有回复时改用备用线路并替换模型名，之后的请求继续走备用线路；试用期不用备用线路；没有备用时重试一次后停止并显示原因；非流式请求不受 2 分钟限制；已开始回复的慢请求不被中断；继续制作时已完成的步骤显示为完成；运行详情不含提示词和 Key，也不发给模型。桌面端到端测试（模拟 LLM、隔离数据）：运行详情内容、简洁模式隐藏详情、设置保存。没有调用真实付费接口；线路切换只用模拟服务测试过，真实中转站的表现需要实际运行确认，这也没有解决中转站本身卡住的原因。

## 0.6.23 · 智能生图显示制作步骤，不再只有“处理中”

- **步骤清单**：分析期间，“制作进度与结果”显示准备素材、读取商品页、保存商品图、分析资料和参考图、规划套图、提交生成，标出已完成和正在进行的步骤。右上角的标签、制作历史和侧边栏提示使用同样的步骤名。
- **每步的细节**：读取方式（直接读取，或网站拦截后改用浏览器及用时）、已保存商品图张数、已查看参考图张数、已写好的套图张数，以及当前这一步的用时。
- 开始或继续制作后页面回到顶部，直接看到步骤。
- **能分辨慢和卡住**：等待模型时显示“等待模型回复（已等 X 秒）”；模型回复时显示“模型正在回复，已收到约 X 字”并持续增加；30 秒没有新内容时显示“模型暂时没有新内容（已等 X 秒）”。
- 不显示百分比或预计时间：模型回复的长短差别很大，估算不可靠。Agent 自己决定顺序，所以可能回到前面的步骤。“已写好 X 张”在每批保存时才变化（每批最多 6 张）。
- 不增加任何模型或生图请求，也不增加费用。步骤记录不发给模型。回复字数只保存在内存里，不写入数据库，也不保存模型回复的内容。0.6.23 之前开始的需求继续后才有步骤。

### 验证范围

## 0.6.21 · 同一个问题再次询问时等待补充；参考素材显示预览图；重整内置技能的细节一致性规则

- **现象**：LLM 能力验证全部通过、所有 LLM 请求都成功，制作仍以“Agent 未保存套图方案，请补充资料或明确继续”失败。

### “优化”对话框的说明
- 说明改为写清要去掉什么、换成什么，并点名是谁或哪个位置，附上实测有效的例子：“右侧女性脱掉米白色针织衫，改穿和左侧同款的卫衣，颜色 Maroon，胸前图案和袖口刺绣与左侧完全相同。”

### 套图细节一致性：重整五个内置技能和规划指令
评估和方案见 `docs/skill-consistency-assessment-2026-11-01.md`。本版只改写规则，没有增加成图检查，不能保证每张图的细节完全一致。
- **固定设计组合**：胸前的标题、图案、配饰，袖口的名字、图标，分别作为一个整体，一次确定字形、弧度、字距、间距、比例、位置和数量，不再每张各排一次。位置按衣服部位（中轴、拉链末端、袖口接缝）描述，与画面位置分开。

## 0.6.17 · 优化袖口时带上样板图，允许放直手臂；坐姿图有刺绣的手不再搭在腿上

## 0.6.14 · 识别 Amazon “Continue shopping”拦截页；验证页不再交给 Agent；商品链接自动清理

外部测试 0.6.13（客户包 IW-8VE7-9FVB-00XN）用 Amazon 链接制作时，补充资料里出现“商品链接打不开（Amazon 返回验证页），请上传……实拍图”。

- **原因**：Amazon 对这次直连请求返回了“Click the button below to continue shopping”拦截页，而不是商品页。应用只认识 Cloudflare、DataDome、PerimeterX 和 Walmart 的验证页，把这个页面当成正常商品页保存（标题“Amazon.com”、没有图片），也没有改用浏览器读取。Agent 看到的商品资料只有这个页面，于是要求上传实拍图。另外，指令里的链接写成“【https://…th=1】”时，商品链接框带上了末尾的“】”；手机版分享链接（/gp/aw/d/）还带着十几个搜索和跟踪参数。
- **识别拦截页**：直连读取和浏览器读取都会识别 Amazon 的“Continue shopping”页和字符验证码页（按页面表单和页面文字两种方式判断）。直连遇到时改用浏览器读取；浏览器里也遇到时，20 秒后弹出窗口，点一下“Continue shopping”即可继续。
- **验证页不再交给 Agent**：浏览器读到的仍是验证页时（例如没有点按钮），这次读取按失败处理，显示黄色“暂时无法读取商品链接”，提示上传图片或粘贴商品描述，不会再把验证页的文字当成商品资料。之前保存了拦截页的需求，点“继续制作”时会重新读取商品页。
- **链接清理**：商品链接在“【】「」（）《》”等全角括号和标点处截断（商品链接框与后台一致）。Amazon 商品链接（/dp/、/gp/product/、手机版 /gp/aw/d/）自动简化为 `https://www.amazon.<站点>/dp/商品编号`，去掉搜索和跟踪参数，手机版改为桌面版页面；其他网站的链接保持原样。

### 验证范围
自动测试覆盖：Amazon 拦截页（含页面表单的和只有文字的）会改用浏览器读取；浏览器也返回拦截页时按读取失败处理，标题、描述和图片都不保留；0.6.13 保存的拦截页在继续制作时重新读取；链接清理（这次的手机版链接、带标题的 /dp/ 链接、m. 和 smile. 站点、非商品页和其他网站保持原样）。浏览器辅助程序的验证页识别规则已更新，没有在真实 Amazon 拦截页上验证弹窗流程（拦截页不能稳定复现）；没有调用真实付费生图或 LLM。

## 0.6.13 · 袖口文字摆正不倾斜；整件衣服的图都照样板画袖口；线色图不再多出衣服

根据 0.6.12 外部测试套图（狗狗头像四分之一拉链卫衣，12 张 + 1 次优化）逐张核对提示词、参考图和成品后修复。Agent 这次严格按 0.6.12 的规则写了提示词（每张袖口句逐字相同、1 张样板图、4 张照样板画），问题出在规则本身和后台附加的内容。

### 袖口文字变斜（新问题）
- **原因一：P004 规则要求文字跟着袖子斜。** 后台附加在每张提示词末尾的 P004 固定规则写着“文字基线与该袖口接缝线平行并随袖口角度倾斜”，P004 技能还写着“袖子斜放时文字跟着袖口线一起斜，不单独摆正成画面水平”，而指令要求“位置摆正居中”。平铺图里袖子总有角度，文字就跟着斜了。
- **原因二：样板图本身是斜的。** 样板图的提示词要求只拍袖口特写，但它唯一的参考图是整件折叠卫衣的原商品图，生图模型照着画成了整件折叠卫衣、袖子斜放、文字倾斜；照样板画的 4 张又复制了这个斜度。
- **修复**：P004 改为“这只袖子在画面里竖直向下、袖口接缝水平，文字与接缝平行，图标和文字在画面中水平摆正、不倾斜”（后台固定规则和技能同时修改）。样板图提示词开头由后台加一句“只拍局部近景特写，袖子竖直、文字水平摆正，不画整件衣服，也不照参考图画整件衣服”；技能要求样板图不放整件衣服的参考图。

### 图标有的在上、有的在左
- **原因**：尺寸图、颜色总览图的提示词写着“袖子折到衣身后方、袖口不在画面内”，线色图写着“画面里没有衣服”，所以这些图没有写袖口句，也没有照样板画。但后台在每张提示词后面都附加了整件衣服的统一锁定项和 P004 袖口规则，生图模型照样画出了整件卫衣和袖口刺绣，排列只能靠猜：线色图里多出了一件卫衣，狗掌跑到了名字上方。
- **修复**：只要画面里出现整件衣服（平铺、挂拍、穿着、尺寸图、颜色图、礼盒里的整件），就一律当作看得见袖口：写袖口句并照样板画；不再用“袖子折到后方”去藏袖口。画面里完全没有商品的图（线色卡、布样、字体样张）由 Agent 标为“无商品”，后台不再附加统一锁定项和商品规则，只保留“整张清晰”这一条。

### 优化后看起来没变
- 0.6.12 的修复让修改要求排在最前面并优先执行，这次确实重新生成了，袖口位置有细微变化，但没有改到想要的样子。原因：
  1. 原图制作要求里的 P004 规则和锁定项都写着“随袖口角度倾斜”，等于告诉模型现在的斜度就是对的，和“摆正”的要求直接冲突；原图要求里还写着“画面里没有名字和狗掌”，与原图实际不符。
  2. “袖口处标识应该和袖子平行”有两种理解：文字顺着袖子长度方向写，或者文字与袖口边平行。模型无法判断是哪一种，只做了很小的调整。
  3. 名字和狗掌只占整张图很小一块，生图接口会重画整张图，小细节很难被精确改动。
- **修复**：优化旧图片时，原图要求里的“随袖口角度倾斜”自动替换为“图标和文字在画面中水平摆正、不倾斜”。“优化”框的示例改为“把袖口的狗掌和 Amelia 摆正成水平的一行，狗掌在左”，写清改成什么样更容易改对。小细节仍可能改不到位；改不到位时，新版本重新制作整套的效果会比反复优化好。

### 验证范围
自动测试覆盖：P004 固定规则和所有内置技能不再要求文字随袖子倾斜；优化旧图片时倾斜说法被替换；无商品图片不附加锁定项和袖口规则、只保留清晰度规则；样板图提示词带有局部特写说明；无商品图片不能做样板图或照样板画；0.6.12 的三个技能副本自动升级，P004 旧副本仍附加固定规则。没有调用真实付费生图，效果需要在新一套图中确认；之前保存的方案不受影响，请用新版本重新制作。

## 0.6.12 · 细节样板图：先生成袖口特写，其他图片照它画

0.6.11 让每张提示词用同一句话描述袖口，但生图模型仍是各自照文字理解；它照参考图画要准得多，而用户的参考图里往往还没有新做的袖口。本版让一套图先生成一张“细节样板图”，再交给其他图片照着画。

- **怎么工作**：套图里有小而重复的细节（袖口名字和图标、小标签等）出现在 3 张以上时，Agent 选一张这组细节最清楚的图（通常是袖口特写）作为样板。后台先生成样板图，完成后把它加为其他看得见这组细节的图片的最后一张参考图，并在提示词开头说明“照样板画排列、顺序、方向、字体、颜色和大小，不照它的构图、背景和姿势”。看不见这组细节的图片不等待，照常同时生成。
- **费用**：样板图本身就是套图中的一张，不额外生成。其他图片仍是每张一次生图请求，只是多带一张参考图；部分中转站按参考图张数加收少量费用，请以中转站价格为准。
- **时间**：照样板画的图片要等样板图完成后才开始，整套通常多等约 30–60 秒。等待期间这些图片未提交、不计费，卡片显示“等待样板图”和“等第 N 张样板图完成后开始”；完成后显示“已照第 N 张样板图画袖口等细节”。
- **样板图失败时**：照样板画的图片不再等待，按文字说明照常生成，卡片注明“样板图没有成功，这张按文字说明生成”；提示词里不会出现样板图的说明。样板图被暂停时，其他图片继续等待，恢复样板图后自动继续。
- **技能更新**：“电商套图规划”和“生图提示词写法”加入样板图的选择和写法（整套最多一张；照样板画的图片最多选 3 张参考图，第 4 张留给样板图）。未修改过的技能升级时自动更新。
- 之前保存的方案没有样板图，行为不变。

### 验证范围
自动测试覆盖：照样板画的图片在样板图完成之后才提交，且收到样板图作为最后一张参考图和提示词说明；无关图片不等待；样板图失败时其他图片不带样板照常生成；方案校验（最多一张样板图、样板图不能照自己画、没有样板图时不能标 useSample、照样板画的图片最多 3 张参考图）；提交套图时任务正确关联样板图；0.6.11 的技能副本自动升级。前端类型检查通过；没有做桌面界面截图验证，没有调用真实付费生图。

## 0.6.11 · 袖口名字和图标在整套图里排列一致；“优化”能真正改动图片

### 优化不起作用的修复
问题：对一张颜色总览图点“优化”，写“袖子处的图标和文字应该是左右排列”，新图和原图几乎一模一样（确实重新生成了一次，只是没有改）。原因有三：
- 优化请求开头固定写着“其余内容保持完全一致：……文字方向与排列……都不要变化”，正好禁止了这次要改的内容；生图模型照着这句保留了原样。“优化”框里原来的示例“袖口名字改成横排”也会被同一句挡住。
- 优化请求后面附着原图的完整制作要求，里面描述的还是原来的样子，比一句修改要求长得多，且没有说明二者冲突时听谁的。
- “应该是左右排列”是判断，不是具体动作，生图模型不确定该改哪里。

修复：修改要求放在最前面，标明“必须做到，改完后要能明显看出变化”，并说明它优先于原图现状和原图制作要求；需要保持不变的清单不再包含“文字方向与排列”，且只适用于修改没涉及的部分。“优化”框的示例和提示改为写清改哪里、改成什么，例如“把袖口的狗掌移到名字 Amelia 左边，两者排成一行”。之前优化过的图片再次优化时，旧格式的说明也能正确去掉，不会层层嵌套。

### 袖口名字和图标在整套图里排列一致
问题：同一套 12 张图里，袖口的狗掌和名字有的左右并排、有的上下叠放；名字有的横着、有的竖着。原因：
- 每张提示词只写了“从左到右依次是狗掌、Amelia”，没写同行还是叠放，也没写文字在画面里的方向；袖口元素面积小，后面很长的锁定项里的写法常被忽略。
- 规格写的是“文字与袖口接缝平行”，但各图手臂姿势不同（下垂、横放在桌上），同一句话在画面里就成了横排或竖排。
- 颜色总览图写着“袖口不显示名字”，画面却是整件平铺、袖口完整可见，生图模型照样画了袖口刺绣，排列也是随机的。

以下内置技能更新（未修改过的自动升级）：
- **电商套图规划**：新增“袖口句”。写好锁定项后定一句话，写清哪只袖子、同行还是叠放、左右顺序、文字在画面里的方向，在每张看得见袖口的提示词里逐字复制。看得见袖口刺绣的图里，有刺绣的前臂在画面中竖直（自然下垂或举杯时竖起），不横放在桌上、不抱在胸前；平铺时袖子顺着衣身垂下。看得见袖口就必须按袖口句画，不再写“袖口不显示”；真不想展示时用构图让袖口确实不在画面内。颜色叠放图改为“袖子折到衣身下面，袖口不在画面内”。
- **P004 生图规则**：袖口小图标一节加入袖口句和姿势要求。
- **生图提示词写法**：新增小元素组的固定句、姿势和“看得见就不能写隐藏”三条规则，并加入保存前检查。
- Agent 基本说明也加入袖口句要求。

### 验证范围
自动测试覆盖：优化请求中修改要求在原图要求之前、带有优先说明、不再包含“文字方向与排列”；旧格式的优化说明能被去掉；0.6.10 的三个技能副本未修改时自动升级，P004 旧副本仍附加项目固定规则。没有调用真实付费生图，效果需要在实际套图中确认。

## 0.6.3 · 试用与正式使用同一套 Key，额度由上游兜底

按新的决定调整客户版：不再单独准备试用 Key，试用和正式使用是同一套 Key。真正控制花费的是每个 Key 在上游后台的额度——交付时设为试用额度，收款后由你调高；软件里的计数器和激活码负责显示和拦截。没有自有服务器时，软件端的计数无法做到绝对不被破解，所以额度必须在上游设好。

**客户软件**
- **试用只用主线路**：试用期只使用图片线路 1 和 LLM 线路 1，不切换到备用线路；输入激活码后启用全部线路和主备切换。
- **计数不能靠重装重置**：试用张数除了记在数据目录，还用 Windows 加密保存在用户目录和注册表里，按软件标识区分，取最大值。重新安装、换数据目录、删除数据都不会重置试用；记录被改动时直接视为试用结束。
- **以上游额度为准**：如果上游支持（幻灵、1 Route 的 `/v1/usage`，查询不计费），软件每分钟读取一次图片线路 1 的剩余额度并显示；上游额度用完时，即使本地计数还有剩余也停止试用。中转站拒绝请求（额度用完）时，提示“试用额度已用完，请输入激活码”，同批未发送的图片暂停。
- **激活码离线校验**：`customer.dat` 只保存激活码的校验值（25 位随机码，无法反推或猜出），输入正确的码才能进入正式使用。激活状态同样保存在用户目录和注册表，同一台电脑换数据目录或升级后无需重新输入；激活状态会用保存的激活码重新校验，单独复制激活标记无效。
- 授权页显示试用线路的上游剩余额度，并说明重装不会重置试用。

**管理员工具**
- 每位客户 8 条线路：图片主用 3、备用 3，LLM 主用 1、备用 1。5 位客户共 40 个 Key，不再需要试用 Key。
- 客户页新增“交付与收款”：交付前把各 Key 额度设为试用额度（图片线路 1 约“试用张数 + 2”张图的金额、LLM 线路 1 少量，其余设为最低）；收款后在上游调高额度，点“已收款并调高额度”记录下来，再发激活码。客户列表显示“试用中 / 已收款”。
- 上游新增“剩余额度查询地址”（Sub2API 默认为 API 地址 + `/usage`；1 Route 需填 `https://api.1route.dev/v1/usage`）。
- 任何线路所在的上游不能单独限额时（如 DeepSeek 官方），Key 池和客户页都会提示：Key 在收款前就随软件包交付，只能靠独立的小额账户或支持单 Key 额度的中转来限制。

**注意**：0.6.2 及之前生成的客户包（旧格式）在 0.6.3 中不再被接受，请用新版管理员工具重新生成交付包。目前还没有向客户交付过，不受影响。

## 0.6.2 · 管理员工具 ImageWorkbenchAdmin.exe（阶段 2）

新增只在你自己电脑上运行的管理员工具，用来管理客户、软件标识、激活码、Key 池，并生成客户交付包。它不会发给客户，构建命令是 `scripts\build-admin.ps1`，生成 `release\admin\ImageWorkbenchAdmin.exe`。数据保存在 `%LOCALAPPDATA%\ImageWorkbenchAdmin`，与客户软件分开。

- **客户台账**：新建客户时自动生成软件标识和 25 位激活码（激活码用 Windows DPAPI 加密保存，可随时查看、复制补发）。记录套餐与有效期、额度备注、试用张数，以及创建、分配、换 Key、交付、续费、备注等全部操作。
- **上游与 Key 池**：先添加上游（图片中转站或 LLM 供应商的地址和模型），再按“试用 / 主用 / 备用”粘贴导入 Key（每行一个）。同一个 Key 按哈希只能导入一次；界面和台账只显示 Key 的后 4 位，Key 本身用 DPAPI 加密。可写额度备注、停用 Key。
- **分配**：每位客户 10 条线路——图片试用 1、主用 3、备用 3，LLM 试用 1、主用 1、备用 1。“自动分配空缺线路”从可用 Key 中挑选，图片主用尽量来自不同上游；一个 Key 只能分给一位客户。备用图片线路的切换顺序可以调整。
- **单 Key 额度提示**：上游可标注能否给单个 Key 设硬额度（幻灵、1 Route 等 Sub2API 可以；DeepSeek 官方不行），并可填写后台地址，Key 列表可一键“打开后台”手动设额度。试用 Key 所在的上游不能单独限额时，导入处、Key 列表和客户页都会提示风险和两种做法（每个软件标识单独开小额账户，或放到支持单 Key 额度的中转后面）。不阻止打包，由你决定。
- **LLM 能力验证**：客户版的智能生图只用验证通过的 LLM 线路。管理工具可以对 LLM Key 运行一次应用自带的能力验证（4 个很短的请求，会产生少量费用，执行前会提示确认）。
- **生成交付包**：一键构建一份不含你本机数据的程序（`build.ps1 -NoLocalProfile`，写入签名公钥），写入签名的 `customer.dat`，打包为 `release\customers\<软件标识>\ImageWorkbench-<客户>-<版本>.zip`。打包后自动检查：包内只有程序文件和 `customer.dat`，没有你本机的连接，也没有这位客户任何 Key 或激活码的明文；不通过就删除 ZIP。交付记录包含版本、时间、线路版本和 SHA-256。
- **换 Key**：在客户页为某条线路选择新 Key。已交付过的旧 Key 永久停用、不会再分给别人；重新生成交付包后线路版本加 1，客户覆盖升级即自动换上，激活码不变。续费、禁用在上游后台操作，管理工具里记下即可。
- **签名密钥**：首次运行自动生成，用 DPAPI 保存。可导出用密码加密的备份、在新电脑上恢复。**请务必备份**：丢失后已交付的客户软件无法再用新包升级。

## 0.6.1 · 识别幻灵、1 Route 的“单个 Key 额度用完”

## 0.6.0 · 客户版：软件标识、试用 20 张与激活码（阶段 1）

为交付给客户做准备。客户软件包在程序旁带一个签名的 `customer.dat`；没有这个文件时（你自己的开发版本）一切与之前相同。

- **软件标识与授权文件**：`customer.dat` 包含软件标识（如 `IW-7K3Q-M9TA-2XRB`）、客户名、试用线路和一个用激活码加密的“正式配置”。文件由管理员密钥签名，被改过或签名不对时显示“软件授权文件无效或已被修改”，并停止生图。
- **激活前试用**：首次启动自动配置试用的图片线路和 LLM 线路（已由提供方验证能力，无需客户操作），默认 20 张。成功生成的图片计入试用；失败、取消和被拒绝的不计入；“结果未知”计入 1 张。左侧显示“试用剩余 N / 20 张”。超出剩余张数的请求不会提交；用完后停止发起新的生图请求，并在工作台和智能生图提示输入激活码。
- **不能靠清除数据重置**：真正的上限是上游给试用 Key 设的额度；额度用完时中转站会拒绝请求，软件提示“试用额度已用完，请输入激活码”（不会再提示充值）。复制或重装同一份软件共享同一个试用额度。
- **激活**：在“连接与设置 → 授权”输入 25 位激活码（大小写、空格和短横线都可以）。激活码只能解开本软件标识的配置：输错或用别的客户的码都会提示“激活码与本软件不匹配”，不需要联网。激活后自动启用专属的图片线路（主用 + 备用）和 LLM 线路，并设好主备切换；试用期间的图片、任务和项目全部保留。
- **保持激活**：激活状态和激活码用 Windows DPAPI 加密保存在数据目录，重启和升级后不用重新输入。升级包里如果带了更新过的线路（例如换了 Key），启动时自动换上。
- **客户看不到 Key**：客户版的“连接与设置”不显示地址和 Key，不能添加、修改或删除线路，只显示“图片线路 1 / 2 …”“LLM 线路 1 / 2”和它们的健康状态。日志、备份和 CSV 导出都不含 Key 和激活码。
- **数据目录保护**：一个数据目录属于哪个软件标识会被记录下来；用另一份软件打开时，不沿用其授权和额度，并说明原因。
- 构建脚本新增 `-LicensePublicKey` 参数，供下一阶段的管理员工具生成客户软件包时写入签名公钥。

下一阶段（管理员工具）会负责：生成软件标识和激活码、管理 50 个 Key（每位客户 LLM 试用/主/备 3 个、图片试用 1 个和主备各 3 个）、签名并打包 `customer.dat`、记录交付和续费。

## 0.5.6 · 中转站余额不足不再误报为“API Key 无效”

问题：1route 等中转站在账户余额不足时返回 HTTP 403（内容为 “insufficient balance”），应用把所有 401/403 都当成 API Key 无效，提示重新输入密钥，并暂停同批图片。Key 其实没有问题，重新输入也没用。

- **分开识别**：中转站拒绝生图时，返回内容含有余额不足、额度用完、欠费等说法（如 insufficient balance、insufficient_quota、余额不足，或 HTTP 402，以及额度用完时的 429）的，提示“中转站账户余额不足，中转站拒绝了请求，未生成也不计费。请到中转站后台充值后重新生成”，并说明 API Key 不需要重新输入。其他 401/403 仍提示 API Key 无效。智能生图页面相应显示“生图中转站账户余额不足”。以前版本里这类图片的卡片也会改为余额不足的提示。
- **配合备用中转站**：设置了主用/备用后，余额不足或 Key 被拒绝的中转站在 10 分钟内标为“不可用”（模型列表检查无法判断余额，所以不靠它恢复）。同批还没发送的图片改发到模型相同、状态正常的备用中转站，不额外计费；没有可用的备用时暂停，未提交、未计费，充值后可恢复生成。未设置主用/备用时，与之前一样暂停同批未提交的图片，只是提示改为充值。
- **中转站监控**：“失败”分别统计余额不足和 API Key 被拒绝，调用记录和 CSV 中注明失败原因。

0.5.5 的安装包已包含以上改动的初版，但当时尚未完成桌面测试；0.5.6 是测试完成的版本。

### 验证范围
自动测试覆盖：余额不足、额度用完与 Key 无效的区分（含 402、429、中文提示）；未设置备用时只发出一张、其余暂停且提示充值；有备用时其余图片改发到备用、主用标为“账户余额不足”；没有备用时暂停且不再发送；监控按原因统计。桌面验证中，模拟中转站返回 403 insufficient balance，卡片和页面提示余额不足、不出现“API Key 无效”，充值后一键重新生成只多发一次请求。没有调用真实付费生图。

## 0.5.5 · 同一套图里图案保持一致

修复：用户改了图案（例如“鹅在喝珍珠奶茶”）时，套图里有的图鹅戴圣诞帽、缠彩灯，有的图没有。原因是每张图都带着原商品的参考图，参考图里还是旧图案（圣诞帽、彩灯串、冬青枝）；方案的锁定项只描述了新图案，没有说明旧图案的这些配饰要去掉，提示词里也只写“不照搬原有图案”。生图模型照参考图画比照文字画更用力，于是每张图各自决定要不要把旧配饰画回来。另外，不同图片的参考图顺序也不一样。

以下三个内置技能更新（未修改过的自动升级，修改过的保持不变）：
- **商品与参考图分析**：用户改图案、款式或工艺时，先写“改款对照表”，把参考图里主图案每个看得见的特征逐项标为保留、去掉或改成。用户没提到的旧特征默认去掉，所有图片一致。
- **Etsy 套图规划**：主图案在锁定项写成两句封闭清单，“图案只包含：……”和“图案里没有：……”，后一句点名参考图里有、新设计去掉的每个特征（例如“鹅不戴圣诞帽，身上没有彩灯串，嘴里没有冬青枝”）。每张提示词用同一个固定短名提到主图案，不在个别图片里换说法或增减细节。看得见主图案的各张图用同一组、同一顺序的参考图；参考图仍是旧设计时，在“参考图”和“避免”行点名不要画的特征。
- **生图提示词写法**：新增“同一图案在每张图里画成一样”一节，内容同上，并加入保存前的检查项。
- Agent 的基本说明也加了同样的要求。

## 0.5.3 · LLM 连接中断后自动恢复时，不再误报“制作未完成”

问题：智能生图显示“制作未完成，资料已保留。可继续制作，详细错误请查看日志。”，但套图其实已经提交、图片正常生成。日志显示，分析期间本机代理（127.0.0.1:10808）断开了一次 LLM 连接；Claude Code 自动重试后完成了方案并提交生图。应用把这次中断记成了需求的错误，之后没有清除，所以一直显示警告。

- LLM 连接中断只记为“连接中断 N 次”和最近一次原因，不再记为错误。分析正常完成时，之前留下的错误会被清除。
- 智能生图页面显示一行提示：“LLM 连接中断一次，已自动重试并继续完成。不影响生图，也不会额外计费。”鼠标悬停可看到中断原因。
- 只有制作真的失败或中断时才显示“制作未完成”警告；如果失败前发生过连接中断，详细错误会注明“LLM 连接中断 N 次，最近一次：……”。
- 旧版本留下的这类误报（需求已提交但仍带着错误）打开时自动改为上述提示。

### 验证范围
自动测试覆盖：连接中断后分析成功时，需求没有错误、记录了 1 次中断；分析失败时错误中注明连接中断；旧需求的误报转为提示，真正的失败保持不变。桌面验证中，模拟 LLM 在分析时断开一次连接，Claude Code 自动重试后 12 张图全部完成，页面显示重试提示且没有“制作未完成”警告。另外修正了桌面测试中的模拟方案，补上 0.5.2 起启用 P004 时必需的袖口说明。没有调用真实付费生图。

## 0.5.2 · 袖口不要设计时，不再出现袖口刺绣

修复：指令要求“袖口不要加任何设计”时，部分图片仍在画面右侧袖口画出小图案。原因是启用 P004 时，后台总会在每张提示词末尾附加“袖口刺绣只在最终画面右侧那只袖子的袖口……”，生图模型把这句当成袖口一定有刺绣，即使方案的锁定项写明两只袖口都是纯色。

- **“P004 生图规则”技能更新**：新增“先判断袖口有没有刺绣”，袖口两条规则只在有袖口刺绣时使用；没有时锁定项和提示词都不描述袖口刺绣的位置或方向。未修改过的技能升级时自动更新，修改过的保持不变（修改过的技能本来就不附加固定规则）。
- 0.5.2 之前保存的方案没有这项说明，仍附加完整规则；需要按新规则出图时，请重新制作。

## 0.5.1 · 生图提示词写法：让每张图更贴合制作要求

借鉴 Codex imagegen 技能里的提示词方法，新增内置技能“生图提示词写法”（image-prompting），并调整“Etsy 套图规划”，让 Agent 写出的每张提示词更容易被生图模型准确执行。技能正文为英文，设置界面里的名称、说明以及向用户的提问仍为中文；保存的提示词仍沿用中文和各技能的固定句子。

- **分行写提示词**：每张按“用途、场景、主体、风格、构图、光线、材质、参考图、画面文字（逐字）、本张变化、约束、避免”分行写，只写需要的行。“用途”写明第几张和图片类型（真实摄影、产品摄影、细节特写、信息图），因为 purpose 字段不会发给生图模型。
- **画面文字逐字**：画面里出现的每个名字和文字都带引号、保留大小写单独列出，客户名字附逐字母拼写，并写明字体、颜色和位置；信息图逐项写出全部尺码数字和颜色名，结尾说明“除以上文字外没有其他文字、标志或水印”。
- **参考图按顺序说明作用**：最关键的参考图放第一张，提示词写明“图1=客户成品图，照它画袖口名字；图2=只取颜色”等，避免模型照搬不相关的背景或排版。
- **不添加没要求的内容**：用户要求详细时只整理不加料；不添加额外人物、道具、品牌、标语、价格或水印，不自行决定左右位置。
- **修改方案只改相关的图**：继续制作中提出修改时，只改涉及的图片和行，其他提示词、锁定项和参考图保持不变。
- **优先级**：P004 等项目规则、刺绣约束、商品分析和套图规划都优先于此技能；在 P004 下不使用任何虚化相关的词。
- 每张提示词的建议长度从约 200 字调整为约 250 字（含分行标签），超过 6 张仍分批保存。
- 升级时，未修改过的“Etsy 套图规划”自动更新，新技能自动加入并启用；修改过的技能保持不变，删除过的内置技能不会恢复。

### 验证范围
自动测试覆盖：新数据目录安装并启用新技能；0.5.0 数据目录升级时加入新技能、未修改的“Etsy 套图规划”自动更新；新技能通过 Skill 格式校验且不含 P004 禁用的虚化词。没有调用真实付费生图，提示词改进对出图效果的影响需要在实际套图中观察。

## 0.5.0 · 多个生图中转站：免费健康检查、自动切换备用、524 自动重新生成（可选）

单一中转站的同步接口经常在约 2 分钟时被 Cloudflare 断开（HTTP 524）。本版支持配置多个中转站，让生图在一家变慢时继续进行。

- **主用与备用**：在“连接与设置 → 生图中转站”中，每个中转站可设为“主用”，或打开“备用”开关并调整顺序。新的生图工作台草稿和智能生图需求默认选择主用中转站；选择框会显示主用/备用和健康状态。
- **免费健康检查**：生图期间每 3 分钟读取一次主用和备用中转站的模型列表（不生成图片、不计费），也可点“立即检查（免费）”。无法连接、HTTP 5xx 或 API Key 被拒绝时标记为“不可用”；最近 15 分钟内出现超时，或最近生成明显变慢（超过 90 秒）时标记为“变慢”。无法读取模型列表的中转站仍可生图，但不会被用作备用。
- **自动把未发送的图片转到备用（默认开启，不额外计费）**：主用变慢或不可用时，还没发送过的图片改用健康的备用中转站。备用中转站的模型列表必须包含完全相同的模型 ID。卡片显示“已从「A」转到「B」· 未发送过，不额外计费”。没有可用备用时，变慢的中转站一次只发一张；不可用的中转站上的图片会暂停（未提交、未计费），可恢复生成。
- **524 后自动换中转站重新生成（默认关闭，可能额外计费）**：开启时会弹出费用提示并需要确认。遇到 HTTP 524 等中转站超时的图片，会在健康、模型相同的备用中转站重新生成一次；没有备用时，等原中转站恢复正常后再重新生成。每张最多自动重新生成 1 次，每批最多 3 张。原请求可能已经计费，因此这些图片可能产生两次费用，卡片和日志都会注明。
- 未设置主用或备用时，生图行为与之前完全相同，也不会进行健康检查。

### 验证范围
用本地模拟中转站和隔离数据验证：免费检查只请求模型列表，从不调用生图接口；未发送的图片转到同模型备用，已超时的图片在默认设置下不会重发；模型 ID 不完全相同的中转站不会被使用；不可用的中转站上的图片暂停且未提交；开启自动重新生成后每张只多发一次、每批最多 3 张，并在原中转站恢复后才重发。桌面验证覆盖设置主用/备用、免费检查、费用确认对话框（取消与确认）、自动切换与重新生成的卡片提示、无障碍检查和窄窗口布局。没有调用真实付费生图。

## 0.3.12 · 下载不再占用生图名额，分开显示生成与下载用时

中转站监控显示一张图约 30–45 秒，但应用卡片上一张图要 35 秒到 2 分半。原因是之前卡片显示的是生成和下载的合计时间，而且下载完成前这张图会一直占着“同时生成”的名额。实际下载常要 80–110 秒，排在后面的图只能等。

- 中转站返回结果后，这张图立即让出生成名额，下一张图马上开始提交。图片下载改在后台单独进行，最多同时下载 4 张，不计入“同时生成张数”。
- 卡片和任务详情分开显示两段时间：“生成 X 秒 · 下载 Y 秒”；下载过程中显示“下载中”并实时计时。旧版本生成的任务只有合计时间，仍显示“用时”。
- 计费规则不变：每张图只提交一次生图请求，下载失败或重试只会重新下载，不会重新生图。

### 验证范围
用本地模拟服务和隔离数据验证：只允许同时生成 1 张、并让所有下载卡住，3 张图仍然依次完成生成，每张只请求一次；下载恢复后全部保存，生成和下载用时都有记录。没有调用真实付费生图。

## 0.3.11 · 下载超时恢复与批量补下载

0.3.10 一批 10 张图中，4 张已收到中转站返回的图片链接，但下载文件均在 120 秒后被本机程序中断；另有 2 张生图请求收到 HTTP 524。两类问题发生在不同阶段。

- 图片下载总等待预算从 2 分钟延长至 10 分钟，包含所有重试与间隔。连接错误、文件传输中断、HTTP 408/429/5xx 时最多尝试 3 次 GET，间隔 1 秒、2 秒；不重发生图请求。403/404/410 等不可访问或过期链接不自动重试，32 MB 上限不变。
- 失败时保留原结果链接，支持逐张“补下载”，套图新增“补下载全部失败图片”。旧版本失败的图片也可直接补下载，不会重新生图。
- 智能生图卡片和任务详情使用相同错误提示，区分下载超时、保存失败与生成结果未知；可展开查看详细错误。下载超过两分钟时说明仍在取图，不再显示正在等待中转站生图的提示。
- HTTP 524 等生成超时仍为结果未知，不自动重发；本版未改变中转站接口。诊断文字改为描述本次请求，避免把所有网关超时笼统说成固定两分钟上限。

### 验证范围
使用本地模拟服务和隔离数据验证：截断传输后自动取回完整图片，生图请求始终只有一次；临时 HTTP 错误恢复，过期链接不自动重试，取消及总预算能中断读文件与重试间隔。桌面验证覆盖错误详情、键盘操作、窄窗口、无障碍和一键补下载不会重新生成。没有调用真实付费生图，实际下载改善需在真实网络下确认；链接失效或源站持续不可访问仍可能下载失败。

## 0.3.10 · 中转站超时说明、返回智能生图保留未完成需求、导航进度圈

### 中转站约 2 分钟超时（HTTP 524）的排查结论
把“同时生成张数”改为 2、质量改为自动后仍偶发“结果未知”。逐张核对耗时：正常图片 29–64 秒完成，失败的每一张都在提交后约 116–130 秒被断开（Cloudflare 返回 HTTP 524，或连接被直接关闭），应用自身的超时为 10 分钟，并非应用中断。结论是中转站的同步生图接口（/images/edits）单次最多等约 2 分钟，中转站上游偶尔生成变慢就会超过；降低并行数和质量只能减少、不能避免。断开时中转站可能仍在生成并计费，所以继续标记为“结果未知”、不自动重发。

- 这类失败现在明确说明：“中转站等待约 N 秒后断开（HTTP 524 / 连接被关闭）…可能仍在中转站生成并已计费，请先在中转站后台核对…降低同时生成张数或质量只能减少、不能避免”。
- 免费探测（不带密钥、不计费）确认中转站另有需要 API Key 的批量接口 /v1/images/batches（提交、查询、下载均在 /v1 下）以及异步提交接口 /v1/image-playground/edits（但查询任务的接口不在 /v1 下，可能依赖网页登录）。改用批量接口可彻底避开 2 分钟上限，但需要用真实密钥做付费测试，留待单独确认。

### 智能生图
- 离开智能生图再回来时：最近一次需求如果还在分析、等待补充资料、生成图片或有暂停图片，会直接回到这个需求；已完成则显示新建需求页面。只看最近一次需求，不会被几天前未补充资料的旧需求拉回去。
- 左侧“智能生图”后新增进度圈：生成中按“已完成张数 / 总张数”填充，分析中显示旋转图标，等待补充资料显示黄色圆点，暂停时显示为异常色；悬停提示与读屏文字为“智能生图生成中，已完成 x / y 张”等。需求完成后进度圈消失。链接的可访问名称保持“智能生图”，进度作为描述提供。

### 验证范围
Go 测试覆盖：最近需求的分析/生成（按张数计数）/暂停/完成四种状态，旧的待补充需求不会被选中；HTTP 524 与长时间后断开会得到明确说明，短时间断开不会误判。桌面端到端测试 19 项通过，新增覆盖：完成后返回为新建需求且无进度圈、验证等待中离开再返回仍在该需求且显示分析中、待补充资料时返回仍在该需求且显示黄色圆点。另外修正了一处因 0.3.8 草稿自动修复而产生的测试时序问题（不影响实际使用）。

## 0.3.7 · 统一袖口小图标的左右顺序

0.3.6 的一组 6 张图里，袖口脚掌有的在名字左边、有的在右边。原因是技能示例让 Agent 写成“脚掌紧挨首字母 A，位于名字靠肘部的一端”：P004 要求名字沿袖口接缝排列，名字两端离肘部一样远，这句话等于没说左右，生图模型只能随机放。

- **后台固定附加规则**新增“袖口小图标与名字的左右顺序在每张图中完全相同”。用 0.3.6 版 P004 技能开始的需求在升级后仍会附加固定规则。
- 未修改过的内置技能自动升级，用户编辑过的保持不变。

- **新内置技能“P004 生图规则”（p004-rules）**：只保留和生图规划有关的规则，并写成可直接放进统一设计规格的固定句子，方便 deepseek-flash 照抄：
  - 人物模特（含成人、儿童、婴儿）只用欧美人；
  - 刺绣实际尺寸长边和短边都不超过 25 cm，同一图案在各图中实际尺寸和比例一致；
  - 卫衣胸前主刺绣以衣服本体中轴线居中（以服装中心为准，不以图片中心为准）；
  - 袖口刺绣只在最终画面右侧那只袖子，文字基线与袖口接缝平行并随袖口角度倾斜，位于袖筒中心、不压罗纹；少用背面视角以免前后矛盾；
  - 全图清晰，背景也不虚化，提示词中不出现“虚化、景深、柔焦”等词；
  - 一个需求只做一个产品变体。
  原规则中的文件夹与文件命名、STATUS.md/PRODUCT_BRIEF.md 交接、读取 D:\CODEX 文件等内容不适用于本应用，未纳入；“同时运行最多 4 个任务”可用“同时生成张数”下拉设置。
- 新数据目录默认安装并启用；已有数据目录升级后自动添加一次并启用，之后删除不会再被加回，也可在“连接与设置 → Skills”中停用。
- **后台固定附加规则**：本次制作使用的是未修改的 P004 技能时，后台在每张图提示词末尾附加“项目固定规则（P004）”，即使 LLM 漏写也能传给生图模型；重新生成和优化沿用原提示词，同样带上。停用或修改了该技能时不再附加，以免和修改后的规则冲突。
- **内置技能优先级**：三个内置技能开头说明，启用了项目规则技能时，其关于位置、方向、尺寸、清晰度和人物的规定优先；袖口方向不再照参考图，而按 P004 执行。“P004”不再被当作需要向用户询问或自行编造的刺绣工艺。未修改过的内置技能自动升级，用户编辑过的保持不变。

## 0.3.5 · 修正技能中导致细节不一致的写法

检查 0.3.4 一组 6 张套图后发现：胸前图案全部一致，袖口名字和脚掌仍有差异。原因一部分在技能：Agent 写出的统一设计规格把两种方向说法拼在一起（“沿袖口方向竖排”），生图模型每张理解不同；规格只写“左袖”，尺寸图把名字画到了另一只袖子上；信息图里模型自行添加了细节小图，小图里的袖口又是另一种画法；别家尺码长图作为参考图时被照搬版式。本版只修技能，不改生图流程。

- **方向只用两种固定写法**：横向（沿袖口一圈，手臂下垂时水平）或纵向（沿袖子长度方向，写明从哪端读起、字母顶部朝向），照参考图选一种原样照抄，不得混用，也不再用“横排/竖排”简写。示例改为明确标注“只是示范”，不再暗示默认方向。
- **位置同时写两种说法**：统一设计规格写“穿着者左袖（正面视角时是画面右侧那只袖子）”；每张提示词改用画面位置描述，不再只写“左袖”。元素之间的关系不用“上方/下方”，改为“紧挨首字母 A、在名字靠肩膀的一端”这类不随方向变化的说法。
- **信息图不加多余内容**：尺寸图、线色图写明“只包含上述板块，不要额外添加细节拼图、小图、材质说明”。
- **参考图选择**：画面能看到袖口时，放一张袖口最清楚的参考图；只借用数据或排版思路的图（如别家尺码表）不放进参考图，数据直接写进提示词。
- **保存前自查**：逐条检查每个元素只有一种方向说法、位置写全、名字拼写正确。
- Agent 系统提示同步加入方向和位置规则。未修改过的内置技能自动升级（包括 0.3.3、0.3.4 的版本），用户编辑过的保持不变。

### 验证范围
Go 测试覆盖三个技能从 0.3.3/0.3.4 自动升级、技能文本不含矛盾的方向说法、新规则存在。技能对出图一致性的实际效果需要在下一次真实套图中确认；生图模型本身仍有随机性，个别图可以用“优化”修正。

## 0.3.4 · 修复方案输出过长导致制作失败

0.3.3 实际运行中，智能分析在保存 12 张方案时失败，界面显示“Claude Code 执行失败：[claude-code:unrecognized_model] …deepseek-flash…”。查看运行记录发现真正原因是 LLM 单次回复超过了 8192 tokens 的输出上限（新技能要求更细的方案，且这次读到了全部 16 张商品图）；`unrecognized_model` 只是 Claude Code 尝试放宽上限时，因不认识该模型名而产生的后续错误。

- 方案可以分批保存：`save_suite_plan` 新增 `append` 参数，Agent 每次暂存不超过 6 张，最后一次提交时合并并整体校验，单次回复不再需要容纳全部张数。不分批的旧用法照常可用。最终保存校验失败时暂存清空，要求重新完整保存，避免新旧张数混在一起。
- 技能与 Agent 提示要求每张 prompt 约 200 字以内（统一设计规格由后台附加，不在每张重复），超过 6 张时分批保存，保存前不再长篇分析。
- 再遇到输出超限时，界面显示真实原因“LLM 单次输出超过上限（N tokens），方案没有保存”，并提示可在 LLM 供应商设置中调高“单次输出上限”，不再显示误导性的 `unrecognized_model`。
- 已升级到 0.3.3 的内置“Etsy 套图规划”技能会再次自动升级；用户编辑过的版本保持不变。

### 验证范围
Go 测试覆盖分批暂存与合并、每批上限、缺少统一设计规格、失败后清空暂存、旧的一次性保存、输出超限时显示真实原因、0.3.3 技能自动升级。尚未在真实 LLM 上复现同样的 12 张方案。

## 0.3.3 · 生图技能重写与大图查看

### 生图技能
针对实际套图中的细节跑偏（袖口名字有的横排有的竖排、袖口名字和脚掌在尺寸图/线色图里跑到衣身上、8 色图每件衣服的图案各不相同），重写三个内置技能：
- **商品与参考图分析**：为每个个性化文字和图案写出位置图，包括逐字母内容、穿着者视角的位置和参照物、方向与阅读方向（用“沿袖口罗纹方向、手臂下垂时水平”这类实物描述）、相对大小、颜色工艺和相邻关系；说明正面照片里穿着者左袖在画面右侧的镜像关系。
- **刺绣定制约束**：解释小细节为什么跑偏，要求写明哪只袖子、只出现在哪里、各有几个，画面看不到时不把元素搬到别处。
- **Etsy 套图规划**：固定每张提示词的写法（画面 → 能看到/看不到什么 → 本张变化 → 排除项）；颜色展示图改用布样或色块、最多一件完整展示图案；尺寸图和线色图只放一件衣服且元素位置与主图一致、文字面板只放短词；字体选项单独排列；附 locked 和难画图片的写法示例，方便较小的 LLM 照着写。
- 技能描述写得更具体，便于 Agent 判断何时调用。技能正文改为 Markdown 文件随程序打包。未修改过的内置技能自动升级（包括 0.3.1 的版本），用户编辑过的保持不变；已开始的需求继续使用当时冻结的版本。

### 大图查看
- 套图结果和“之前的版本”都可以点开大图，显示原图而不是缩略图。
- 支持“上一张 / 下一张”按钮和键盘 ← →，按套图顺序浏览（每张的当前版本后紧跟它的之前版本），标题显示“第 N 张”和序号。
- 点击图片在“适应窗口 / 实际大小”间切换，便于检查袖口文字等细节。
- 大图窗口里可直接“下载原图”，当前版本还可直接“优化”。

### 验证范围
技能改动通过内置技能校验与升级测试（未修改的旧版本升级、用户编辑版本保留）。原计划用 skill-creator 的新旧技能对比评测，但本机环境的子代理模型不可用，未能自动运行；技能效果需要在下一次真实套图中确认。大图查看由桌面端到端测试覆盖（打开、键盘与按钮切换、之前版本不显示“优化”、实际大小切换、关闭），智能生图端到端测试 8 项通过。

## 0.3.2 · 并行生成

- 生图队列从逐张生成改为并行：同时发出多张图的请求，整套图的总耗时明显缩短。
- 智能生图“更多设置”新增“同时生成张数”下拉（1–8 张，默认 3 张），保存在本机。生成中也可调整并立即生效：调高会马上开始更多图片，调低时已在生成的图片继续完成，之后不再超出新上限。该设置对生图工作台同样生效。
- 并行不改变计费安全规则：每张图仍只提交一次，超时、断线或 5xx 仍标记为结果未知且不自动重试；停止的任务在真正提交前会再次核对状态，不会被发出。退出应用时会等待正在进行的请求结束后再关闭数据库。
- 中转站可能限制同时请求数，出现大量失败或 HTTP 429 时请调低张数。

### 验证范围

本地模拟中转站验证：并行数严格不超过设置值、调高立即生效、调低不中断进行中的请求、每张只提交一次、停止后的任务不会被发出、设置重启后保留；Go 测试连续 3 轮通过；17 项真实 Wails 桌面测试通过。尚未在用户真实中转站上验证其并发限制。

## 0.3.1 · 浏览器读取受阻商品页与套图优化

Etsy 等网站会拦截应用的直接请求（如 HTTP 403），0.3.0 遇到这种情况时只能提示“暂时无法读取商品链接”。0.3.1 在直连受阻时改用随包的固定版 WebView2 读取页面，读不到时仍可上传图片或粘贴描述；同时新增套图逐张“优化”。

### 浏览器读取商品页

- 直连返回 401/403/429/503、网络失败、人机验证页或页面没有商品资料时，自动改用浏览器读取。无效链接、本机/内网地址和 404 不会改用浏览器。
- 浏览器由独立的 `product-browser.exe` 在隐藏窗口中加载页面，等验证页消失、页面内容稳定后再取渲染结果，交给原有解析流程。
- 验证页 20 秒内仍未自动通过时，弹出“完成验证后将自动继续”窗口，由用户手动完成一次验证。关闭窗口时回到上传图片/粘贴描述的提示。
- 制作进度显示“正在用浏览器读取商品页”“需要你在弹出的窗口里完成验证”和实时的“等待验证中（已 X 秒）”。
- 每次读取最长 3 分钟；取消制作、超时、浏览器异常退出都会结束辅助程序。页面上限 4 MB，单张图片上限 32 MB，页面跳转后的地址会再次检查，不访问本机或内网。
- 商品图片仍先直接下载，失败时用同一浏览器会话补取（不带 Cookie）。
- 商品资料提供结构化商品图片（含 `contentURL` 写法）时只使用这些图片，不再混入页面中的推荐商品图和重复缩略图。0.3.0 直连成功的页面同样受益。
- 浏览器 Cookie 保存在当前数据目录的 `product-browser` 文件夹，不进入备份、迁移和发布包。“连接与设置 → 本地数据与备份 → 清除商品页浏览器数据”可删除，读取进行中时不可清除。
- Claude 仍然只能调用 `fetch_product`，不能操作浏览器；页面内容仍按不可信资料处理。
- 日志记录改用浏览器的原因、验证窗口、用时、页面大小和候选图片数，以及失败原因。地址查询参数在写入前隐藏，不记录页面内容。

### 套图优化

- 新增“优化”：智能生图的每张已完成图片下方都有“优化”按钮，填写想怎么调整（例如“袖口名字改成横排”），应用以这张图为底图发起一次图生图，只修改写明的内容。这是新的、可能计费的请求，提交前显示费用提示；同一次提交重复点击不会重复生成，同一张图在生成中不能再次优化。
- 优化结果成为这张图的当前版本，旧版本保留在“之前的版本”中，可查看和下载。“下载整套图片”只打包每张的当前版本，按原顺序编号。连续优化不会把提示词层层嵌套。
- 智能生图“更多设置”全部改为下拉选择：生图模型从所选中转站的模型列表中选择（默认使用连接设置的模型；获取列表只查询模型，不生图、不计费），图片尺寸从常用尺寸中选择并随画面比例自动匹配，质量显示为自动/低/中/高。
- 生图工作台的“最近生成”不再显示智能生图的套图，它们只在智能生图页面查看和下载。
- 跨图一致：内置“Etsy 套图规划”和“刺绣定制约束”技能新增统一设计规格，要求为每个文字和图案元素写明内容、字体、方向（横排/竖排/沿袖口方向）、位置、大小和颜色，并在每张图中完整沿用，避免出现同一袖口名字有的横排、有的竖排。未修改过的内置技能自动升级，用户编辑过的版本保持不变；Agent 系统提示也加入同样要求。已开始的需求继续使用当时冻结的技能版本。

### 修复

- 图生图上传参考图时，每张图片都被标成 `application/octet-stream`，OpenAI 兼容接口会拒绝（实测中转站返回 HTTP 502，且没有生成记录）。现在按图片内容标为 `image/png`、`image/jpeg` 或 `image/webp`。之前标记为“结果未知”的这类任务，请先核对平台记录再明确重新生成。
- 开启系统代理时，本机 DNS 可能间歇性解析失败（no such host），导致商品图片只保存了 1–2 张。现在解析失败会重试，已确认是公网的域名缓存 5 分钟；解析到本机或内网地址仍然拒绝，且不缓存。图片未能保存时，日志记录张数和首个原因。

### 升级

关闭旧版，完整解压升级包覆盖程序目录，保留 data、data-location.txt 和自选数据目录。新包在 ImageWorkbench.exe 旁多了 `product-browser.exe`，需要一起保留。本机构建沿用原有连接与加密密钥。

# 更新记录

从 0.3.1 起，每个版本的说明都累加在本文件中，最新版本在最上面。更早的版本见 `docs/changelog-0.x.md`。

## 0.4.0 · 同时生成张数上限改为 4

- “更多设置 → 同时生成张数”只保留 1、2、3、4 张，默认仍为 3 张，对生图工作台同样生效。
- 旧版本若设置为 5–8 张，升级后自动按 4 张执行，无需重新设置；1–4 张的设置保持不变。
- 后台下载（最多同时 4 张）仍单独计算，不占用同时生成名额。

### 验证范围
用本地模拟服务和隔离数据验证：上限为 4 时并行请求不超过 4，5 和 8 被拒绝；旧版本保存的 8 张读取为 4 张。没有调用真实付费生图。

## 0.3.12 · 下载不再占用生图名额，分开显示生成与下载用时

中转站监控显示一张图约 30–45 秒，但应用卡片上一张图要 35 秒到 2 分半。原因是之前卡片显示的是生成和下载的合计时间，而且下载完成前这张图会一直占着“同时生成”的名额。实际下载常要 80–110 秒，排在后面的图只能等。

- 中转站返回结果后，这张图立即让出生成名额，下一张图马上开始提交。图片下载改在后台单独进行，最多同时下载 4 张，不计入“同时生成张数”。
- 卡片和任务详情分开显示两段时间：“生成 X 秒 · 下载 Y 秒”；下载过程中显示“下载中”并实时计时。旧版本生成的任务只有合计时间，仍显示“用时”。
- 计费规则不变：每张图只提交一次生图请求，下载失败或重试只会重新下载，不会重新生图。

### 验证范围
用本地模拟服务和隔离数据验证：只允许同时生成 1 张、并让所有下载卡住，3 张图仍然依次完成生成，每张只请求一次；下载恢复后全部保存，生成和下载用时都有记录。没有调用真实付费生图。

## 0.3.11 · 下载超时恢复与批量补下载

0.3.10 一批 10 张图中，4 张已收到中转站返回的图片链接，但下载文件均在 120 秒后被本机程序中断；另有 2 张生图请求收到 HTTP 524。两类问题发生在不同阶段。

- 图片下载总等待预算从 2 分钟延长至 10 分钟，包含所有重试与间隔。连接错误、文件传输中断、HTTP 408/429/5xx 时最多尝试 3 次 GET，间隔 1 秒、2 秒；不重发生图请求。403/404/410 等不可访问或过期链接不自动重试，32 MB 上限不变。
- 失败时保留原结果链接，支持逐张“补下载”，套图新增“补下载全部失败图片”。旧版本失败的图片也可直接补下载，不会重新生图。
- 智能生图卡片和任务详情使用相同错误提示，区分下载超时、保存失败与生成结果未知；可展开查看详细错误。下载超过两分钟时说明仍在取图，不再显示正在等待中转站生图的提示。
- HTTP 524 等生成超时仍为结果未知，不自动重发；本版未改变中转站接口。诊断文字改为描述本次请求，避免把所有网关超时笼统说成固定两分钟上限。

### 验证范围
使用本地模拟服务和隔离数据验证：截断传输后自动取回完整图片，生图请求始终只有一次；临时 HTTP 错误恢复，过期链接不自动重试，取消及总预算能中断读文件与重试间隔。桌面验证覆盖错误详情、键盘操作、窄窗口、无障碍和一键补下载不会重新生成。没有调用真实付费生图，实际下载改善需在真实网络下确认；链接失效或源站持续不可访问仍可能下载失败。

## 0.3.10 · 中转站超时说明、返回智能生图保留未完成需求、导航进度圈

### 中转站约 2 分钟超时（HTTP 524）的排查结论
把“同时生成张数”改为 2、质量改为自动后仍偶发“结果未知”。逐张核对耗时：正常图片 29–64 秒完成，失败的每一张都在提交后约 116–130 秒被断开（Cloudflare 返回 HTTP 524，或连接被直接关闭），应用自身的超时为 10 分钟，并非应用中断。结论是中转站的同步生图接口（/images/edits）单次最多等约 2 分钟，中转站上游偶尔生成变慢就会超过；降低并行数和质量只能减少、不能避免。断开时中转站可能仍在生成并计费，所以继续标记为“结果未知”、不自动重发。

- 这类失败现在明确说明：“中转站等待约 N 秒后断开（HTTP 524 / 连接被关闭）…可能仍在中转站生成并已计费，请先在中转站后台核对…降低同时生成张数或质量只能减少、不能避免”。
- 免费探测（不带密钥、不计费）确认中转站另有需要 API Key 的批量接口 /v1/images/batches（提交、查询、下载均在 /v1 下）以及异步提交接口 /v1/image-playground/edits（但查询任务的接口不在 /v1 下，可能依赖网页登录）。改用批量接口可彻底避开 2 分钟上限，但需要用真实密钥做付费测试，留待单独确认。

### 智能生图
- 离开智能生图再回来时：最近一次需求如果还在分析、等待补充资料、生成图片或有暂停图片，会直接回到这个需求；已完成则显示新建需求页面。只看最近一次需求，不会被几天前未补充资料的旧需求拉回去。
- 左侧“智能生图”后新增进度圈：生成中按“已完成张数 / 总张数”填充，分析中显示旋转图标，等待补充资料显示黄色圆点，暂停时显示为异常色；悬停提示与读屏文字为“智能生图生成中，已完成 x / y 张”等。需求完成后进度圈消失。链接的可访问名称保持“智能生图”，进度作为描述提供。

### 验证范围
Go 测试覆盖：最近需求的分析/生成（按张数计数）/暂停/完成四种状态，旧的待补充需求不会被选中；HTTP 524 与长时间后断开会得到明确说明，短时间断开不会误判。桌面端到端测试 19 项通过，新增覆盖：完成后返回为新建需求且无进度圈、验证等待中离开再返回仍在该需求且显示分析中、待补充资料时返回仍在该需求且显示黄色圆点。另外修正了一处因 0.3.8 草稿自动修复而产生的测试时序问题（不影响实际使用）。

## 0.3.9 · 密钥无效时暂停同批图片，失败图片一键重新生成

0.3.8 使用中，生图中转站保存的 API Key 有误，12 张图同时被中转站以 HTTP 401 拒绝，界面只提示“详细错误请查看日志”，修正密钥后需要逐张点“重新生成”。

- **密钥无效时暂停**：生图中转站返回 HTTP 401/403 时，该图标记为“API Key 无效（HTTP 401）…未生成也不计费”，同批尚未提交的图片自动转为“已暂停（未提交、未计费）”，不再继续发送；已在发送中的请求（最多为“同时生成张数”）照常结束。日志记录暂停张数。
- **明确提示**：套图结果顶部显示“生图中转站拒绝了 API Key”，说明未生成也不计费、同批未提交图片已暂停，并给出“连接与设置”的链接；单张图片显示具体原因。
- **重新生成全部失败图片**：结果区新增“重新生成全部失败图片（N 张）”按钮，一次重新生成所有失败图片、恢复所有暂停图片。点击前确认“可能产生费用”；“结果未知”的图片不包含在内（可能已生成并计费，需先核对平台记录）；用户自己停止的图片也不包含。重复点击不会重复提交。
- 桌面测试脚本在旧的 release 运行时目录不存在时，自动改用构建所用的固定版 WebView2。

### 验证范围
Go 测试：同时生成 1 张时，首张 401 后其余 3 张暂停且未发送；修正密钥后一键操作重新生成 1 张、恢复 3 张，共只多发 4 次请求；结果未知的图片未被重发；再次点击提示没有可重新生成的图片。桌面端到端测试 9 项通过，其中新增用例模拟中转站拒绝密钥，验证顶部提示、单张提示、按钮、费用确认和恢复后成功。另一次完整运行中出现过一次瞬时的颜色对比度告警（禁用状态控件），重跑两次未复现。

## 0.3.8 · 修复删除连接后开始制作报“记录不存在”

删除并重新创建生图中转站后，智能生图草稿仍指向已删除的连接，点击“开始生成套图”时界面显示“操作未完成：记录不存在: sql: no rows in result set”。

- 打开智能生图时，草稿里已删除的 LLM 供应商或生图中转站会自动换成现有的唯一同类连接（生图模型同时改为使用连接默认）；同类连接有多个时留空，由用户在“更多设置”中选择。已删除的项目也会自动清空。
- 仍然找不到连接、项目或参考素材时，显示可操作的原因，例如“所选生图中转站已删除或未选择，请在‘更多设置’中重新选择”；继续旧需求而其连接已删除时，提示新建需求并选择现有连接。

### 验证范围
Go 测试复现删除并新建生图中转站：草稿自动换成新连接；存在多个候选时留空；直接开始时显示可读原因而不是数据库错误。

## 0.3.7 · 统一袖口小图标的左右顺序

0.3.6 的一组 6 张图里，袖口脚掌有的在名字左边、有的在右边。原因是技能示例让 Agent 写成“脚掌紧挨首字母 A，位于名字靠肘部的一端”：P004 要求名字沿袖口接缝排列，名字两端离肘部一样远，这句话等于没说左右，生图模型只能随机放。

- **P004 生图规则**（主要修改）：新增“袖口小图标和名字的排列”一节。默认写法为“图标与名字在同一条基线上，紧挨在名字首字母之前，按阅读顺序先看到图标、再看到名字”；用户明确要求放在名字后面或正上方时，换成对应的固定写法。每张提示词再写一句画面里从左到右的顺序，例如“画面右侧袖口上，从左到右依次是：黑色脚掌、Amelia”。
- **商品与参考图分析、刺绣定制约束、Etsy 套图规划**：同步把小图标位置改成按阅读顺序的“同行”或“叠放”两种固定写法，删去按离肘部或肩膀远近区分两端的示例。
- **后台固定附加规则**新增“袖口小图标与名字的左右顺序在每张图中完全相同”。用 0.3.6 版 P004 技能开始的需求在升级后仍会附加固定规则。
- 未修改过的内置技能自动升级，用户编辑过的保持不变。

### 验证范围
Go 测试覆盖：所有内置技能中不再有按离肘部或肩膀远近描述图标位置的写法、新规则存在、0.3.6 版技能自动升级、0.3.6 版 P004 冻结副本仍附加固定规则。实际出图效果需在下一次套图中确认。

## 0.3.6 · 引入 P004 生图规则

把店铺的 P004 生图规则引入为内置技能，并由后台把核心规则固定附加到每张图的提示词。

- **新内置技能“P004 生图规则”（p004-rules）**：只保留和生图规划有关的规则，并写成可直接放进统一设计规格的固定句子，方便 deepseek-flash 照抄：
  - 人物模特（含成人、儿童、婴儿）只用欧美人；
  - 刺绣实际尺寸长边和短边都不超过 25 cm，同一图案在各图中实际尺寸和比例一致；
  - 卫衣胸前主刺绣以衣服本体中轴线居中（以服装中心为准，不以图片中心为准）；
  - 袖口刺绣只在最终画面右侧那只袖子，文字基线与袖口接缝平行并随袖口角度倾斜，位于袖筒中心、不压罗纹；少用背面视角以免前后矛盾；
  - 全图清晰，背景也不虚化，提示词中不出现“虚化、景深、柔焦”等词；
  - 一个需求只做一个产品变体。
  原规则中的文件夹与文件命名、STATUS.md/PRODUCT_BRIEF.md 交接、读取 D:\CODEX 文件等内容不适用于本应用，未纳入；“同时运行最多 4 个任务”可用“同时生成张数”下拉设置。
- 新数据目录默认安装并启用；已有数据目录升级后自动添加一次并启用，之后删除不会再被加回，也可在“连接与设置 → Skills”中停用。
- **后台固定附加规则**：本次制作使用的是未修改的 P004 技能时，后台在每张图提示词末尾附加“项目固定规则（P004）”，即使 LLM 漏写也能传给生图模型；重新生成和优化沿用原提示词，同样带上。停用或修改了该技能时不再附加，以免和修改后的规则冲突。
- **内置技能优先级**：三个内置技能开头说明，启用了项目规则技能时，其关于位置、方向、尺寸、清晰度和人物的规定优先；袖口方向不再照参考图，而按 P004 执行。“P004”不再被当作需要向用户询问或自行编造的刺绣工艺。未修改过的内置技能自动升级，用户编辑过的保持不变。

Go 测试覆盖：新数据目录安装并启用 P004 技能、旧数据目录只添加一次且删除后不再加回、技能通过校验；使用未修改的 P004 技能时 12 张提示词都以固定规则结尾且只出现一次，修改或停用后不再附加；三个内置技能从 0.3.5 自动升级。规则对实际出图的效果需要在下一次真实套图中确认。

## 0.3.5 · 修正技能中导致细节不一致的写法

检查 0.3.4 一组 6 张套图后发现：胸前图案全部一致，袖口名字和脚掌仍有差异。原因一部分在技能：Agent 写出的统一设计规格把两种方向说法拼在一起（“沿袖口方向竖排”），生图模型每张理解不同；规格只写“左袖”，尺寸图把名字画到了另一只袖子上；信息图里模型自行添加了细节小图，小图里的袖口又是另一种画法；别家尺码长图作为参考图时被照搬版式。本版只修技能，不改生图流程。

- **方向只用两种固定写法**：横向（沿袖口一圈，手臂下垂时水平）或纵向（沿袖子长度方向，写明从哪端读起、字母顶部朝向），照参考图选一种原样照抄，不得混用，也不再用“横排/竖排”简写。示例改为明确标注“只是示范”，不再暗示默认方向。
- **位置同时写两种说法**：统一设计规格写“穿着者左袖（正面视角时是画面右侧那只袖子）”；每张提示词改用画面位置描述，不再只写“左袖”。元素之间的关系不用“上方/下方”，改为“紧挨首字母 A、在名字靠肩膀的一端”这类不随方向变化的说法。
- **信息图不加多余内容**：尺寸图、线色图写明“只包含上述板块，不要额外添加细节拼图、小图、材质说明”。
- **参考图选择**：画面能看到袖口时，放一张袖口最清楚的参考图；只借用数据或排版思路的图（如别家尺码表）不放进参考图，数据直接写进提示词。
- **保存前自查**：逐条检查每个元素只有一种方向说法、位置写全、名字拼写正确。
- Agent 系统提示同步加入方向和位置规则。未修改过的内置技能自动升级（包括 0.3.3、0.3.4 的版本），用户编辑过的保持不变。

### 验证范围
Go 测试覆盖三个技能从 0.3.3/0.3.4 自动升级、技能文本不含矛盾的方向说法、新规则存在。技能对出图一致性的实际效果需要在下一次真实套图中确认；生图模型本身仍有随机性，个别图可以用“优化”修正。

## 0.3.4 · 修复方案输出过长导致制作失败

0.3.3 实际运行中，智能分析在保存 12 张方案时失败，界面显示“Claude Code 执行失败：[claude-code:unrecognized_model] …deepseek-flash…”。查看运行记录发现真正原因是 LLM 单次回复超过了 8192 tokens 的输出上限（新技能要求更细的方案，且这次读到了全部 16 张商品图）；`unrecognized_model` 只是 Claude Code 尝试放宽上限时，因不认识该模型名而产生的后续错误。

- 方案可以分批保存：`save_suite_plan` 新增 `append` 参数，Agent 每次暂存不超过 6 张，最后一次提交时合并并整体校验，单次回复不再需要容纳全部张数。不分批的旧用法照常可用。最终保存校验失败时暂存清空，要求重新完整保存，避免新旧张数混在一起。
- 技能与 Agent 提示要求每张 prompt 约 200 字以内（统一设计规格由后台附加，不在每张重复），超过 6 张时分批保存，保存前不再长篇分析。
- 再遇到输出超限时，界面显示真实原因“LLM 单次输出超过上限（N tokens），方案没有保存”，并提示可在 LLM 供应商设置中调高“单次输出上限”，不再显示误导性的 `unrecognized_model`。
- 已升级到 0.3.3 的内置“Etsy 套图规划”技能会再次自动升级；用户编辑过的版本保持不变。

### 验证范围
Go 测试覆盖分批暂存与合并、每批上限、缺少统一设计规格、失败后清空暂存、旧的一次性保存、输出超限时显示真实原因、0.3.3 技能自动升级。尚未在真实 LLM 上复现同样的 12 张方案。

## 0.3.3 · 生图技能重写与大图查看

### 生图技能
针对实际套图中的细节跑偏（袖口名字有的横排有的竖排、袖口名字和脚掌在尺寸图/线色图里跑到衣身上、8 色图每件衣服的图案各不相同），重写三个内置技能：
- **商品与参考图分析**：为每个个性化文字和图案写出位置图，包括逐字母内容、穿着者视角的位置和参照物、方向与阅读方向（用“沿袖口罗纹方向、手臂下垂时水平”这类实物描述）、相对大小、颜色工艺和相邻关系；说明正面照片里穿着者左袖在画面右侧的镜像关系。
- **刺绣定制约束**：解释小细节为什么跑偏，要求写明哪只袖子、只出现在哪里、各有几个，画面看不到时不把元素搬到别处。
- **Etsy 套图规划**：固定每张提示词的写法（画面 → 能看到/看不到什么 → 本张变化 → 排除项）；颜色展示图改用布样或色块、最多一件完整展示图案；尺寸图和线色图只放一件衣服且元素位置与主图一致、文字面板只放短词；字体选项单独排列；附 locked 和难画图片的写法示例，方便较小的 LLM 照着写。
- 技能描述写得更具体，便于 Agent 判断何时调用。技能正文改为 Markdown 文件随程序打包。未修改过的内置技能自动升级（包括 0.3.1 的版本），用户编辑过的保持不变；已开始的需求继续使用当时冻结的版本。

### 大图查看
- 套图结果和“之前的版本”都可以点开大图，显示原图而不是缩略图。
- 支持“上一张 / 下一张”按钮和键盘 ← →，按套图顺序浏览（每张的当前版本后紧跟它的之前版本），标题显示“第 N 张”和序号。
- 点击图片在“适应窗口 / 实际大小”间切换，便于检查袖口文字等细节。
- 大图窗口里可直接“下载原图”，当前版本还可直接“优化”。

### 验证范围
技能改动通过内置技能校验与升级测试（未修改的旧版本升级、用户编辑版本保留）。原计划用 skill-creator 的新旧技能对比评测，但本机环境的子代理模型不可用，未能自动运行；技能效果需要在下一次真实套图中确认。大图查看由桌面端到端测试覆盖（打开、键盘与按钮切换、之前版本不显示“优化”、实际大小切换、关闭），智能生图端到端测试 8 项通过。

## 0.3.2 · 并行生成

- 生图队列从逐张生成改为并行：同时发出多张图的请求，整套图的总耗时明显缩短。
- 智能生图“更多设置”新增“同时生成张数”下拉（1–8 张，默认 3 张），保存在本机。生成中也可调整并立即生效：调高会马上开始更多图片，调低时已在生成的图片继续完成，之后不再超出新上限。该设置对生图工作台同样生效。
- 并行不改变计费安全规则：每张图仍只提交一次，超时、断线或 5xx 仍标记为结果未知且不自动重试；停止的任务在真正提交前会再次核对状态，不会被发出。退出应用时会等待正在进行的请求结束后再关闭数据库。
- 中转站可能限制同时请求数，出现大量失败或 HTTP 429 时请调低张数。

### 验证范围

本地模拟中转站验证：并行数严格不超过设置值、调高立即生效、调低不中断进行中的请求、每张只提交一次、停止后的任务不会被发出、设置重启后保留；Go 测试连续 3 轮通过；17 项真实 Wails 桌面测试通过。尚未在用户真实中转站上验证其并发限制。

## 0.3.1 · 浏览器读取受阻商品页与套图优化

Etsy 等网站会拦截应用的直接请求（如 HTTP 403），0.3.0 遇到这种情况时只能提示“暂时无法读取商品链接”。0.3.1 在直连受阻时改用随包的固定版 WebView2 读取页面，读不到时仍可上传图片或粘贴描述；同时新增套图逐张“优化”。

### 浏览器读取商品页

- 直连返回 401/403/429/503、网络失败、人机验证页或页面没有商品资料时，自动改用浏览器读取。无效链接、本机/内网地址和 404 不会改用浏览器。
- 浏览器由独立的 `product-browser.exe` 在隐藏窗口中加载页面，等验证页消失、页面内容稳定后再取渲染结果，交给原有解析流程。
- 验证页 20 秒内仍未自动通过时，弹出“完成验证后将自动继续”窗口，由用户手动完成一次验证。关闭窗口时回到上传图片/粘贴描述的提示。
- 制作进度显示“正在用浏览器读取商品页”“需要你在弹出的窗口里完成验证”和实时的“等待验证中（已 X 秒）”。
- 每次读取最长 3 分钟；取消制作、超时、浏览器异常退出都会结束辅助程序。页面上限 4 MB，单张图片上限 32 MB，页面跳转后的地址会再次检查，不访问本机或内网。
- 商品图片仍先直接下载，失败时用同一浏览器会话补取（不带 Cookie）。
- 商品资料提供结构化商品图片（含 `contentURL` 写法）时只使用这些图片，不再混入页面中的推荐商品图和重复缩略图。0.3.0 直连成功的页面同样受益。
- 浏览器 Cookie 保存在当前数据目录的 `product-browser` 文件夹，不进入备份、迁移和发布包。“连接与设置 → 本地数据与备份 → 清除商品页浏览器数据”可删除，读取进行中时不可清除。
- Claude 仍然只能调用 `fetch_product`，不能操作浏览器；页面内容仍按不可信资料处理。
- 日志记录改用浏览器的原因、验证窗口、用时、页面大小和候选图片数，以及失败原因。地址查询参数在写入前隐藏，不记录页面内容。

### 套图优化

- 新增“优化”：智能生图的每张已完成图片下方都有“优化”按钮，填写想怎么调整（例如“袖口名字改成横排”），应用以这张图为底图发起一次图生图，只修改写明的内容。这是新的、可能计费的请求，提交前显示费用提示；同一次提交重复点击不会重复生成，同一张图在生成中不能再次优化。
- 优化结果成为这张图的当前版本，旧版本保留在“之前的版本”中，可查看和下载。“下载整套图片”只打包每张的当前版本，按原顺序编号。连续优化不会把提示词层层嵌套。
- 智能生图“更多设置”全部改为下拉选择：生图模型从所选中转站的模型列表中选择（默认使用连接设置的模型；获取列表只查询模型，不生图、不计费），图片尺寸从常用尺寸中选择并随画面比例自动匹配，质量显示为自动/低/中/高。
- 生图工作台的“最近生成”不再显示智能生图的套图，它们只在智能生图页面查看和下载。
- 跨图一致：内置“Etsy 套图规划”和“刺绣定制约束”技能新增统一设计规格，要求为每个文字和图案元素写明内容、字体、方向（横排/竖排/沿袖口方向）、位置、大小和颜色，并在每张图中完整沿用，避免出现同一袖口名字有的横排、有的竖排。未修改过的内置技能自动升级，用户编辑过的版本保持不变；Agent 系统提示也加入同样要求。已开始的需求继续使用当时冻结的技能版本。

### 修复

- 图生图上传参考图时，每张图片都被标成 `application/octet-stream`，OpenAI 兼容接口会拒绝（实测中转站返回 HTTP 502，且没有生成记录）。现在按图片内容标为 `image/png`、`image/jpeg` 或 `image/webp`。之前标记为“结果未知”的这类任务，请先核对平台记录再明确重新生成。
- 开启系统代理时，本机 DNS 可能间歇性解析失败（no such host），导致商品图片只保存了 1–2 张。现在解析失败会重试，已确认是公网的域名缓存 5 分钟；解析到本机或内网地址仍然拒绝，且不缓存。图片未能保存时，日志记录张数和首个原因。

### 升级

关闭旧版，完整解压升级包覆盖程序目录，保留 data、data-location.txt 和自选数据目录。新包在 ImageWorkbench.exe 旁多了 `product-browser.exe`，需要一起保留。本机构建沿用原有连接与加密密钥。

### 验证范围

在本机用应用自带的 WebView2 测试了 3 个真实 Etsy 商品页：使用全新浏览器资料时都能在约 15 秒内自动通过验证页，取得完整标题、描述和全部商品图；保留 Cookie 后约 6–13 秒。测试中没有出现必须手动完成的验证，因此“弹窗手动验证”只用本地模拟页面验证过。网站的反爬策略随时可能变化，不保证每次成功，上传图片/粘贴描述仍是兜底方式。用户真实中转站已确认修复后可正常出图；“优化”和模型下拉尚未在真实中转站上验证。

自动化测试全部使用本地模拟页面与隔离数据，不访问真实网站，也不调用付费接口：模拟辅助程序测试覆盖超时、取消、崩溃、关闭窗口、大小上限与内网跳转；真实辅助程序测试覆盖脚本渲染页、重定向、自动通过的验证页、需要弹窗的验证页和空白页；优化测试覆盖版本保留、重复提交、嵌套提示词和套图导出；桌面端到端测试覆盖“等待验证”进度、清除浏览器数据、优化流程、工作台不显示智能套图和“更多设置”下拉。

验收：Go 测试（`go test ./...`，其中 3 项真实辅助程序测试由 `scripts/test-product-browser.ps1` 运行并通过）、vet、TypeScript、格式检查和本机配置保留测试通过；17 项真实 Wails 桌面测试通过。发布包已校验包含 `product-browser.exe` 且不含个人数据。

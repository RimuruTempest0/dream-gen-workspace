0.7.20부터 화면이 어두운 테마로 바뀌었고, 왼쪽 탐색 메뉴는 아이콘 막대로 접혀 있으며(마우스를 올리면 펼쳐짐) 이름도 바뀌었습니다: 스마트 생성→창작, Image Workbench→전문가 모드, 프롬프트 템플릿→템플릿, 작업 센터→생성 기록, 소재 라이브러리→작품과 소재. 연결 및 설정, 중계 서버 모니터, LLM 모니터, 로그는 "시스템" 안으로 들어가 각각 "연결", "서비스 상태", "모델 상태", "로그" 네 개의 탭이 되었습니다. 0.7.24부터 화면과 안내 메시지에서 "중계 서버"는 "이미지 서비스"로, "LLM 공급자 / LLM"은 "AI 모델"로 부릅니다(라이선스 회선 이름 "LLM 회선 1 / 2"는 그대로입니다). 아래 내용은 여전히 예전 이름을 사용합니다.

표시 언어(0.8.0부터): 화면을 中文, English, Tiếng Việt, 日本語, 한국어 다섯 가지 언어로 표시할 수 있습니다. 처음 실행할 때는 Windows 언어를 따르고, 이 다섯 가지가 아니면 중국어로 표시합니다. 이후 왼쪽 탐색 메뉴 아래쪽이나 "시스템 → 연결 → 표시 언어"에서 바꿀 수 있으며, 바로 적용되고 다시 시작해도 유지됩니다. AI의 질문, 판단, 설명은 표시 언어로 작성됩니다. 이미지 프롬프트는 표시 언어가 중국어이면 중국어로, 그 밖에는 영어로 작성됩니다. 이미지 속 글자는 입력한 그대로 그리며 번역하지 않습니다. 저장된 로그와 설명은 작성될 때의 언어를 유지합니다. 프로그램 폴더에는 다섯 가지 언어의 사용 설명서가 있습니다. 원클릭 업데이트로 0.8.0으로 올리면 중국어 사용 설명서만 들어 있고, 다른 언어판은 전체 패키지에 있습니다.

Windows 11 x64만 지원합니다.
압축 파일 전체를 풀고 ImageWorkbench.exe를 더블클릭합니다.
EXE와 같은 위치의 runtime, agent 폴더와 product-browser.exe를 그대로 두세요. 각각 화면 실행 구성 요소, 내장 Claude Code, 상품 페이지 브라우저입니다.
업그레이드할 때는 먼저 이전 버전을 닫고 백업을 만드세요. 프로그램 폴더를 덮어쓸 때 data와 data-location.txt는 남겨 두세요.
0.7.11부터: 처음 열 때 데이터베이스가 자동으로 업그레이드되며(작업이 많으면 몇 초 더 걸림), 이후에는 이전 버전에서 이 데이터를 열 수 없으므로 먼저 백업하세요. 작업이 아무리 많아도 생성과 작업 센터가 느려지지 않습니다.

처음 설정:
연결 및 설정 → 연결 추가 → 이름, Base URL, API Key, 기본 모델을 입력합니다.
Base URL에는 API 접두사를 입력합니다. 예: https://example.com/v1.
연결 테스트는 모델 목록만 가져오며 이미지를 생성하지 않습니다.
연결 테스트는 먼저 주소와 키를 확인하고, 기다리는 동안 안내를 표시하며 최대 30초입니다. "테스트 취소"를 클릭할 수 있습니다.
네트워크 요청은 명시적인 HTTP_PROXY / HTTPS_PROXY 설정을 우선 사용하고, 일반 실행 시에는 Windows에서 켜 둔 수동 시스템 프록시를 사용합니다.
모델 조회, 이미지 생성, 이미지 다운로드는 같은 네트워크 규칙을 사용합니다. 시스템 프록시를 바꾼 후에는 앱을 다시 시작하세요.
Windows 프록시는 자동으로 바꾸지 않습니다. PAC만 설정한 환경은 아직 자동 감지를 지원하지 않습니다.
모델 목록을 공개하지 않는 중계 서버는 모델 ID를 직접 입력할 수 있습니다.

이미지 생성:
작업대에서 연결을 선택하고 프롬프트를 입력한 뒤 생성을 클릭합니다.
참조 이미지를 추가하면 이미지 기반 생성으로 바뀝니다. 일괄 모드에서는 한 줄에 프롬프트 하나를 씁니다.
크기와 품질은 사용하는 모델의 능력에 맞게 입력하세요. auto는 해당 매개변수를 보내지 않습니다.
이미지는 로컬 소재 라이브러리에 자동 저장되며, 원본 내보내기에서 저장 위치를 고를 수 있습니다.
소재 라이브러리 → 일괄 관리: 이미지를 클릭하면 선택되고(다시 클릭하면 해제), "불러온 항목 모두 선택"도 할 수 있습니다. 선택한 이미지는 ZIP으로 내보내거나(원본, 목록 순서대로 번호를 붙이고 원래 파일 이름 유지) 소재 라이브러리에서 제거할 수 있습니다. 제거는 목록에서 숨기는 것일 뿐이며 파일과 작업 참조는 남아 있습니다. "완료"를 클릭하면 일괄 관리를 끝냅니다.
최근 생성은 한 번 제출한 묶음별로 표시되며, 저장된 이미지마다 "이미지 다운로드"가 있습니다.
같은 묶음은 "세트 다운로드"를 클릭해 ZIP 하나로 저장할 수 있으며, 저장된 원본을 모두 포함하고 미리보기 개수의 제한을 받지 않습니다.
아직 모두 완료되지 않았을 때는 버튼이 "완료된 이미지 다운로드"로 표시되며, 생성되지 않았거나 저장에 실패한 이미지는 ZIP에 포함되지 않습니다.
저장 대화 상자를 취소하면 파일이 만들어지지 않으며, 다운로드는 이미지 생성 API를 다시 호출하지 않습니다.

키와 데이터:
키는 현재 Windows 사용자 기준으로 암호화되며 백업에 포함되지 않습니다.
컴퓨터나 사용자를 바꾼 후에는 API Key를 다시 입력하세요.
data에는 작업 데이터가, cache에는 다시 만들 수 있는 캐시가 저장됩니다.
연결 및 설정 → 데이터 위치 열기: 파일 탐색기에서 현재 폴더를 봅니다.
연결 및 설정 → 저장 위치 변경: 빈 폴더를 선택하고 이전을 확인한 뒤 사용합니다.
기존 이미지, 작업, 템플릿과 이 컴퓨터의 암호화된 키가 함께 이전되며 원래 폴더는 남아 있습니다.
새 위치는 즉시 적용되며 일반 실행 시에도 이 위치를 기억합니다. 진행 중이거나 대기 중인 작업이 있으면 먼저 끝내거나 중지해야 합니다.
백업에는 템플릿, 작업, 이미지가 포함되며 키와 임시 결과 링크는 포함되지 않습니다.
복원 전에 원래 데이터 폴더가 보존되며, 아직 제출하지 않은 작업은 키를 설정한 후 직접 재개해야 합니다.

시간 초과 및 종료:
제출하는 동안 연결 중, 중계 서버 대기 중, 결과 수신 중 등 실제 단계와 기다린 시간을 표시합니다.
2분이 넘는 느린 응답 안내는 요청을 취소하거나 자동으로 다시 시도하지 않습니다.
작업 상세는 계속 새로 고쳐지며 응답 상태와 플랫폼 요청 ID(플랫폼이 제공하는 경우)를 표시합니다.
생성 중에 최소화해도 계속 실행됩니다. 작업이 있을 때 닫으면 안내가 표시됩니다.
결과 불명(0.6.27부터): 자동으로 한 번 다시 생성하며, 정상인 예비 중계 서버를 우선 사용합니다. 원래 요청이 이미 과금되었을 수 있으므로 이 이미지는 두 번 과금될 수 있습니다. 자동으로 다시 생성한 이미지의 결과가 또 불명이면 다시 보내지 않으니 플랫폼 기록을 확인하세요.
다운로드 실패(0.6.27부터): 30초, 2분, 5분 후에 각각 자동으로 다시 다운로드하며, 이미지를 다시 받기만 하고 다시 생성하지 않습니다. 그래도 실패하면 "다시 다운로드"를 클릭할 수 있습니다. 앱을 시작할 때도 24시간 이내에 저장되지 않은 이미지를 자동으로 다시 다운로드합니다.
콘텐츠 심사 거부(0.6.28부터): 이미지 생성 모델의 콘텐츠 심사가 어떤 이미지를 거부하면(예: "이 프롬프트는 콘텐츠 정책을 위반할 수 있습니다") 먼저 그대로 한 번 자동으로 다시 보냅니다. 또 거부되면 LLM이 이 이미지의 표현만 고쳐 쓰고(상품 디자인, 따옴표 안의 화면 속 문구, 참조 이미지는 그대로) 한 번 더 보냅니다. 거부된 요청은 이미지를 만들지 않았으므로 보통 과금되지 않으며, 고쳐 쓰기에는 LLM 토큰이 조금 사용됩니다. 두 번 모두 통과하지 못했을 때만 프롬프트를 수정하거나 잘못 판정되었을 수 있는 참조 이미지를 바꾸라고 안내합니다.
상품 페이지 읽기(0.7.1부터): 브라우저가 상품 페이지를 열지 못하면(네트워크 끊김, 프록시 끊김) 자동으로 다시 열며 최대 3번 시도합니다. 아예 연결할 수 없을 때는 기다리지 않고 바로 "네트워크 연결 실패"를 알립니다. 그래도 읽지 못하면 7일 이내에 다른 제작에서 같은 링크로 읽은 상품 정보와 상품 이미지를 그대로 사용하며, 참조 이미지 업로드를 요구하지 않습니다.
수동 / 자동 모드(0.7.4부터, 0.7.5부터 스스로 답하는 방식으로 변경): 스마트 생성 페이지의 "새 요청" 옆에서 전환합니다. 수동 모드(기본값)는 부족한 정보를 한꺼번에 질문하고, 입력하면 계속 진행합니다. 자동 모드도 부족한 정보를 똑같이 찾아내지만, 제작 도우미가 질문마다 스스로 답합니다: 지시에 적힌 것은 그대로 쓰고, 원래 링크에서 알 수 있는 것은 원래 링크를 따르며, 자유롭게 고를 수 있는 것은 어울리는 것을 고르되 최근 수동 답변 10개의 습관을 참고합니다. 도저히 추론할 수 없는 것(새 이름, 실제 크기 등)은 합리적인 값을 정하고 "확인 필요"로 표시합니다. "제작 도우미의 판단"에 질문별 답, 근거, 이유를 나열하고 바로 세트 전체를 생성합니다.
보정(0.7.6부터): "보정"을 클릭해 수정 내용을 적으면, 앱은 먼저 LLM이 이 이미지의 원래 제작 요구를 수정 내용과 일치하도록 고치게 한 뒤(예: 원래 "가운데 한 마리만 자수"였는데 수정 내용이 세 마리 모두라면 세 마리 모두로 고침) 생성합니다. 고쳐 쓰는 동안 "프롬프트 고쳐 쓰는 중"이 표시되며, 전송되지 않고 과금되지 않습니다. 수정 내용에서 새 문구를 주거나 삭제를 요구하지 않는 한 기존 화면 속 문구는 유지됩니다.
디테일 샘플(0.7.8부터): 샘플 이미지는 최고 품질로 생성됩니다. 생성 후 LLM이 디자인 근거(액세서리 모양, 품종, 문구의 철자와 색, 좌우 위치)와 대조해 확인하고, 불합격이면 자동으로 다시 그리며 최대 2번입니다. 다른 이미지는 확인이 끝난 뒤에 그려지며, 샘플을 1번 참조 이미지이자 유일한 디자인 근거로 삼습니다. 제작 도우미는 참조 이미지에서 일부를 잘라내(예: 비교 이미지에서 이번 제품만 잘라냄) 깔끔한 근거로 쓸 수도 있습니다.
디자인 영역마다 샘플 하나(0.7.9부터): 한 세트에서 디자인 영역(가슴 그림, 소매 끝 이름 등)마다 샘플이 하나씩 있으며 최대 3장입니다. 가슴 등 주 디자인에는 앞면 전체의 디자인 원본을 사용해 위치, 방향, 크기를 보여 줍니다. 다른 이미지는 화면에 보이는 디자인 영역에 해당하는 샘플을 따라 그리며, 이미지 카드에 어떤 샘플을 따랐는지 표시됩니다.

진단 패키지(0.7.10부터): 문제가 생기면 왼쪽 "로그"에서 "진단 패키지 내보내기"를 클릭하고 저장된 ZIP을 소프트웨어 제공자에게 보내세요. 패키지에는 버전, 라이선스 모드, 회선 이름과 상태, 최근 로그와 실패 원인이 들어 있으며, API Key, 활성화 코드, 회선 주소, 프롬프트, 이미지, 스킬 내용은 들어 있지 않습니다.

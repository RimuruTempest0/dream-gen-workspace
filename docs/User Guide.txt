Image Workbench · Portable

From 0.7.20 the interface is dark, and the left navigation is a collapsed icon bar (it expands when you hover over it). Several items were renamed: Smart Generation → Create, Image Workbench → Pro mode, Prompt Templates → Templates, Task Center → History, Asset Library → Works & Assets. Connections & Settings, Relay Monitor, LLM Monitor and Logs moved under "System", as the four tabs "Connections", "Service status", "Model status" and "Logs". From 0.7.24 the interface and messages call the "image relay" an "image service", and the "LLM provider / LLM" an "AI model" (the licensed line names "LLM line 1 / 2" are unchanged). The rest of this guide still uses the old names.

Display language (from 0.8.0): the program can be shown in five languages: 中文 (Chinese), English, Tiếng Việt, 日本語 and 한국어. On first start it follows the Windows language, and shows Chinese if Windows uses another language; afterwards you can switch at the bottom of the left navigation or in "System → Connections → Display language". The change applies right away and is kept after a restart. The AI writes its questions, judgments and explanations in the display language; image prompts are written in Chinese when the display language is Chinese and in English otherwise; text in the image is drawn exactly as you wrote it, never translated. Saved logs and messages keep the language they were written in. The program folder has this guide in all five languages; a one-click update to 0.8.0 brings only the Chinese guide, and the other languages are in the full package.

Windows 11 x64 only.
Extract the whole archive, then double-click ImageWorkbench.exe.
Keep the runtime and agent folders and product-browser.exe next to the EXE: they are the interface runtime, the built-in Claude Code and the product page browser.
To upgrade, close the old version and make a backup first; when overwriting the program folder, keep data and data-location.txt.
From 0.7.11: the database upgrades itself the first time you open the program (with many tasks this takes a few extra seconds); after that, older versions can no longer open this data, so back up first. However many tasks you have, generation and the Task Center will not slow down.

First-time setup:
Connections & Settings → Add connection → enter a name, Base URL, API Key and default model.
For the Base URL enter the API prefix, for example https://example.com/v1.
Test connection only fetches the model list; it does not generate images.
Test connection first checks the address and key and shows a message while waiting, for at most 30 seconds; you can click "Cancel test".
Network requests use an explicit HTTP_PROXY / HTTPS_PROXY setting first; a normal start uses the manual system proxy enabled in Windows.
Model queries, image generation and image downloads follow the same network rules. Restart the program after changing the system proxy.
Windows proxy settings are never changed automatically; environments configured only with PAC are not yet auto-detected.
For relays that do not publish a model list, you can enter the model ID by hand.

Generating images:
In the workbench, choose a connection, enter a prompt and click Generate.
Adding a reference image switches to image-to-image. In batch mode, write one prompt per line.
Set size and quality according to what the model supports; auto does not send that parameter.
Images are saved to the local Asset Library automatically; Export original lets you choose where to save.
Asset Library → Batch manage: click an image to select it (click again to deselect), or use "Select all loaded". Selected images can be exported as a ZIP (originals, numbered in list order and keeping their file names) or removed from the Asset Library. Removing only hides them from the list; the files and task references are kept. Click "Done" to leave batch management.
Recent generations are shown by submitted batch, and every saved image has "Download image".
For a batch you can click "Download set" to save one ZIP containing all saved originals, not limited by how many previews are shown.
While the batch is not finished, the button reads "Download finished images"; images not generated or not saved are not in the ZIP.
Cancelling the save dialog creates no file; downloading never calls the image generation API again.

Keys and data:
Keys are encrypted for the current Windows user and are not included in backups.
After changing computer or user, enter the API Key again.
data holds your work; cache can be rebuilt.
Connections & Settings → Open data location: view the current folder in File Explorer.
Connections & Settings → Change save location: choose an empty folder, confirm the move and use it.
Existing images, tasks, templates and this computer's encrypted keys move together; the original folder is kept.
The new location takes effect immediately and is remembered for normal starts; finish or stop any active or waiting tasks first.
Backups contain templates, tasks and images, but not keys or temporary result links.
Before restoring, the original data folder is kept; tasks not yet submitted must be resumed by hand after the keys are set up.

Timeouts and quitting:
While submitting, the actual stage is shown (connecting, waiting for the relay, receiving the result) along with how long it has waited.
The slow-response notice after two minutes does not cancel the request or retry automatically.
Task details keep refreshing and show the response status and the platform request ID (if the platform provides one).
Generation continues while minimized; quitting asks first if tasks are running.
Unknown result (from 0.6.27): the image is regenerated automatically once, preferring a healthy backup relay. The original request may already have been charged, so this image may be charged twice. If an automatically regenerated image's result is still unknown, it is not sent again; please check the platform's records.
Download failed (from 0.6.27): the image is downloaded again automatically after 30 seconds, 2 minutes and 5 minutes. This only fetches the image again and never regenerates it; if it still fails, click "Download again". When the program starts, it also re-downloads images from the last 24 hours that were not saved.
Rejected by content review (from 0.6.28): when the image model's content review rejects an image (for example "this prompt may violate our content policy"), it is first resent unchanged once; if it is rejected again, the LLM rewrites only this image's wording (the product design, the text in quotes and the reference images stay the same) and it is resent once more. A rejected request produced no image and is usually not charged; rewriting uses a few LLM tokens. Only if both attempts fail are you asked to edit the prompt or replace a reference image that may have been misjudged.
Reading product pages (from 0.7.1): when the browser cannot open a product page (no network, proxy dropped) it reopens it automatically, up to 3 times; when there is no connection at all it reports "Network connection failed" quickly instead of waiting. If the page still cannot be read, the product details and product images that another job read from the same link within 7 days are reused, and you are no longer asked to upload reference images.
Manual / automatic mode (from 0.7.4; from 0.7.5 it answers by itself): switch it next to "New request" on the Smart Generation page. In manual mode (the default), missing information is asked for all at once and the job continues once you fill it in. Automatic mode finds the same missing information, but the production assistant answers each question itself: what the instructions say is used as written; what the original link shows is followed; free choices get a matching pick, following the habits of your last 10 manual answers; whatever truly cannot be inferred (such as a new name or a real size) gets a reasonable value marked "check this". "Production assistant's decisions" lists each answer with its basis and reasoning, and the whole set is generated directly.
Refine (from 0.7.6): after you click "Refine" and describe the change, the program first has the LLM rewrite this image's original production requirements to match the change (for example, if it said "only the middle one is embroidered" and the change asks for all three, it now says all three), then generates. While rewriting, "Rewriting prompt" is shown; nothing is sent and nothing is charged. Existing text in the image is kept unless the change gives new text or asks for it to be removed.
Detail sample (from 0.7.8): the sample image is generated at the highest quality. After it is generated, the LLM checks it against the design basis (accessory shape, breed, spelling and colour of text, left/right position); if it fails, it is redrawn automatically, at most 2 times. The other images wait for the check before they are drawn, and use the sample as reference image 1 and the only design basis. The production assistant can also crop a detail from a reference image (for example, cut this item out of a comparison image) as a clean basis.
One sample per design area (from 0.7.9): each design area in a set (such as the chest graphic or a name on the cuff) gets its own sample, at most 3. Main designs such as the chest use a design master of the whole front, showing position, orientation and size. Other images follow the samples for the design areas visible in them, and the image card says which samples it followed.

Diagnostic package (from 0.7.10): when something goes wrong, go to "Logs" on the left, click "Export diagnostic package" and send the saved ZIP to your software provider. It contains the version, license mode, line names and status, recent logs and failure reasons; it contains no API Key, activation code, line address, prompts, images or skill content.
Usage estimate (from 0.7.10): above "Start generating set" in Smart Generation, an estimate based on this computer's records is shown: the time per generated image and roughly how many tokens the smart analysis uses. When the customer edition can read the balance of image line 1, it also shows this job's image cost based on recent actual spending. Nothing is shown when there are no records; the relay's and LLM provider's billing is what counts. Once the customer edition is activated, "Connections & Settings → License" also shows the remaining balance of image line 1.
Shop rules (from 0.7.16): in "Connections & Settings → Shop rules", write down the requirements every set for your shop must follow; you can attach images or text material. Enabled rules take priority over all skills in Smart Generation. A skill can be given a "category": skills without a category are always used; skills with a category are used only when it is selected under Smart Generation "More settings → Product category".
Software updates (Creative Edition, from 0.7.32): when a new version is available, "New version" appears at the bottom of the left icon bar; open it to see the version number and the update notes. Click "Update now" once and the program downloads, verifies and restarts by itself; images, tasks and settings are kept, and if the update fails the previous program is restored automatically. You can click it while images are generating: after downloading, it waits for the images to finish and then restarts. To turn off automatic checking, go to "System → Connections → Software updates". If you are told a full package is needed, or the update server cannot be reached, ask your software provider for the full package and extract it over the program folder (keep data and data-location.txt). Versions before 0.7.32 do not have this feature and must first be upgraded once with the full package.
Hosted Edition (Creative Edition, from 0.7.34): if your software provider gave you a license file customer.dat, go to "System → Connections → Hosted Edition license", click "Import license file", choose it and enter the activation code. From then on the provider's lines are used, and you do not need to enter addresses or keys. A Hosted Edition package sent directly by the provider already contains it; just extract it. While hosted, you cannot add your own connections; connections you set up earlier are kept but not used. When the license expires or the trial is used up, no new images can be generated; contact the provider to renew and import the new license file. To go back to your own services: close the program, delete customer.dat from the program folder and open it again; the provider's lines are removed and your own connections return.
Software updates (from 0.7.13, E-commerce Edition): when a new version is available, "New version" appears on the left. Go to "Connections & Settings → Software updates" and click "Download update"; once it has downloaded and passed verification, click "Restart and update". The program closes, updates and reopens by itself; images, tasks, settings and the license are kept, and if the update fails the previous program is restored automatically. If images are generating, wait for them to finish before updating. You can turn off "Check for updates automatically". If you are told a full package is needed, ask your software provider for the full package and extract it over the program folder (keep data, data-location.txt and customer.dat).
Product page browser (from 0.7.13): it is used only to read product pages; it does not open new windows, download files or save passwords.
License validity (from 0.7.12): the customer edition may have an expiry date, shown as "Valid until" in "Connections & Settings → License". You are reminded 7 days before it expires; after it expires no new images can be generated, while existing images, tasks and exports are unaffected. After you renew, the software provider sends a new customer.dat; click "Import license file" in "Connections & Settings → License" and choose it. No reinstall is needed, and images and activation are kept. Please do not set the system clock back: a time more than an hour earlier than the last use is treated as expired; setting the correct time again restores it.
Built-in skills (from 0.7.17): the customer edition can also view, edit, enable or disable built-in skills (including P004; with P004 disabled its fixed rules are no longer added). The software provider can choose which built-in skills to deliver; those not delivered start disabled, and you can turn them on when you need them.
Bundled component check (from 0.7.10): if the built-in Claude Code or product-browser.exe has been replaced or damaged, the program refuses to start it and asks you to extract the software package again in full.
This version supports relays compatible with the OpenAI Images protocol. A relay's own web-only interfaces may not be compatible.
The full package needs no separate runtime installation; the fixed runtime is updated together with each new full package.

Smart Generation (0.3.0):
Set up the LLM provider and image connection in Settings, save, and verify the model's required capabilities.
In Smart Generation, enter the complete production instructions, links and reference material; the default is 12 images at 1:1.
Provider, model and image parameters are under "More settings", all chosen from drop-down lists that remember your last choice. The model list comes from the selected relay (query only, not charged), and the size follows the aspect ratio automatically. From 0.6.18, "Image model" lists every model the relay returns (for example gpt-image-2, gpt-image-2-w, gpt-image-2.5, gpt-image-2.5-flare), waiting at most 30 seconds for the query; when the relay cannot be queried for the moment, the last list obtained is shown (from "Test connection / Get models", a free check or an earlier query).
Cancel generation (from 0.6.18): in the Task Center and Smart Generation results, images waiting to run, waiting for the relay or paused have "Cancel generation". Clicking it asks "Cancel generation?"; it is cancelled only when you click "Cancel generation" again, while "Keep generating" keeps it. Images not yet submitted are not charged when cancelled. For images already submitted to the relay, the program stops waiting for the result, but the relay may still generate and charge for them; the relay's records are what count. Images the relay has already returned and that are being saved cannot be cancelled. "Stop queue" is still used to stop all images in a batch that have not been submitted.
Production time (from 0.6.19): "Time used / Total time" at the top right of Smart Generation counts only the time the program is actually working. While it waits for you to add information it shows "Timer paused"; it resumes after you add it, and the waiting time is not counted. Waiting after confirming a plan, or before continuing after an interrupted or failed analysis, is not counted either. Waits that were already added and continued in an older version are still included in the time.
Clicking "Start generating set" authorizes this job's LLM and image generation calls, which may incur charges.
Missing information is asked for all at once; once everything needed is there, the whole set is generated in the background automatically. If what you add is not enough to decide the answer, the same question appears again with the input box cleared; please answer it again as asked.
Run details (from 0.6.24): Smart Generation shows the run record of Claude Code and the LLM (tool calls, tokens and time for each request), without prompts or skill content. Run details always appear in the production progress; the entries are collapsed by default and expand when you click "Run details" (from 0.7.1 there is no longer a "Show production details" setting).
Production time limit (from 0.6.25): each job has a limit of 20 minutes. The product page is read before analysis starts. When a single model reply runs out of its output limit, thinking is turned off automatically and the plan continues to be written. When the product page has more than 8 images, the production assistant looks only at the first 8; all uploaded reference images are looked at. If run details show a network handshake timeout or a dropped connection, check your proxy or network.
No LLM reply (from 0.6.24): when a request gets no reply at all for 2 minutes, an activated version switches automatically to LLM line 2 (if set up); during the trial or without a backup line it retries once, and stops if there is still no reply. Your information is kept; click "Continue" to try again.
Production steps (from 0.6.23): during analysis, Smart Generation shows the current step and its details (reading the product page, saving product images, analysing information and reference images, planning the set, and so on), how long this step has taken and whether the model is still replying. This stage is done by the built-in production assistant and the selected LLM; image generation has not started yet, so there are no image generation charges.
Prompt templates (from 0.6.22, replacing "Projects & Templates"): create and manage them under "Prompt Templates" on the left. Both the Image Workbench and Smart Generation input boxes have "Apply template" and "Save as template" at the top right; if the box already has content, you are asked whether to replace or append, so nothing is overwritten directly. "Use in Image Workbench" and "Use in Smart Generation" on the template page take a template straight to that page. Press Ctrl + Enter in the input box to generate or start production directly.
Choose existing assets (from 0.6.21): the "Or choose existing assets" drop-down shows small previews; hover over a preview to see it large, and type a file name to filter.
Leaner built-in skills (from 0.6.26): each rule now lives in only one skill, P004 gained a pose table, and the content sent to the model is no longer repeated, so fewer tokens are used. "Load skill" no longer appears in run details; skills are sent together with the prompt. Built-in skills you have not changed are upgraded automatically.
Built-in skills (from 0.6.21): the chest and cuff designs are each planned as a fixed combination; see the changelog for the details of the rules. Built-in skills you have not changed are upgraded automatically, changed ones are kept, and requests already created are not affected. These rules only affect prompt planning; the program does not check the generated images yet, so details still need to be checked by hand after generation.
Customers only see production progress and images; they do not need to look at the analysis, rules, or edit and confirm prompts.
If reading is blocked, upload the original product images or paste a product description; technical details are in the logs. The yellow "Cannot read the product link for now" appears only when the product page truly cannot be read; when the page was read and only some images could not be saved, a single grey note is shown, and you can upload reference images if needed.
Amazon product links (including mobile /gp/aw/d/ links) read all high-resolution main images (1500 pixels) of the current variant, the product title, the "About this item" points and the product details, and no longer save the small thumbnails and icons on the page. From 0.6.14, Amazon links are simplified to amazon.com/dp/product-number automatically before reading, and punctuation such as "】" at the end of the link is removed. When Amazon occasionally returns a "Click the button below to continue shopping" page, the browser is used to read it instead; if a window pops up, click "Continue shopping" once. This page is no longer treated as product information.
Walmart product links (walmart.com/ip/…, walmart.ca is also supported) read all full-size product images of the currently selected colour, the product title, the product introduction, the detailed description and the specifications (brand, colour, size, fabric, and so on), and no longer save the small thumbnails and icons on the page. When Walmart occasionally shows a "Robot or human?" check, a window pops up asking you to press and hold the button once.
Product sites with dedicated support for now: Etsy, Amazon, Walmart. Other sites are read in a generic way; if they are not read completely, upload reference images or paste a product description.
Images can be downloaded one by one, as a whole-set ZIP, or partly finished.
When the image relay rejects the API Key (HTTP 401/403), images in the same batch that have not been submitted are paused automatically and not charged. After entering the key again in "Connections & Settings", click "Regenerate all failed images" to resume them all at once (you are reminded that charges may apply; images with unknown results are not included).
When the relay account balance is insufficient (for example it returns HTTP 403 "insufficient balance"), the message "Relay account balance is insufficient" is shown and you do not need to re-enter the API Key: top up in that relay's console, then click "Regenerate all failed images". If backup relays are set up, images in the same batch that have not been sent are switched to a backup automatically, at no extra charge.
Customer edition (customer.dat next to the program): the first start gives a trial of 20 images (during the trial only image line 1 and LLM line 1 are shown and used), and the remaining count is shown on the left. Successfully generated images count; failed, cancelled and rejected ones do not; an unknown result counts as 1 image. Reinstalling or clearing data does not reset the trial. When it is used up, enter the activation code in "Connections & Settings → License" to enable all lines (including backups); earlier images and tasks are kept, and you never need to enter it again on later starts or upgrades. The customer edition neither shows nor lets you change line addresses and keys.
Click any image in a set to see the full-size original: use Previous/Next or the ← → keys to switch, click the image to switch between fit to window and actual size, and download the original or refine it directly.
A finished image can be refined with "Refine": write how you want it adjusted, and it is generated once more using this image as the base (may incur charges). The old version is kept under "Previous versions", and set downloads contain only the current version. State clearly what to change and what to change it to (for example "move the paw print on the cuff to the left of the name Amelia, in one row"); this is easier to get right than a judgement such as "it should be side by side". To replace something already in the image, say what to remove and what to replace it with (for example "the woman on the right takes off the off-white cardigan and wears the same sweatshirt as the one on the left, colour Maroon, with chest graphic and cuff embroidery exactly the same as on the left"). From 0.6.11 the adjustment takes priority over how the original image looks. From 0.6.17, when an image whose cuff was drawn from the sample image is refined, the sample image is sent to the image model too; when asked to straighten the cuff text, the embroidered arm may be straightened.
Sets from Smart Generation are shown only on the Smart Generation page, not in "Recent generations" of the Image Workbench.
When you leave Smart Generation and come back, if the latest request is not finished (analysing, waiting for information, generating, or with paused images) you return to it automatically; if it is finished, the new request page is shown. The progress ring after "Smart Generation" on the left shows how many images are finished; it spins while analysing and shows a yellow dot while waiting for information.
When an image shows "The relay disconnected after waiting about N seconds (HTTP 524)", this is caused by the relay's synchronous interface limit of about 2 minutes. The image may already have been generated and charged; please check in the relay's console before deciding whether to regenerate.
More settings → Images at once: choose how many image requests are sent to the relay at the same time (1–4, default 3). You can change it during generation and it takes effect immediately; when lowered, images already generating still finish. Relays may limit concurrency; if many fail or you see HTTP 429, lower it. As soon as an image finishes generating it frees its slot, and downloading continues in the background (at most 4 downloads at once) without using the images-at-once slots; cards show the "Generate" and "Download" times separately.
Multiple image relays (Connections & Settings → Image relays / Backup switching): set one relay as "Primary", turn on "Backup" for the others and put them in order. During generation the program runs a free check every 3 minutes (only reads the model list, generates nothing, costs nothing) and shows "Healthy / Slow / Unavailable". When the primary is slow or unavailable, images not yet sent switch automatically to a healthy backup relay with exactly the same model ID, at no extra charge. "After 524, switch relay and regenerate automatically" is off by default; before turning it on you are warned about charges: each timed-out image is regenerated automatically at most once, at most 3 per batch; the original request may already have been charged, so you may be charged twice. Without primary/backup set up, everything works as before.
If the LLM connection drops during analysis (for example the local proxy disconnects), Claude Code retries automatically; when it succeeds, the page only shows "The LLM connection dropped once; retried automatically and finished", and image generation is not affected. "Production not finished" is shown only when production really fails, and the detailed error notes the dropped connection.
Relay Monitor / LLM Monitor (left navigation): Relay Monitor counts, per relay, every image request actually sent (succeeded, unknown result, failed, time, switched in or out and the relay request ID); LLM Monitor counts every request sent to an LLM provider (time, tokens, dropped connections and errors) and totals them per Smart Generation request. You can filter by time, connection and type, and export call records as CSV to check billing against each provider's console. Request content and API Keys are not saved.
After cancelling, an abnormal exit or a restore, nothing is re-analysed or submitted automatically; images waiting to be generated can be resumed explicitly.
An unknown result is regenerated automatically once (may be charged twice); downloading again never regenerates.
Old requests can be resumed explicitly with "Continue"; batches already submitted are never created twice.
Skills are enabled, disabled and managed in Settings; they only carry out instructions and material, and the version is frozen while running.
The built-in "P004 image rules" skill is enabled by default: Western models; embroidery no larger than 25 cm and consistent across images; chest embroidery on sweatshirts centred on the garment's centre line; cuff embroidery only on the sleeve on the right side of the image, with the text parallel to the cuff seam; the whole image sharp, not blurred. When it is enabled, these rules are added to every image's prompt in the background. After you change or disable this skill they are no longer added. When the product has no cuff embroidery (for example the instructions say "no design on the cuffs"), from 0.5.2 the two cuff rules are no longer added; instead the prompt says neither cuff has embroidery.
The built-in "How to write image prompts" skill (0.5.1) is enabled by default: each prompt in a set states, line by line, its purpose, what each reference image is for and the text that must appear in the image (names spelled out letter by letter), and adds no brands, text or props that were not asked for; when a plan is revised, only the affected images change. The skill content is in English; the interface and questions are still in Chinese. When it conflicts with other skills such as P004, the other skill wins.
Keeping the design consistent within a set (0.5.5): the main design is written in the locked items as two sentences, "the design contains only…" and "the design has no…". When the design was changed but the reference images still show the old design, the removed old features are named (such as a Santa hat or string lights), and all images use the same group of reference images in the same order.
E-commerce set planning (0.6.8, formerly "Etsy set planning"): applies to Etsy, Amazon and Walmart, with the target platform taken from the instructions; Amazon/Walmart main images default to a pure white background with only the product. Detail images are macro close-ups; scenes such as parties state the number of people and the props; with a theme such as Christmas, every scene image has themed props; option images such as thread colours or fonts use only options with a basis, and if there is no basis you are asked for one. From 0.6.11, every image in which the cuff is visible describes the cuff name and icon in the same sentence (same row or stacked, left/right order, text direction), and the embroidered arm hangs naturally, so the whole set is arranged consistently.
Detail sample image (0.6.12): when small details such as a cuff name and icon appear in 3 or more images, a close-up of the cuff is generated first as a sample, and the other images in which the cuff is visible are drawn from it once it is finished (the card shows "Waiting for sample image"; while waiting nothing is submitted or charged, usually 30–60 seconds more). The sample image is one of the images in the set, not an extra one; if the sample fails, the other images are generated from the text description as usual.
Straight cuff text (0.6.13): P004 now has the embroidered sleeve hanging straight down in the image, with the cuff text level instead of tilting with the sleeve; every image showing the whole garment draws the cuff from the sample; images without the product, such as thread colour cards and fabric swatches, are no longer drawn as a whole garment.

Product page browser (0.3.1):
When a product site blocks direct reading, the program opens the product page in the built-in browser in the background, usually within a dozen seconds or so.
If a "Will continue automatically after verification" window appears, complete the site's verification in the window; it continues automatically afterwards.
If you close that window or more than 3 minutes pass, you are asked instead to upload product images or paste a description.
Browser cookies are saved in the current data folder and are not included in backups; Connections & Settings → Clear product page browser data deletes them.
The browser only reads pages; Claude cannot operate it. Not every site is guaranteed to be readable.

Logs (0.2.2):
"Logs" on the left shows the stages and errors of the program, connection verification, smart analysis and image generation tasks.
You can filter by log level, source, keyword and related ID, view details, page through, and refresh manually or automatically.
The latest 5000 entries are kept; they move and are backed up with the current data folder, and keys are masked before writing.
Recording starts from this version; logs for old tasks are not made up, and old tasks can be viewed in the Task Center.

LLM single output limit: 65536 tokens by default (from 0.7.2, including the model's thinking; the 8192 and 32768 saved by older versions are applied as 65536 automatically, with no need to re-verify the line). When thinking uses up this limit before the plan is written, the following requests of this job turn thinking off and write the plan directly. If the model you use supports a lower limit, enter that model's actual limit in "Connections & Settings → LLM provider → Edit".

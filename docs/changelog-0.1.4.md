# 0.1.4 网络接收修复

普通资源管理器双击启动不继承 Codex 终端的进程代理变量；此前 Go 客户端只使用环境代理，没有读取 Windows 系统代理。本机已启用手动系统代理，但用户与系统环境未持久设置 HTTP_PROXY / HTTPS_PROXY，因此旧应用普通启动会直连。

修复为：显式环境代理优先，否则读取当前 Windows 用户的手动系统代理。尊重系统绕过规则和 NO_PROXY，localhost 保持直连。模型查询、生成、图片下载一致使用此规则。不改系统设置、不关闭 TLS 验证、不自动重发。PAC 自动发现暂不支持。任务详情新增实际网络路由。

## 验证证据

公开静态文件 `/assets/index-DPDAQkXl.js`，大小 208,445 字节，未携带密钥、未调用生成接口：

| 网络方式 | 结果 |
|---|---|
| 当前进程代理 | 约 2.256 秒完整接收 |
| 强制直连 | 30 秒超时，只收到 106,559 字节 |
| 修复后，清除所有进程代理变量 | 成功读取 Windows 系统代理，约 2.742 秒完整接收 |

HTTP/1.1 和 HTTP/2 经当前代理都能完整接收该文件。不能据此认定是 HTTP/2 特有问题。系统代理模拟路由、localhost/NO_PROXY 绕过、本地图片协议测试通过。

真实请求：2026-10-11 20:39:42，gpt-image-2，平台报告 24.43 秒；客户端接收数据缓慢增长，20:49:42 达到 10 分钟超时，总计 1,436,111 字节，未解析出完整 JSON。平台请求 ID 为 459746ba-4127-4830-a44d-550a12086030。没有重发付费生成请求；既有请求的缺失数据无法通过软件升级恢复。

此次验证证明网络路由差异及修复后的系统代理读取/接收行为，尚未在付费生成接口重新验证。

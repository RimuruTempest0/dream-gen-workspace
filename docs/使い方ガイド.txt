Image Workbench · Portable

0.7.20 から画面はダークテーマになり、左側のナビゲーションはアイコンバーに折りたたまれ（マウスを重ねると展開します）、名称も変わりました：スマート生成→創作、Image Workbench→プロモード、プロンプトテンプレート→テンプレート、タスクセンター→生成履歴、素材ライブラリ→作品と素材。接続と設定、中継サーバー監視、LLM 監視、ログは「システム」にまとめられ、それぞれ「接続」「サービス状態」「モデル状態」「ログ」の 4 つのタブになりました。0.7.24 から画面とメッセージでは「中継サーバー」を「画像サービス」、「LLM プロバイダー / LLM」を「AI モデル」と呼びます（ライセンス回線名「LLM 回線 1 / 2」は変わりません）。以下では旧名称のまま説明します。

表示言語（0.8.0 以降）：画面は 中文、English、Tiếng Việt、日本語、한국어 の 5 言語で表示できます。初回起動時は Windows の言語に合わせ、この 5 つ以外のときは中国語で表示します。その後は左側のナビゲーションの下部、または「システム → 接続 → 表示言語」で切り替えられ、すぐに反映され、再起動後も保たれます。AI の質問、判断、説明は表示言語で書かれます。画像プロンプトは表示言語が中国語のときは中国語、それ以外は英語で書かれます。画像内の文字はあなたが書いたとおりに描かれ、翻訳されません。保存済みのログや説明は書かれたときの言語のままです。プログラムフォルダーには 5 言語の使い方ガイドがあります。ワンクリック更新で 0.8.0 にした場合は中国語版だけが入り、ほかの言語版はフルパッケージに含まれます。

Windows 11 x64 のみ対応しています。
圧縮ファイルをすべて展開し、ImageWorkbench.exe をダブルクリックします。
EXE と同じ階層にある runtime、agent フォルダーと product-browser.exe は残してください。それぞれ画面の実行コンポーネント、内蔵の Claude Code、商品ページブラウザーです。
アップグレードの前に旧バージョンを閉じ、バックアップを作成してください。プログラムフォルダーを上書きするときは data と data-location.txt を残してください。
0.7.11 から：初回起動時にデータベースが自動でアップグレードされます（タスクが多い場合は数秒多くかかります）。その後は旧バージョンでこのデータを開けなくなるため、先にバックアップしてください。タスクがいくら多くても、生成とタスクセンターは遅くなりません。

初回設定：
接続と設定 → 接続を追加 → 名前、Base URL、API Key、既定のモデルを入力します。
Base URL には API のプレフィックスを入力します。例：https://example.com/v1。
接続テストはモデル一覧を取得するだけで、画像は生成しません。
接続テストはまずアドレスとキーを確認し、待機中はメッセージを表示します。最長 30 秒で、「テストをキャンセル」をクリックできます。
ネットワーク要求は明示的な HTTP_PROXY / HTTPS_PROXY の設定を優先し、通常の起動では Windows で有効にした手動のシステムプロキシを使います。
モデルの照会、画像生成、画像のダウンロードは同じネットワークルールを使います。システムプロキシを変更したらアプリを再起動してください。
Windows のプロキシは自動で変更しません。PAC のみを設定した環境の自動検出にはまだ対応していません。
モデル一覧を公開していない中継サーバーでは、モデル ID を手入力できます。

画像の生成：
ワークベンチで接続を選び、プロンプトを入力して「生成」をクリックします。
参照画像を追加すると画像から画像への生成になります。一括モードでは 1 行に 1 つのプロンプトを書きます。
サイズと品質は使用するモデルの能力に合わせて入力してください。auto の場合はそのパラメーターを送信しません。
画像はローカルの素材ライブラリに自動保存されます。「元画像を書き出す」では保存先を選べます。
素材ライブラリ → 一括管理：画像をクリックすると選択され（もう一度クリックで解除）、「読み込み済みをすべて選択」もできます。選択した画像は ZIP として書き出す（元画像、一覧の順に番号を付け、元のファイル名を保持）か、素材ライブラリから外すことができます。外すのは一覧から非表示にするだけで、ファイルとタスクからの参照は残ります。「完了」をクリックすると一括管理を終了します。
最近の生成は送信した回ごとに表示され、保存済みの各画像に「画像をダウンロード」があります。
同じ回の画像は「セットをダウンロード」で 1 つの ZIP に保存できます。保存済みの元画像をすべて含み、プレビューの表示数には制限されません。
すべて完了していないうちはボタンが「完了した画像をダウンロード」と表示され、未生成または保存に失敗した画像は ZIP に含まれません。
保存ダイアログをキャンセルしてもファイルは作られません。ダウンロードで画像生成 API を再び呼び出すことはありません。

キーとデータ：
キーは現在の Windows ユーザーで暗号化され、バックアップには含まれません。
パソコンやユーザーを変えた場合は、API Key を入力し直してください。
data には作業データ、cache には再作成できるキャッシュが保存されます。
接続と設定 → データの場所を開く：エクスプローラーで現在のフォルダーを表示します。
接続と設定 → 保存場所を変更：空のフォルダーを選び、移行を確認して使用します。
既存の画像、タスク、テンプレート、このパソコンの暗号化されたキーが一緒に移行され、元のフォルダーは残ります。
新しい場所はすぐに有効になり、通常の起動でもその場所を記憶します。実行中や待機中のタスクがある場合は、先に終了または停止してください。
バックアップにはテンプレート、タスク、画像が含まれ、キーと一時的な結果リンクは含まれません。
復元の前に元のデータフォルダーは残されます。まだ送信していないタスクは、キーを設定してから手動で再開してください。

タイムアウトと終了：
送信中は、接続中、中継サーバー待ち、結果の受信中といった実際の段階と待機時間を表示します。
2 分を超える応答遅延のお知らせは、要求をキャンセルしたり自動で再試行したりしません。
タスクの詳細は随時更新され、応答状態とプラットフォームの要求 ID（提供されている場合）を表示します。
生成中に最小化しても処理は続きます。タスクがあるときに閉じると確認が表示されます。
結果不明（0.6.27 から）：自動で 1 回再生成し、正常な予備の中継サーバーを優先して使います。元の要求がすでに課金されている可能性があるため、この画像は 2 回課金されることがあります。自動で再生成した画像の結果がまた不明の場合は自動では再送しないので、プラットフォームの記録を確認してください。送り直す場合は「失敗した画像をすべて再生成」をクリックします。自動再生成が画像サービスに拒否された場合（利用枠の使い切り、Key の誤りなど）、カードにはその拒否が表示されます。
ダウンロード失敗（0.6.27 から）：30 秒後、2 分後、5 分後に自動で再ダウンロードします。画像を取り直すだけで、再生成はしません。それでも失敗した場合は「再ダウンロード」をクリックできます。アプリの起動時にも、24 時間以内に保存されなかった画像を自動で再ダウンロードします。
コンテンツ審査による拒否（0.6.28 から）：画像生成モデルのコンテンツ審査がある画像を拒否した場合（例：「このプロンプトはコンテンツポリシーに違反している可能性があります」）、まずそのまま自動で 1 回再送します。また拒否されたら、LLM がこの画像の言い回しだけを書き換え（商品デザイン、引用符内の画面上の文字、参照画像は変えません）、もう 1 回再送します。拒否された要求は画像を生成していないため、通常は課金されません。書き換えには LLM のトークンを少し使います。2 回とも通らなかった場合にのみ、プロンプトの修正や、誤判定された可能性のある参照画像の差し替えを求めます。
商品ページの読み取り（0.7.1 から）：ブラウザーが商品ページを開けない（ネットワーク切断、プロキシの切断）場合は自動で開き直し、最大 3 回試します。まったく接続できないときはすぐに「ネットワーク接続に失敗しました」と表示し、無駄に待ちません。それでも読み取れない場合は、7 日以内に別の制作で同じリンクから読み取った商品情報と商品画像を使い、参照画像のアップロードは求めません。
手動 / 自動モード（0.7.4 から、0.7.5 から自分で回答する方式に変更）：スマート生成ページの「新しい依頼」の横で切り替えます。手動モード（既定）では、足りない情報をまとめて質問し、入力すると続行します。自動モードでも足りない情報を見つけますが、制作アシスタントが各質問に自分で答えます：指示に書かれていることはそのまま使い、元のリンクから分かることは元のリンクに従い、自由に選べることは合うものを選び、最近の手動回答 10 件の傾向を参考にします。どうしても推測できないこと（新しい名前、実際のサイズなど）は妥当な値を選び「要確認」と表示します。「制作アシスタントの判断」には各質問の回答、根拠、理由が一覧表示され、そのままセット全体を生成します。
最適化（0.7.6 から）：「最適化」をクリックして修正内容を入力すると、アプリはまず LLM にこの画像の元の制作要件を修正内容に合わせて書き換えさせ（例：元は「真ん中の 1 匹だけ刺繍あり」で、修正で 3 匹とも刺繍ありにする場合は 3 匹とも刺繍ありに書き換えます）、それから生成します。書き換え中は「プロンプトを書き換え中」と表示され、送信も課金もされません。修正内容で新しい文字を指定するか削除を求めない限り、元の画面上の文字は保持されます。
詳細サンプル（0.7.8 から）：サンプル画像は最高品質で生成されます。生成後、LLM がデザインの根拠（アクセサリーの形、品種、文字のつづりと色、左右の位置）と照合し、不合格なら自動で描き直します（最大 2 回）。ほかの画像は照合が終わるのを待ってから描かれ、サンプルを 1 枚目の参照画像かつ唯一のデザインの根拠として使います。制作アシスタントは参照画像から一部を切り出して（例：比較画像から今回の 1 点だけを切り出す）すっきりした根拠にすることもできます。
デザイン領域ごとにサンプル 1 枚（0.7.9 から、0.8.1 で変更）：セット内のデザイン領域（胸の図柄、袖口の名前など）ごとにサンプルを 1 枚作り、最大 3 枚です。サンプルが固定するのはそのデザイン領域の中のデザインだけです。できるだけ参照画像からその領域を切り出して使い、新しいデザインで切り出せるものがない場合だけ、そのデザイン領域のサンプルを描きます（0.8.1 から前面全体の画像は使いません）。ほかの画像は（最適化も含め）、画面に見えるデザイン領域に対応するサンプルからデザインだけを写し、サンプルの構図、ポーズ、見せ方、シーンは写しません。画像カードにはどのサンプルに従ったかが表示されます。

診断パッケージ（0.7.10 から）：問題が起きたら、左側の「ログ」で「診断パッケージを書き出す」をクリックし、保存した ZIP をソフトウェア提供元に送ってください。パッケージにはバージョン、ライセンスモード、回線の名前と状態、最近のログ、失敗の原因が含まれ、API Key、アクティベーションコード、回線のアドレス、プロンプト、画像、スキルの内容は含まれません。
使用量の目安（0.7.10 から）：スマート生成の「セットの生成を開始」の上に、このパソコンの記録に基づく目安を表示します：1 枚あたりの生成時間、スマート分析で使うおおよそのトークン数。顧客版が画像回線 1 の残高を読み取れる場合は、最近の実際の消費から計算した今回の画像費用も表示します。記録がない場合は表示されません。実際の金額は中継サーバーと LLM プロバイダーの請求によります。顧客版をアクティベートすると、「接続と設定 → ライセンス」にも画像回線 1 の残高が表示されます。
ショップルール（0.7.16 から）：「接続と設定 → ショップルール」に、あなたのショップのすべてのセットが守るべき要件を書きます。画像や文字資料を添付できます。有効なルールはスマート生成時にすべてのスキルより優先されます。スキルには「カテゴリー」を設定できます：カテゴリーのないスキルは毎回使われ、カテゴリーのあるスキルはスマート生成の「詳細設定 → 商品カテゴリー」で選ばれたときだけ使われます。
ソフトウェアの更新（クリエイティブ版、0.7.32 から）：新しいバージョンがあると、左側のアイコンバーの下部に「新しいバージョンがあります」と表示され、開くとバージョン番号と更新内容を確認できます。「今すぐ更新」を 1 回クリックすると、ソフトウェアが自分でダウンロード、検証、再起動を行います。画像、タスク、設定はすべて保持され、更新に失敗した場合は元のプログラムに自動で戻ります。画像の生成中でもクリックでき、ダウンロード後は画像の完了を待ってから自動で再起動します。自動確認が不要な場合は「システム → 接続 → ソフトウェアの更新」でオフにできます。フルパッケージが必要と表示された場合や更新サーバーに接続できない場合は、ソフトウェア提供元からフルパッケージを入手し、プログラムフォルダーに上書き展開してください（data と data-location.txt は残します）。0.7.32 より前のバージョンにはこの機能がないため、先にフルパッケージで 1 回アップグレードしてください。
ホスト版（クリエイティブ版、0.7.34 から）：ソフトウェア提供元からライセンスファイル customer.dat を受け取った場合は、「システム → 接続 → ホスト版ライセンス」で「ライセンスファイルを読み込む」をクリックしてそれを選び、アクティベーションコードを入力します。以後は提供元の回線を使い、アドレスや Key を自分で入力する必要はありません。提供元から直接送られたホスト版のソフトウェアパッケージにはすでに含まれているので、展開するだけです。ホスト版の利用中は自分の接続を追加できず、以前に設定した接続は保持されますが使われません。期限切れや試用分の使い切り後は新しい画像を生成できないので、提供元に連絡して更新し、新しいライセンスファイルを読み込んでください。自分のサービスに戻すには：ソフトウェアを閉じ、プログラムフォルダー内の customer.dat を削除してから開き直します。提供元の回線は削除され、元の接続が戻ります。
ソフトウェアの更新（0.7.13 から、EC 版）：新しいバージョンがあると左側に「新しいバージョンがあります」と表示されます。「接続と設定 → ソフトウェアの更新」で「更新をダウンロード」をクリックし、ダウンロードと検証が終わったら「再起動して更新」をクリックします。ソフトウェアが自動で閉じ、更新して開き直します。画像、タスク、設定、ライセンスはすべて保持され、更新に失敗した場合は元のプログラムに自動で戻ります。画像の生成中は、完了を待ってから更新してください。自動確認が不要な場合は「更新を自動で確認」をオフにできます。フルパッケージが必要と表示された場合は、ソフトウェア提供元からフルパッケージを入手し、プログラムフォルダーに上書き展開してください（data、data-location.txt、customer.dat は残します）。
商品ページブラウザー（0.7.13 から）：商品ページの読み取りにだけ使い、新しいウィンドウを開いたり、ファイルをダウンロードしたり、パスワードを保存したりはしません。
ライセンスの有効期限（0.7.12 から）：顧客版には有効期限がある場合があり、「接続と設定 → ライセンス」に「有効期限」が表示されます。期限の 7 日前にお知らせします。期限が切れると新しい画像は生成できませんが、既存の画像、タスク、書き出しには影響しません。更新するとソフトウェア提供元から新しい customer.dat が届くので、「接続と設定 → ライセンス」で「ライセンスファイルを読み込む」をクリックしてそれを選ぶだけです。再インストールは不要で、画像とアクティベーション状態はすべて保持されます。システムの時刻を戻さないでください：前回の使用時刻より 1 時間以上前の時刻は期限切れとみなされます。正しい時刻に戻せば元に戻ります。
内蔵スキル（0.7.17 から）：顧客版でも内蔵スキル（P004 を含む。P004 を無効にすると、その固定ルールは付加されなくなります）を表示、編集、有効化、無効化できます。ソフトウェア提供元は、どの内蔵スキルを付けて納品するかを選べます。付いていないものは最初は無効になっており、必要なら自分で有効にできます。
同梱コンポーネントの検証（0.7.10 から）：内蔵の Claude Code や product-browser.exe が置き換えられたり壊れたりした場合、ソフトウェアはそれらの起動を拒否し、ソフトウェアパッケージをもう一度すべて展開するよう求めます。
このバージョンは OpenAI Images 互換の中継プロトコルに対応しています。中継サーバー独自の Web 専用インターフェースは互換性があるとは限りません。
フルパッケージはランタイムを別途インストールする必要がありません。固定ランタイムは新しいバージョンのフルパッケージと一緒に更新されます。

スマート生成（0.3.0）：
設定で LLM プロバイダーと画像生成の接続を設定し、保存してモデルに必要な能力を検証します。
スマート生成に完全な制作指示、リンク、参照素材を入力します。既定は 12 枚、1:1 です。
プロバイダー、モデル、画像のパラメーターは「詳細設定」にあり、すべてドロップダウンで選び、前回の選択を記憶します。モデル一覧は選択した中継サーバーから取得し（照会のみ、課金なし）、サイズは画面比率に合わせて自動で決まります。0.6.18 から「画像生成モデル」には中継サーバーが返すすべてのモデル（例：gpt-image-2、gpt-image-2-w、gpt-image-2.5、gpt-image-2.5-flare）が表示され、照会は最長 30 秒待ちます。中継サーバーを一時的に照会できない場合は、前回取得した一覧（「接続テスト / モデルを取得」、無料チェック、以前の照会から）を表示します。
生成のキャンセル（0.6.18 から）：タスクセンターとスマート生成の結果で、実行待ち、中継サーバー待ち、一時停止中の画像の横に「生成をキャンセル」があります。クリックすると「生成をキャンセルしますか？」と表示され、もう一度「生成をキャンセル」をクリックすると実行されます。「生成を続ける」をクリックすると残ります。まだ送信していない画像はキャンセルしても課金されません。すでに中継サーバーに送信した画像は、キャンセル後は結果を待ちませんが、中継サーバーが生成して課金する可能性があるので、中継サーバーの記録を基準にしてください。中継サーバーから返ってきて保存中の画像はキャンセルできません。「キューを停止」は引き続き、その回のまだ送信していない画像をすべて止めるために使います。
制作時間（0.6.19 から）：スマート生成の右上の「経過時間 / 累計時間」は、アプリが実際に処理している時間だけを数えます。情報の追加を待っている間は「計測を一時停止中」と表示され、追加すると計測が再開し、待ち時間は含まれません。プランの確認後や、分析の中断・失敗のあとに続行するまでの待ち時間も含まれません。旧バージョンで追加して続行済みの待ち時間は、引き続き時間に含まれます。
「セットの生成を開始」をクリックすると、今回の LLM と画像生成サービスの呼び出しを許可したことになり、費用が発生する場合があります。
情報が足りない場合はまとめて追加し、必要な情報がすべてそろうとバックグラウンドで自動的にセット全体を生成します。追加した内容で答えを決められない場合は、同じ質問がもう一度表示され、入力欄は空になるので、質問に沿って入力し直してください。
実行の詳細（0.6.24 から）：スマート生成に Claude Code と LLM の実行記録（ツールの呼び出し、要求ごとのトークン数と時間）を表示します。プロンプトとスキルの内容は含みません。実行の詳細は制作の進行状況に常に表示され、明細は既定で折りたたまれており、「実行の詳細」をクリックすると展開されます（0.7.1 から「制作の詳細を表示」の設定はなくなりました）。
制作時間の上限（0.6.25 から）：1 回の制作の上限は 20 分です。商品ページは分析の開始前に読み取ります。モデルの 1 回の応答が出力上限を使い切った場合は、自動で思考をオフにしてプランの作成を続けます。商品ページの画像が 8 枚を超える場合、制作アシスタントは最初の 8 枚だけを見ます。アップロードした参照画像はすべて見ます。実行の詳細にネットワークのハンドシェイクのタイムアウトや接続の切断が表示された場合は、プロキシやネットワークを確認してください。
LLM の応答なし（0.6.24 から）：要求に 2 分間まったく応答がない場合、アクティベート済みのバージョンは自動で LLM 回線 2（設定されている場合）に切り替えます。試用期間中や予備回線がない場合は 1 回再試行し、それでも応答がなければ停止します。情報は保持され、「制作を続ける」をクリックすると再試行できます。
制作の手順（0.6.23 から）：分析中、スマート生成には現在の手順と詳細（商品ページの読み取り、商品画像の保存、情報と参照画像の分析、セットの計画など）、その手順にかかった時間、モデルがまだ応答中かどうかが表示されます。この間の処理は内蔵の制作アシスタントと選択した LLM が行い、画像生成はまだ始まっていないため、画像生成の費用は発生しません。
プロンプトテンプレート（0.6.22 から、「プロジェクトとテンプレート」に代わるもの）：左側の「プロンプトテンプレート」で新規作成と管理を行います。Image Workbench とスマート生成の入力欄の右上には「テンプレートを適用」と「テンプレートとして保存」があり、入力欄にすでに内容がある場合は置き換えるか追加するかを先に確認し、直接上書きはしません。テンプレートページの「Image Workbench で使う」「スマート生成で使う」で、そのまま対応するページに持って行けます。入力欄で Ctrl + Enter を押すと、そのまま生成または制作を開始します。
既存の素材を選ぶ（0.6.21 から）：「既存の素材から選ぶこともできます」のドロップダウンには小さなプレビューが表示され、プレビューにマウスを重ねると大きく表示されます。ファイル名を入力して絞り込めます。
内蔵スキルの簡素化（0.6.26 から）：各ルールは 1 つのスキルにだけ置かれ、P004 にポーズ表が追加され、モデルに送る内容の重複がなくなってトークンが減りました。実行の詳細に「スキルを読み込み」は表示されなくなり、スキルはプロンプトと一緒に送られます。変更していない内蔵スキルは自動でアップグレードされます。
内蔵スキル（0.6.21 から）：胸と袖口のデザインはそれぞれ固定の組み合わせとして計画されます。ルールの詳細は更新履歴を参照してください。変更していない内蔵スキルは自動でアップグレードされ、変更したものは保持され、作成済みの依頼には影響しません。これらのルールはプロンプトの計画にだけ影響し、アプリは現時点で完成画像をチェックしないため、生成後も細部は人の目で確認する必要があります。

読み取りが妨げられた場合は、商品の元画像をアップロードするか商品説明を貼り付けてください。技術的な詳細はログにあります。黄色の「商品リンクを一時的に読み取れません」は、商品ページを本当に読み取れないときだけ表示されます。ページは読み取れて一部の画像だけ保存できなかった場合は、灰色の説明が 1 行表示されるだけなので、必要に応じて参照画像を追加してください。
Amazon の商品リンク（モバイル版の /gp/aw/d/ リンクを含む）では、現在のバリエーションのすべての高解像度メイン画像（1500 ピクセル）、商品タイトル、「About this item」の要点、商品の詳細を読み取り、ページ上の小さなサムネイルやアイコンは保存しなくなりました。0.6.14 から、Amazon のリンクは自動で amazon.com/dp/商品番号 に簡略化してから読み取り、リンク末尾の「】」などの記号は取り除きます。Amazon がときどき「Click the button below to continue shopping」のページを返す場合は、ブラウザーでの読み取りに切り替えます。ウィンドウが表示されたら「Continue shopping」を 1 回クリックするだけです。このページが商品情報として扱われることはなくなりました。
Walmart の商品リンク（walmart.com/ip/…、walmart.ca にも対応）では、現在選択している色のすべての原寸の商品画像、商品タイトル、商品紹介、詳細説明、仕様（ブランド、色、サイズ、生地など）を読み取り、ページ上の小さなサムネイルやアイコンは保存しなくなりました。Walmart がときどき「Robot or human?」の確認を表示した場合は、ウィンドウが開くので、ボタンを 1 回長押ししてください。
現在個別に対応している商品サイト：Etsy、Amazon、Walmart。ほかのサイトは汎用の方法で読み取ります。読み取りが不完全な場合は、参照画像をアップロードするか商品説明を貼り付けてください。
画像は 1 枚ずつのダウンロード、セット全体の ZIP、一部完了分のダウンロードに対応しています。
画像生成の中継サーバーが API Key を拒否した場合（HTTP 401/403）、同じ回のまだ送信していない画像は自動で一時停止し、課金されません。「接続と設定」でキーを入力し直したら、「失敗した画像をすべて再生成」をクリックすると一度に再開できます。失敗・一時停止・結果不明の画像をすべて送り直します。確認画面には合計枚数とそのうち結果不明の枚数が表示されます（結果不明の画像は元の要求ですでに課金されている可能性があり、送り直すと二重に課金される場合があります）。確認は 1 回だけです。
画像サービスが利用枠の使い切りで拒否した場合（試用枠やアカウント残高を含む。例：HTTP 403「insufficient balance」や「该令牌额度已用尽」が返る）、表示は常に「回線の利用枠を使い切りました」です。API Key を入力し直す必要はありません。同じ回のまだ送信していない画像は一時停止し、課金されません。利用枠が戻ったら（その中継サーバーの管理画面でチャージ、ホスト版はソフトウェア提供元に連絡、試用中はアクティベーションコードを入力）、「失敗した画像をすべて再生成」をクリックしてください。予備の中継サーバーを設定している場合、同じ回のまだ送信していない画像は自動で予備に送り直され、追加の課金はありません。
顧客版（プログラムの横に customer.dat がある場合）：初回起動ですぐに 20 枚まで試用できます（試用期間中は画像回線 1 と LLM 回線 1 だけを表示・使用します）。左側に残り枚数が表示されます。生成に成功した画像は数えられ、失敗、キャンセル、拒否されたものは数えられません。結果不明は 1 枚と数えます。再インストールやデータの消去で試用はリセットされません。使い切ったら「接続と設定 → ライセンス」でアクティベーションコードを入力すると、すべての回線（予備を含む）が有効になります。それまでの画像とタスクはすべて保持され、以後の起動やアップグレードで再入力する必要はありません。顧客版では回線のアドレスと Key は表示されず、変更もできません。
セット内の任意の画像をクリックすると元画像を大きく表示します：前へ/次へ、またはキーボードの ← → で切り替え、画像をクリックするとウィンドウに合わせる/実際のサイズを切り替えます。そのまま元画像をダウンロードしたり最適化したりできます。
完了した画像は「最適化」をクリックし、どう調整したいかを書くと、新しい生成リクエストを送ります（費用が発生する場合があります）。旧バージョンは「以前のバージョン」に残り、新しい画像はセット内の同じ位置に入ります。セット全体のダウンロードには現在のバージョンだけが含まれます。0.8.1 から方法は 2 つです。モデル・人物・ポーズ・シーン・見せ方（例：平置きにする）を変える場合は、元の画像を修正せず、この画像のプランから生成し直すため、見た目がはっきり変わります。商品そのものとデザイン領域のデザインは変わりません。その他の部分的な調整（例：明るく、袖口をまっすぐに）は元の画像を修正します。送信後に AI がどちらかを判断し、画像カードに「プランから生成し直し」か「元の画像を修正」かを表示します。判断できなかった場合は元の画像を修正し、カードにもそう表示されます。調整の要望は、どこをどう変えるかを具体的に書いてください（例：「袖口の犬の足跡を名前 Amelia の左に移し、2 つを 1 列に並べる」）。「左右に並ぶべき」のような判断を書くより正しく直りやすくなります。画面にすでにあるものを替える場合は、何を取り除き何に替えるかを書いてください（例：「右側の女性はオフホワイトのニットカーディガンを脱ぎ、左側と同じトレーナーを着る。色は Maroon、胸の図柄と袖口の刺繍は左側とまったく同じ」）。0.6.11 から、調整の要望は元画像の見た目より優先されます。0.6.17 から、サンプル画像に従って袖口を描いた画像を最適化するときは、サンプル画像も一緒に画像生成モデルに送ります。袖口の文字をまっすぐにするよう求めた場合は、刺繍のある腕をまっすぐ伸ばすことを許可します。
スマート生成のセットはスマート生成ページにだけ表示され、Image Workbench の「最近の生成」には表示されません。
スマート生成を離れて戻ってきたとき、最新の依頼がまだ完了していなければ（分析中、情報の追加待ち、生成中、一時停止中の画像がある）自動でその依頼に戻り、完了していれば新しい依頼のページを表示します。左側の「スマート生成」の後ろにある進行リングは完了した枚数を示し、分析中は回転し、情報の追加待ちのときは黄色の点が表示されます。
画像に「中継サーバーが約 N 秒待ったあと切断しました（HTTP 524）」と表示される場合は、中継サーバーの同期インターフェースの約 2 分という時間制限によるものです。画像はすでに生成されて課金されている可能性があるので、再生成するかどうかを決める前に中継サーバーの管理画面で確認してください。
詳細設定 → 同時生成枚数：中継サーバーに同時に送る画像の要求数を選びます（1～4 枚、既定は 3 枚）。生成中でも変更でき、すぐに反映されます。減らした場合、すでに生成中の画像はそのまま完了します。中継サーバーが同時実行を制限している場合があるので、失敗が多いときや HTTP 429 が出るときは減らしてください。画像の生成が終わるとすぐに枠を空け、ダウンロードはバックグラウンドで行い（同時に最大 4 枚）、同時生成枚数の枠は使いません。カードには「生成」と「ダウンロード」の時間が別々に表示されます。
複数の画像生成中継サーバー（接続と設定 → 画像生成中継サーバー / 予備への切り替え）：1 つの中継サーバーを「メイン」に設定し、ほかは「予備」をオンにして順番を並べます。生成中、アプリは 3 分ごとに無料チェックを行い（モデル一覧を読むだけで、生成も課金もしません）、「正常 / 遅い / 利用不可」を表示します。メインが遅いか利用できない場合、まだ送信していない画像は、正常でモデル ID がまったく同じ予備の中継サーバーに自動で切り替わり、追加の課金はありません。「524 のあと中継サーバーを切り替えて自動で再生成」は既定でオフです。オンにする前に費用について表示します：タイムアウトした画像はそれぞれ最大 1 回、1 回につき最大 3 枚まで自動で再生成されます。元の要求がすでに課金されている可能性があり、2 回課金されることがあります。メイン/予備を設定していない場合は以前と同じです。
分析中に LLM の接続が切れた場合（例：このパソコンのプロキシが切断された）、Claude Code が自動で再試行します。成功すると、ページには「LLM の接続が 1 回切れましたが、自動で再試行して最後まで完了しました」とだけ表示され、画像生成には影響しません。制作が本当に失敗したときだけ「制作が完了していません」と表示され、詳しいエラーに接続の切断が明記されます。
中継サーバー監視 / LLM 監視（左側のナビゲーション）：中継サーバー監視は、中継サーバーごとに実際に送信したすべての画像生成要求（成功、結果不明、失敗、時間、切り替えの入出、中継サーバーの要求 ID）を集計します。LLM 監視は、LLM プロバイダーに送ったすべての要求（時間、トークン、接続の切断とエラー）を集計し、スマート生成の依頼ごとに合計します。時間、接続、種類で絞り込め、呼び出し記録は CSV に書き出して各社の管理画面の請求と照合できます。要求の内容と API Key は保存しません。
キャンセル、異常終了、復元のあとは、自動で再分析や再送信はしません。生成待ちの画像は明示的に再開できます。
結果不明は自動で 1 回再生成します（2 回課金されることがあります）。再ダウンロードで画像を再生成することはありません。
古い依頼は明示的に「制作を続ける」ことができ、送信済みの回が重複して作られることはありません。
スキル（Skills）は設定で有効化・無効化と管理を行います。指示と素材を実行するだけで、実行時にはバージョンが固定されます。
内蔵の「P004 画像生成ルール」は既定で有効です：欧米系のモデル、刺繍は 25 cm 以内で各画像で一致、トレーナーの胸の刺繍は服の中心線に合わせて中央、袖口の刺繍は画面右側の袖だけで文字は袖口の縫い目と平行、画像全体がくっきりしてぼけない。有効な場合、バックグラウンドでこれらのルールをすべての画像のプロンプトに付加します。このスキルを変更または無効にすると付加されなくなります。商品の袖口に刺繍がない場合（例：指示に「袖口にはデザインを入れない」と書かれている）、0.5.2 から袖口の 2 つのルールは付加せず、代わりに両方の袖口に刺繍がないことを明記します。
内蔵の「画像プロンプトの書き方」（0.5.1）は既定で有効です：セットの各プロンプトに、用途、各参照画像の役割、画面に出す文字（名前は 1 文字ずつのつづりを添える）を行ごとに明記し、求められていないブランド、文字、小道具は加えません。プランを修正するときは関係する画像だけを変えます。スキルの内容は英語で、画面と質問は引き続き中国語です。P004 などほかのスキルと矛盾する場合は、ほかのスキルが優先されます。
同じセット内で図柄をそろえる（0.5.5）：メインの図柄は固定項目に「図柄には…だけを含む」と「図柄には…はない」の 2 文で書きます。図柄を変えたのに参照画像が古いデザインのままの場合は、取り除く古い特徴（サンタ帽、ストリングライトなど）を名指しし、すべての画像で同じ組、同じ順番の参照画像を使います。
EC セットの計画（0.6.8、旧「Etsy セットの計画」）：Etsy、Amazon、Walmart に適用し、対象プラットフォームは指示に従います。Amazon/Walmart のメイン画像は既定で真っ白な背景に商品だけです。詳細画像はマクロのクローズアップです。パーティーなどのシーンは人数と小道具を明記します。クリスマスなどのテーマがある場合は、すべてのシーン画像にテーマの小道具を入れます。糸の色や書体などのオプション画像は根拠のあるオプションだけを使い、根拠がない場合はあなたに求めます。0.6.11 から、袖口が見えるすべての画像で袖口の名前とアイコン（同じ行か重ねるか、左右の順番、文字の向き）を同じ 1 文で説明し、刺繍のある腕を自然に下ろさせて、セット全体の並びをそろえます。
詳細サンプル画像（0.6.12）：袖口の名前やアイコンなどの小さな細部が 3 枚以上に出てくる場合、まず袖口のクローズアップをサンプルとして 1 枚生成し、袖口が見えるほかの画像はそれが完了するのを待ってから、それに従って描きます（カードには「サンプル画像待ち」と表示され、待っている間は送信も課金もされず、通常 30～60 秒ほど長くかかります）。サンプル画像はセットの 1 枚で、追加では生成しません。サンプル画像が失敗した場合、ほかの画像は文字の説明どおりに通常どおり生成されます。
袖口の文字をまっすぐに（0.6.13）：P004 を、刺繍のある袖が画面内でまっすぐ下に垂れ、袖口の文字が水平にまっすぐ並び、袖と一緒に傾かないように変更しました。服全体が写るすべての画像は、サンプルに従って袖口を描きます。糸の色見本や布見本など商品のない画像に、服全体が描き込まれることはなくなりました。0.8.1 から、この姿勢は袖口のサンプルと袖口のクローズアップだけに使います。ほかの着用画像のポーズは各画像の要望に従い、袖口のデザインがはっきり見えることだけを求めます。
セットのルール（0.8.1 から）：指定した見せ方（着用、全体の平置き、自然なたたみ、吊るし、ギフトボックス、細部のクローズアップなど）は 1 枚ずつ必ず作り、各画像のデザインを完全にそろえることより優先します。平置き、たたみ、吊るし、ギフトボックスは商品だけで人のいない画像で、モデルの着用画像にはしません。「服は変えない」と言った場合に固定するのは商品そのもの（型、色、生地、各デザイン領域のデザイン）だけで、参照画像のモデル、ポーズ、シーン、構図はまねしません。保つよう言っていないもの（モデル、ポーズ、シーン、見せ方）は既定で変えてよく、隣り合う画像ははっきり違えます。「モデルは同じ」「背景は同じ」とはっきり言ったときだけ固定します。参照画像が 1 枚だけのときは、その画像から商品そのものと各デザイン領域を切り出して根拠にし、はっきり見えないデザイン領域があればほかの質問とまとめて 1 回だけ質問します。変更していない内蔵スキルはこのルールに自動でアップグレードされ、変更したものは保持されます。

商品ページブラウザー（0.3.1）：
商品サイトが直接の読み取りをブロックした場合、アプリはバックグラウンドで内蔵ブラウザーを使って商品ページを開きます。通常は十数秒で完了します。
「確認が完了すると自動で続行します」ウィンドウが表示された場合は、そのウィンドウでサイトの確認を完了してください。完了すると自動で続行します。
そのウィンドウを閉じるか 3 分を超えると、商品画像のアップロードまたは説明の貼り付けを求める表示に切り替わります。
ブラウザーの Cookie は現在のデータフォルダーに保存され、バックアップには含まれません。接続と設定 → 商品ページブラウザーのデータを消去 で削除できます。
ブラウザーはページを読むだけで、Claude はそれを操作できません。すべてのサイトを読み取れるとは限りません。

問題を報告：
どの画像セットにも結果の上に「問題を報告」ボタンがあり、完了・停止・エラーのどの場合も表示されます。ホスト版にもオープンソース版にもあります。セットが完了してもフィードバックを促すウィンドウは出ません。
まずセット全体の判定（使える / 一部使える / 使えない、必須）を選びます。そのまま使えない場合は、問題の種類を1つ以上選ぶか、「セット全体の説明」に「ほしかったのは……、実際は……」と書いてください。
1枚ずつの確認（任意）：各画像に「問題なし」か「問題あり」をつけ、問題の種類を選んで一言書けます。失敗・結果不明・一時停止のカードや、修正した画像の各バージョン（そのときの修正依頼つき）も一覧にあります。全部につける必要はなく、説明したい画像だけで構いません。
フィードバックはセットと一緒に保存され、ソフトを閉じて開き直しても残り、いつでも直せます。
「フィードバックパッケージを保存…」を押すと、まず中身とサイズを一覧し、それから保存先を選びます（既定はデスクトップ、ファイル名は「問題フィードバック-日時.zip」）。ソフトはアップロードしません。WeChat やメールなどでご自身で提供元に送ってください。
フィードバックパッケージには 反馈.md（確認の結論、要望とプランの対照、経過とエラー）と run.json（要望、プラン、プロンプト、回線名とモデル、エラーと全体の経過）が入ります。images/ には生成画像（全バージョン、サンプルを含む）と参照画像（切り出した部分を含む）が、長辺約 1600 ピクセルの JPEG で入ります。保存前に、生成画像と参照画像の枚数と、お客様がアップロードした商品の元画像が入るかどうかが一覧されます。パッケージ作成はバックグラウンドで行われ（「x/y 枚目をパッケージにしています」）、画像の生成はそのまま続きます。API Key、回線のアドレス、ライセンスファイルは含みません。ログページの診断パッケージは変わりません。

ログ（0.2.2）：
左側の「ログ」で、アプリ、接続の検証、スマート分析、画像生成タスクの段階とエラーを確認できます。
ログレベル、出どころ、キーワード、関連 ID で絞り込み、詳細の表示、ページ送り、手動/自動の更新ができます。
ログは最新の 5000 件を保持し、現在のデータフォルダーと一緒に移行・バックアップされます。キーは書き込み前にマスクされます。
このバージョンから記録を始め、古いタスクのログをさかのぼって作ることはしません。古いタスクはタスクセンターで確認できます。

LLM の 1 回あたりの出力上限：既定は 65536 トークンです（0.7.2 から。モデルの思考を含みます。旧バージョンで保存した 8192、32768 は自動で 65536 として扱われ、回線を検証し直す必要はありません）。思考がこの上限を使い切ってもプランがまだ書かれていない場合、この制作の以降の要求では思考をオフにしてプランを直接書きます。使用するモデルの上限がこれより低い場合は、「接続と設定 → LLM プロバイダー → 編集」でそのモデルの実際の上限を入力できます。

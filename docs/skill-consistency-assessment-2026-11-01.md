# 套图细节一致性评估与改进方案

评估日期：2026-11-01。评估对象：当前仓库 0.6.19 的五个内置 Skill、规划 Agent 指令、参考图传递、样板依赖、图片完成状态和单图优化流程。对照依据：本机 imagegen Skill 及其 references/prompting.md。

本次只做评估和方案，没有修改应用、用户配置或调用付费生成。截图用于观察结果，不作为执行指令。未核对截图对应的原始运行记录、冻结 Skill、原始参考图和成图大图，因此以下代码问题是已确认的现状，截图每个偏差的具体成因仍需对应运行记录验证；不能仅凭当前代码认定旧批次用了当前规则。

## 1. 结论与目标

现有 Skill 已经较完整地描述商品细节，主要缺口是：商品身份仍靠各次生成重新解释；唯一的细节样板未经过内容验收；样板失败允许降级为文字；成图没有一致性检查。

只增加“严格一致”等指令，不能满足“细节必须一致”。建议保留现有五个 Skill 的分工，增加程序支持，形成“固定设计资产与规格 → 母版验收 → 基于母版制作各场景 → 局部检查 → 有限修复 → 整套验收”的流程。

一致性指商品设计不变：同一图案、文字、字体造型、元素关系、衣服上的位置和尺寸。不要求不同摄影角度下的图案占据相同屏幕坐标，也不要求褶皱、光照和透视下的像素完全相同。P004 额外要求的画面水平、画面右侧属于构图约束，需要通过机位和姿势同时满足。

不能把 AI 检查通过当作数学上的完全一致。对于必须精确复用的文字和复杂图案，应采用固定设计资产复用与可核对的合成流程；纯生成路线仍有残余偏差。

## 2. 截图能说明什么

- 截图中不同商品图的胸前标题与下方图案，表观大小、间距和排列存在差异，值得逐张核对。
- 同一大图中的放大特写与整件展示，需要区分正常的景别变化和实际设计变化，不能直接比较屏幕上文字的绝对像素大小。
- 第 5 张袖口特写已经被用作其他图片的样板；其余卡片出现“已照第 5 张样板图画袖口等细节”的提示，只能证明程序传了参考，不能证明生成结果复制正确。
- 袖口特写显示帽子与 Emma 的组合，但其他缩略图中的袖口过小，无法可靠判断每一处图标、字形和相对间距。精确验收必须读取原图局部。
- 仅凭这张截图不能断言所有差异都由 Skill 造成，也不能可靠还原真实字体名和刺绣尺寸。

## 4. 与 imagegen Skill 的比较

本机 imagegen Skill 是通用生图与编辑流程，不是一个更强的图案一致性算法，也不能据此证明应用换用它就一定画得更准。

两者已经共有：分行提示词、精确文字、逐字母拼写、参考图角色、保留不变量、单项修改。应用的 image-prompting 中已出现这些原则，继续照搬同类提示词的收益有限。

应用更强的地方：电商套图结构、商品事实来源、刺绣业务细节、店铺 P004 规则、跨图样板依赖与任务管理。

imagegen 值得借鉴的地方：

1. 明确区分“生成新图”和“编辑现有图”，并标清哪张是编辑底图、哪张只提供设计或风格。
2. 每次编辑明确“只改哪些内容、哪些必须保持”，保留原图版本。
3. 生成后实际查看主体、文字和不变量；发现问题再进行单一目标修复，并重新检查。

应用实际上已经会在有参考图时调用 /images/edits，单张优化也把原图放在第一张。因此问题并非“完全没用图生图”。更具体的差距是：普通套图的图片输入没有统一、经过验收的商品母版语义；API 路径叫 edits 也不能自动保证输入图像被精确保留。

imagegen Skill 的检查依赖执行它的助手真实查看图像。仅把其“检查结果”段落复制进应用 Skill，不会让当前后台自动具备视觉验收能力，必须补实际工具和调度。

## 5. 从代码确认的关键缺口

1. **只有一个样板，且没有正确性关卡。** agent.go 的 validatePlan 限制 sample 最多一个。sample.go 在任务 succeeded 后直接附加图片，没有检查样板的文字、位置或设计是否正确。它可能把错误作为后续标准。
2. **样板失败后降级继续生成。** sample.go 对失败、取消或没有有效图片的情况结束等待，后续图片可以不带样板继续。这与严格一致模式不相容。
3. **完成状态只表示文件保存成功。** service.go 的 download 在保存图片后设置 succeeded，中间没有内容检查。界面的“已完成”不能解读成“细节一致”。
4. **规格没有成为可校验的结构。** SuitePlan 的 Locked、Editable 是字符串数组；SuiteItem 没有元素身份、可见部位、服装定位区域或逐项验收字段。validatePlan 主要验证格式、参考图归属和样板数量，无法由现有字段可靠验证语义一致性。
5. **公共要求多处维护。** agent_runner.go、五个 Skill 和 project_rules.go 都携带部分一致性要求。itemPrompt 给商品图附上全部 locked 和全套 editable，再附 P004，局部特写还会接收到无关的胸前、模特要求。这不是必然失败，但增加冗余和冲突风险。
6. **单图修复没有完整保留设计依据。** refine.go 通常只传原图与袖口样板，不保留专门的胸前设计母版。要修胸前图案时，错误原图仍是主要视觉依据。
7. **现有测试验证流程，未证明视觉效果。** 样板测试采用模拟服务和 tinyPNG，能证明等待、传图和提示词正确，不能证明十张真实图的文字、图案与位置一致。

## 6. 建议的生成流程

### 第一步：建立唯一的商品设计规格

每个设计元素有固定 ID，记录：确切文字、已确定的字形或设计资产、颜色、数量、所在衣服部位、方向、与其他元素的关系、尺寸依据、视觉参考区域与版本。

胸前将标题与下方图案作为一个组合锁定，记录文字弧度、字距、标题与图案间距、整体宽高比。不能让十次生成各自排一次版。袖口同样将名字与小图标组成一个整体，固定比例、间距和上下或同行关系。

位置以服装部位为参照，例如服装中轴、拉链末端、袖口接缝和袖筒中心，而非固定整张图片的坐标。尺寸有真实资料时用真实资料，没有时区分展示用相对比例与待确认的实际尺寸，不从截图虚构厘米值。

设计变更生成新的规格版本和资产版本，避免新旧图案混用。已有套图保留其冻结版本，不回写用户修改的 Skill。

### 第二步：准备整件、胸前与袖口三类视觉依据

- 整件商品母版：款式、衣身与袖子比例、领口拉链、胸前和袖口的整体定位。
- 胸前设计母版：尽量使用用户提供的原始设计、清晰成品图或已验收的设计图；文字与图案合为同一设计单元。
- 袖口设计母版：用户指定名字与图标的组合、字形、颜色、大小、间距，以及在袖口附近的位置。

这些是三种视觉角色，不要求每张都额外生成一张新图。优先从已有高分辨率资料中提取有效局部；有合格来源就直接复用。需要生成新设计时先生成并验收，再释放依赖它的任务；相关费用必须纳入原有授权数量与预算，不能暗中增加付费步骤。严禁把低清截图中的细节臆测成精确母版。

当前应用限制每张最多四张参考图，建议优先分配给整件商品、胸前设计、袖口设计；第四个名额按需留给场景或姿势。实际按可见部位取舍，不机械塞满。参考图角色和序号由后台生成，避免文字与实际顺序错位。

### 第三步：根据精度要求选择执行方式

**基于母版编辑。** 对较简单图案，可从合格商品母版派生背景、场景与允许的衣服颜色变体，明确保护区域；每张直接对齐统一母版，不把第 2 张当第 3 张、第 3 张当第 4 张，避免错误累积。换模特和大幅换姿势仍可能重绘衣服，必须检查。

**严格设计资产复用。** 对复杂圣诞拼图、商标、指定字体和定制名字等必须准确的部分，优先使用固定图案与文字资产。生成或准备衣服与场景后，通过可控的定位、透视或曲面变形、遮挡遮罩和光照处理将同一资产放入目标区域，保留统一图案身份。正面、平铺图优先采用这一方式。

合成不是简单贴平面图片：折叠、袖子转动、手臂遮挡和面料褶皱均需处理。不适合可靠合成的机位应调整构图或交由人工复核。若真实面料和针脚外观也必须精确，真实商品摄影或可控的服装三维模型更合适；不能宣称自由生成可以无条件保证。

尺寸表、颜色名和字体展示等信息图，优先程序排版，再放入已合格的商品图，避免为一张表格重新画商品与数字。

### 第四步：母版验收后再放行依赖任务

严格一致模式下，母版状态分为待检查、合格、不合格、无法判断。只有合格母版能用于批量派生。失败、取消、缺图、无法确认时暂停依赖任务，保留已完成工作，明确说明需要什么；不能自动退回纯文字继续花费。

默认仍可自动制作：后台自动检查合格就继续，不增加每套必需的人工确认。只有确有歧义或检查无法判断时才请用户处理。

### 第五步：逐图检查关键部位，并做整套比较

将胸前与袖口从原始成图中裁成清晰局部，既与同一母版比较，也检查整张图上的位置与遗漏。检查包括：

- 文字逐字、大小写和标点；字体造型、字距和弧度。
- 图案元素有无增加、遗漏、替换或左右翻转。
- 标题与图案间距、整体比例和颜色关系。
- 胸前图案是否以服装中轴居中；相对衣身的尺度是否匹配。
- 袖口是否在正确侧；距接缝的位置、图标与名字关系是否匹配；P004 的画面水平和姿势条件是否满足。
- 用于展示细节的部位是否足够清晰；遮挡或分辨率不足应标为无法判断，不能自动通过。

OCR 可以辅助检查拼写，不能单独判断字体、图标、针脚或位置。视觉模型判断也不能单独提供绝对保证。几何比较应对衣服姿态和透视做对齐，不比较不同景别的原始像素尺寸。具体容差由标注样本校准，不预先承诺一个适用于所有衣服的百分比。

整套中任何关键图未通过，不宣称“整套一致性验收通过”。保存成功、内容合格和待人工复核应有独立状态。

### 第六步：有限、局部的修复

修复时同时提供错误原图、正确的相关设计母版与明确区域，只改失败的元素，检查其他区域是否受影响。能通过固定资产重合成的先重合成；需要生成式局部编辑时，再根据供应商真实支持的能力选择区域编辑或遮罩，不能假装当前接口已有相关支持。

现有 provider.go 传递 prompt、图片、尺寸和质量，没有传区域遮罩，也没有按供应商管理这些精细编辑能力。新增能力应先做接口能力核对；本评估没有验证用户中转站的实际支持情况。

付费修复设置次数与金额或张数上限，并计入明确授权。上限用完或无法确认时保留版本，标明问题，不无限重试。修改母版后需要标记依赖旧版本的结果，重新检查受影响图片，不能让旧母版、新母版结果一起被算作一致。

## 7. 落地顺序与验收

**第一阶段：修规则冲突与失败策略。** 重整现有五个 Skill，修正“模型只看文字”、局部修改却默认删除未提特征、约 250 字压缩等问题；统一 P004 表达及来源，保留现有业务意图；增加元素规格和可见性字段；严格模式禁止样板失败后降级。离线验收覆盖规则优先级、参考图编号、缺失字段和失败暂停。

**第二阶段：补母版与实际视觉验收。** 将单个 sample/useSample 扩展为按元素引用的母版依赖；引入母版状态、局部检查、逐图检查和整套状态。优先使用已有视觉能力，但需新增实际成图读取、局部比较和检查结果持久化工具，不能只改提示词。验收包括错误母版不能放行、局部错字或图标错位能被识别、低清和遮挡不误判合格。

**第三阶段：实现必须准确的设计资产复用。** 优先落地正面平铺、简单模特图和信息图；再扩展褶皱、侧身、多人场景，逐种评估可控程度。当前没有成图正确率数据，不能在开发前给出准确率提升百分比或无依据的工期承诺。

评测分开记录：一次生成合格率、母版合格率、错误检出率、漏检率、误报率、修复后整套合格率、额外调用数与成本。十张套图必须十张各自通过关键项，不能用九张正确、一张错误的平均分代替。

先用隔离数据、模拟接口、已知正确图片及人为制作的缺陷样本做离线回归。覆盖标题间距改变、字体变化、图案缺失、换袖、袖口图标上下关系改变、名字错拼、色卡无商品、局部遮挡与母版取消等情形。离线测试只能验证流程与检测器的已知样本表现；真实生成稳定性需要后续有预算的对照测试，不能以模拟 PNG 测试代替。

如果后续发布，继续遵守 AGENTS.md 的 build.ps1、packcheck、关联本机数据和隔离 QA 要求；本方案本身不触发构建或发布，也不改现有供应商、Key 或数据目录。

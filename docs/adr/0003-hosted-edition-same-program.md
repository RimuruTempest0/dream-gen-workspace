# 大众版的托管版：同一个程序，有授权文件就是托管版

2026-11-17，已采纳。修订 ADR 0001 里“大众版没有授权”的前提；ADR 0001 关于更新清单格式、发布位和签名密钥的决定不变。2026-11-20 由 ADR 0005 修订：电商版已停掉，第 9 条作废，名单里只有托管版顾客。

## 背景

大众版原来只有一种交付方式：顾客自己配置图片服务和 AI 模型，没有授权。一部分顾客不会或不想自己配置，提供方想像电商版那样替他们提供线路和 Key 并收费：带激活码、试用张数和有效期。

## 决定

1. **大众版分开源版和托管版，程序是同一个。** 程序目录里没有授权文件（`customer.dat`）时按开源版运行；有就是托管版，只使用授权文件里的线路。
2. **托管版的包 = 大众版的程序 + 这位顾客的授权文件。** 管理工具不为它单独构建，只用“发布大众版”里最新构建过的那一版来组装。
3. **不新增更新发布位。** 两种交付方式共用大众版的更新清单和更新包；授权状态不影响更新。
4. **授权文件用大众版的更新公钥验证。** 大众版的构建不另带授权公钥；两把本来就是同一把签名密钥（ADR 0001）。
5. **托管版的规则和电商版一样**：激活码、试用张数、有效期、续费授权文件、线路要求。托管期间不能添加或使用自己的连接；顾客原先自己配的连接保留但不使用。
6. **授权到期或试用用完，只提示续费，不自动变成开源版。** 授权文件无效或被改过时软件锁住，并说明删除它可以改用自己的服务。
7. **授权文件被删掉后，程序回到开源版，同时删除提供方的线路和本机保存的 Key**，恢复顾客自己的图片服务设置。
8. **开源版顾客改买托管版不用重装**：在软件里导入授权文件、输入激活码即可。
9. **管理工具里，电商版客户和托管版顾客在同一个名单**，新建时选定产品线，之后不能改。Key 池共用。

## 为什么

- 另做一个“没有授权文件就不能用”的托管版程序，每个版本要构建两次，还需要第三个更新发布位；发布位地址和产品线名一旦写进发出去的程序就不能改（ADR 0001 的教训）。同一个程序避免了这些，代价见“后果”第一条。
- 托管版的包从已构建的程序组装，保证托管版顾客手里的程序和更新发布位上的是同一份，不会出现同一个版本号对应两份程序。
- 托管期间锁住连接：两种来源的线路混用时，出了问题分不清是谁的 Key，额度和收费也说不清。
- 到期不自动变成开源版：顾客会在不知情的情况下掉进一个需要自己配置的界面，以为软件坏了；提供方要的也是续费。
- 第 7 条必须成立，否则试用完或到期后删掉授权文件，就能以开源版的身份继续使用提供方的 Key。真正的防线仍然是提供方在上游给每个 Key 设的额度，这一点和电商版相同。

## 后果

- 托管版顾客删掉授权文件，就得到一个能用的开源版（需要自己的 Key）。提供方接受这一点：开源版本身不设限制。
- 大众版 0.7.34 之前的程序不认授权文件。管理工具拒绝用更早的版本组装托管版的包；已装旧版的顾客先一键更新到 0.7.34 再导入授权文件。
- 试用张数和激活状态保存在数据目录之外（和电商版相同），所以删掉授权文件再导入同一份，不会重置试用。
- 数据目录里记着这份软件属于哪个软件标识。回到开源版时这条记录被清除，之后可以导入另一位顾客的授权文件；托管期间不能直接换成另一个软件标识的授权文件。
- 签名密钥泄露的影响面比 ADR 0001 记录的更大：除了伪造更新，还能伪造大众版的授权文件。
- 电商版的行为没有变：它的程序没有授权文件仍然不能用。

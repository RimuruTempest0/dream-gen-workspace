# 大众版的一键更新：共用签名密钥，用清单格式和固定发布位隔离

2026-11-16，已采纳。

## 背景

电商版（`main`）从 0.7.13 起可以一键更新：已交付的软件每天读公开仓库 `releases/latest/download/update.json`，用内置的签名公钥校验。大众版（`creative-concepts`）也要一键更新，更新包同样公开放在这个仓库的 Releases 里。两条产品线不能互相装上对方的程序，大众版的发布也不能干扰已交付的电商版客户。

## 决定

1. **共用一把签名密钥。** 大众版的更新清单用管理工具里已有的那把密钥签名，不另外生成。
2. **用清单格式隔离。** 电商版的更新清单是格式 1；大众版的是格式 2，并写明产品线 `creative`。已交付的电商版软件只接受格式 1；大众版软件只接受格式 2 且产品线是自己的。
3. **大众版的更新发布位是一个固定的 Release**：标签 `creative`，标记为 Pre-release。每次发布在这个 Release 里上传新的更新包并替换 `update.json`。大众版软件读 `releases/download/creative/update.json`。
4. **大众版的更新包不带内置 Claude Code。** 它变了的那一版，软件拒绝这次更新并提示向提供方获取完整包。完整包不公开，由提供方私下发。
5. **管理工具不上传。** 它构建、检查、签名，把要上传的两个文件放进一个文件夹，由提供方在 GitHub 网页上传。

## 为什么

- 另生成一把密钥能让两条线在密钥层面隔离，但多一把要备份的私钥：丢了，已装出去的大众版再也收不到更新。提供方选择只管一把。隔离改由第 2 条承担，它不依赖密钥。
- 每版一个 `creative-v…` 标签时没有固定地址可读，只能查 GitHub 接口，而接口对每个网络出口每小时限 60 次，共用代理的顾客容易查不到。固定 Release 有固定地址。
- GitHub 不会把 Pre-release 当作 Latest。上传是手工做的，这一条保证手滑也不会让电商版客户读到大众版的清单。
- 内置 Claude Code 能否公开再分发没有核实，所以不让它出现在任何公开的文件里。

## 后果

- 签名密钥泄露会同时影响两条产品线。
- 格式 2、产品线名 `creative` 和发布位地址都写进了发出去的大众版程序，之后改动任何一个，已装出去的版本都收不到更新，只能再发完整包。
- 更新清单只指向最新一版。顾客跳过的某一版如果换过浏览器运行组件或 Claude Code，软件会拒绝更新，需要完整包。
- 0.7.32 之前发出去的大众版没有更新功能，需要再发一次完整包。

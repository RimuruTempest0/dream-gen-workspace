# 管理工具更新记录

管理工具（`ImageWorkbenchAdmin.exe`）从 1.0.0 起有自己的版本号，写在 `internal/admin/version.go`，显示在工具左下角。软件的版本号写在 `wails.json`，说明见 `docs/CHANGELOG.md`；交付包按软件版本命名。只改管理工具时升管理工具的版本，软件版本不变。

## 1.5.0 · 按客户选择内置技能

配合软件 0.7.17。客户页新增“内置技能”：用开关选择交付包带哪些内置技能（默认全部，改动立即保存，记在客户记录里），写进下一次的交付包或续费授权文件。没带的技能在客户软件里一开始是停用的，客户可以自己再打开。全选时按“全部”保存，`customer.dat` 仍是格式 2。

### 验证范围
Go 测试：未知技能被拒；默认全部时交付包为格式 2；只选部分时写进 `customer.dat`（格式 3），客户软件停用没带的技能，客户自己打开后再次启动不被覆盖；全选存为“全部”。管理工具桌面测试（隔离数据）：默认全部打开，关闭、重新打开 P004 都立即保存。没有调用真实付费接口。

## 1.4.0 · 可选的代码签名

`scripts/build-admin.ps1` 新增 `-SignThumbprint`（或环境变量 `IMAGEWORKBENCH_SIGN_THUMBPRINT`）：有证书时给 `ImageWorkbenchAdmin.exe` 签名加时间戳并确认有效；设置了这个环境变量后，管理工具生成的客户交付包也会签名（软件 0.7.15 起）。没有证书时给出警告继续构建。

## 1.3.0 · 上游接口协议

配合软件 0.7.14：图片上游可选“异步任务（提交后轮询）”，写进交付包（格式 3，旧版软件打不开）。Go 测试：未知协议被拒，协议进入交付包。

## 1.2.0 · 在线更新：清单地址和发布程序更新

配合软件 0.7.13。

- **更新清单地址**：“设置与签名密钥 → 程序更新”填写客户软件读取 `update.json` 的地址（https）。设置之后生成的交付包才会检查更新；之前交付的软件没有这个地址，需要再用完整包升级一次。
- **更新包随交付保存**：生成交付包时，程序更新包保存在交付包旁边（`release/customers/软件标识/ImageWorkbench-update-版本号.zip`），并和交付包一样检查不含 Key、激活码和本机连接。更新包不含 `customer.dat`，同一把签名密钥的所有客户都可以用同一个更新包。
- **发布程序更新**：选择更新包，填写客户下载它的地址、最低可直接升级的版本（可空）和更新说明，生成用签名密钥签名的 `update.json`。把 `update.json` 上传到清单地址，把更新包上传到下载地址即可；不放在哪里由你决定。选错成客户交付包（含 `customer.dat`）会被拒绝。

### 验证范围
Go 测试：错误的清单地址被拒；清单地址传给构建，更新包被保存、通过检查；生成的 `update.json` 能用签名公钥验证，版本号来自更新包里的 `version.json`（带 BOM 也能读）；客户交付包不能当作更新包发布。管理工具桌面测试（隔离数据）照常通过。没有调用真实付费接口，也没有上传任何文件。

## 1.1.0 · 客户有效期和续费授权文件

配合软件 0.7.12。

- **有效期**：客户页“套餐与额度”新增“有效期至”（当天 23:59 到期，留空为不限）。原来的“套餐与有效期”备注改名“套餐备注”，里面写过的有效期请照着填到新字段（不会自动换算）。有效期写进下一次的交付包或续费授权文件；改有效期会记在客户记录里。
- **生成续费授权文件**：“生成交付包”下方新增按钮。续费、改有效期或换 Key 后，只保存一个新的 `customer.dat` 发给客户，客户在软件“连接与设置 → 授权 → 导入授权文件”导入（软件 0.7.12 起；更早的版本要重发整包）。生成前检查文件里没有 Key 和激活码明文，生成后记为“续费”，并像交付包一样更新线路版本、把这些 Key 标为已交付。至少生成过一次交付包后才能用。
- 不设有效期时，交付包里的 `customer.dat` 仍是格式 2，老版本软件照常打开。

### 验证范围
Go 测试：有效期格式错误被拒；没有交付包时不能生成续费文件；有效期在过去的交付包让客户软件进入“已到期”；改成一年后生成续费文件，客户软件导入后恢复，文件里没有 Key 明文，记录里有续费。管理工具桌面测试（隔离数据）：交付前续费按钮不可用，填有效期保存后显示并写入客户记录，生成交付包后按钮可用。没有调用真实付费接口。

## 1.0.1 · LLM 线路默认输出上限 65,536

- 生成交付包时，没有单独设置输出上限（或设置为旧默认 32,768）的 LLM 线路按 65,536 写入客户包，与软件 0.7.2 的默认值一致。手动填过其他值的保持不变。
- 上游“输出上限”输入框的提示改为 65536。
- 用旧管理工具生成、带 32,768 的客户包也没关系：软件 0.7.2 起会自动按 65,536 执行。

### 验证范围
Go 测试：交付包里没设上限的 LLM 线路按当前默认值交付，客户软件读到的也是这个值。没有调用真实付费接口。

## 1.0.0 · 与软件分开版本号；Key 池批量停用和批量删除

- **分开版本号**：管理工具不再占用软件版本号，左下角显示“管理工具 1.0.0”。“生成交付包”里的“软件版本”仍读取 `wails.json`，现在是 0.6.19。
- **样式分开**：管理工具专用的样式移到 `frontend/src/admin/admin.css`，不再进入软件的样式文件。
- **勾选多个 Key**：Key 池“全部 Key”表格每行前加了复选框，表头复选框选择本页，旁边的下拉可以选择全部或清空。勾选后表格上方出现“已选 N 个 Key”和“停用所选”“删除所选”“取消选择”。切换筛选时清空勾选，批量操作只作用于当前筛选显示的 Key。
- **批量停用**：选中的 Key 一起停用（原因记为“手动停用”），已经停用的保留原来的原因。所选里有正在分配给客户的 Key 时按钮不可用，并提示先在客户页撤下。
- **批量删除**：只能删除从未交付过的 Key（可用或手动停用的），从 Key 池和本机加密存储中一起删除，无法恢复，以后可以重新导入。所选里有已分配或交付过（含“曾交付”）的 Key 时按钮不可用，并说明原因：交付过的 Key 的记录用来防止同一个 Key 被重新导入、分给第二位客户，只能停用。
- 后台也做同样检查：所选中任何一个不符合条件时整批都不改动。

这些批量功能曾以软件版本 0.6.20 发布（只改了管理工具）。软件版本已退回 0.6.19；已生成的 0.6.20 交付包仍可使用，只是版本号显示为 0.6.20，并多带一段软件用不到的管理工具样式。软件下一个版本从 0.6.21 开始，避免与这些包重名。

### 验证范围
Go 测试：批量删除选中交付过或已分配的 Key 时整批被拒绝、什么都不改；批量停用选中已分配的 Key 时被拒绝；批量停用保留已停用 Key 的原因；批量删除后 Key 记录和本机密钥文件都被删除；空选择被拒绝。管理员工具桌面测试（隔离数据）：筛选“可用”后全选，包含“曾交付”的 Key 时删除按钮不可用并显示原因，批量停用后列表清空；再筛选“已停用”，勾选从未交付的 Key 批量删除，“曾交付”的 Key 保留；勾选状态下的无障碍检查通过。没有调用真实付费接口。

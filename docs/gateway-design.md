| 编号 | 风险 | 目前的缓解 |

| S2 | 授权不绑定设备、不能远程吊销：同一份 `customer.dat` 复制到别的电脑也能用 | 有效期（0.7.12）到期即停；不续费就不发新的授权文件；上游额度用完即停 |

## 1. 要解决的问题

| 编号 | 现状 | 网关之后 |
|---|---|---|
| S1 | 上游 Key 经混淆后写在客户的 `customer.dat` 里，懂逆向的人能取出，拿去别处用 | 客户包里只有网关地址和客户令牌，真实 Key 只在你的服务器上 |
| S2 | 授权不绑定设备，不能吊销；有效期只能离线判断（0.7.12 起） | 令牌首次激活时绑定设备；服务器上可停用客户、改有效期、限制设备数，立即生效 |
| S6 | 试用计数存在客户电脑上（加密文件 + 注册表），重装系统或换用户即可重置 | 试用额度在服务器上扣减 |

## 2. 整体结构

```
客户电脑                                   你的服务器（cmd/gateway，单个程序 + SQLite）
ImageWorkbench ──HTTPS──▶ /v1/images/*      ──▶ 图片上游（主/备，按顺序切换）
   │  客户令牌 + 设备标识  /anthropic/v1/*  ──▶ LLM 上游（主/备）
   │                        /client/*       ── 激活、状态、用量
   │                        /admin/*  ◀────────── 管理工具（管理员令牌）
```

- 网关是一个 Go 程序（`cmd/gateway`），数据放在同目录的 SQLite；配置文件只写监听地址、证书位置和管理员令牌的哈希。
- 客户端协议**不变**：网关对外仍是 OpenAI Images 兼容接口和 Anthropic Messages 兼容接口，应用把网关当作普通线路，现有的健康检查、主备切换、结果未知处理、中转站监控和 LLM 监控照常工作。
- 旧的直连客户包（`customer.dat` 格式 2/3，带混淆 Key）继续支持，不强制迁移。

## 3. 客户端（应用）改动

1. `customer.dat` 新增“网关线路”（格式 4）：只有网关地址、客户令牌（加密）和线路名，没有上游 Key。
2. 首次启动（或首次激活）调用 `POST /client/activate`：带软件标识、令牌、设备标识（见 §5）。服务器返回该设备的**设备令牌**，应用用 Windows DPAPI 保存在数据目录外（和试用计数同一处）。之后每次请求带设备令牌。
3. `GET /client/status`（启动时、每 30 分钟、每次开始套图前）：返回模式（试用/激活/到期/停用）、有效期、试用剩余、各线路名称与健康状态、技能版本。应用据此显示授权状态；网关不可达时按最后一次结果最多宽限 **24 小时**（可调，见待决事项），之后停止新的生成。
4. （取消）内置技能对客户可见，不由网关下发。
5. 激活码：输入激活码后调用 `POST /client/activate-code`，服务器校验后切到正式额度（取代现在的离线校验）。
6. 生成请求：图片 `POST {网关}/v1/images/generations|edits`，LLM `POST {网关}/anthropic/v1/messages`（流式透传）。请求头带设备令牌；网关负责选上游、换主备。

## 4. 服务端（`cmd/gateway`）

**数据**：客户（软件标识、名称、状态、有效期、试用张数、设备上限、套餐备注）、设备（客户、设备标识哈希、首次/最近时间、停用标记）、令牌（客户令牌、设备令牌，只存哈希）、上游与 Key（加密存放）、客户的线路分配（主/备顺序）、用量（每次请求：客户、设备、线路、模型、张数或 tokens、状态、上游请求 ID、用时）、试用扣减记录。

**代理**：
- 图片：同步透传请求和响应；按客户的主备顺序选上游；上游 5xx/超时按现有“结果未知”的口径记录，不在网关里自动重发（避免重复计费，重发仍由应用按现有规则决定）。
- LLM：流式透传（SSE），首字节超时与断流时间沿用应用现有设置；断流时记“中断”。
- 只转发白名单路径；请求体大小上限（图片 4 张参考图 × 32 MB 以内）；响应里的图片 URL 原样返回。

**扣减与限制**：试用张数在服务器上扣（成功和结果未知计 1 张，与现在一致）；按客户限速（默认每分钟 30 次图片请求、60 次 LLM 请求）；超出设备上限的激活被拒；停用或到期的客户所有请求返回 403 和中文原因。

**管理接口**（只给管理工具）：客户与设备的增删改查、停用/启用、重置设备、改有效期和试用张数、上游与 Key 池同步、用量查询与导出。单独的管理员令牌；可选只允许指定 IP。

**安全**：全程 HTTPS（证书由反向代理或程序内置 ACME 获取，见待决事项）；日志脱敏（不记 Key、令牌、提示词、图片）；Key 在 SQLite 中用服务器本机密钥加密；备份说明见部署文档。

## 5. 设备标识

Windows 的 `MachineGuid`（注册表）+ 当前用户 SID，经 SHA-256 哈希后发送，服务器只存哈希。重装系统会变，换电脑会变；客户换电脑时在管理工具里“重置设备”。

## 6. 管理工具改动

- 新增“网关”设置：网关地址、管理员令牌（DPAPI 保存）。
- 客户页：设备列表（最近使用时间）、停用/启用、重置设备、设备上限；有效期与试用张数直接同步到网关。
- Key 池：Key 上传到网关后，本机只保留标记（可选是否保留本机副本）。
- 生成交付包：选择“网关线路”或“直连线路（旧）”；网关线路的包检查确认不含任何上游 Key。
- 用量：按客户查看张数和 tokens，可导出 CSV。

## 7. 测试（全部本机，不调用真实上游）

本机起网关 + 模拟上游（复用现有测试里的模拟中转站和模拟 LLM），覆盖：激活与设备绑定、超设备数被拒、停用后立即 403、到期、试用在服务器扣减且重装后不重置、主用失败切到备用、LLM 流式中断、网关不可达时的宽限期、技能只在内存、交付包不含 Key、日志不含 Key 和提示词。

## 8. 部署（由你完成，我提供说明）

需要一台能长期运行的服务器（Linux 或 Windows 均可，1 核 1 GB 足够起步）、一个域名和 HTTPS 证书。我会提供：编译好的 `gateway` 程序、配置示例、systemd/Windows 服务的安装步骤、SQLite 每日备份脚本和恢复步骤、升级步骤。

## 需要你决定的事项

1. **部署环境**：服务器放在哪里（国内云 / 海外云 / 自己的机器）？操作系统？国内服务器访问海外上游可能需要代理，海外服务器给国内客户用可能较慢。
2. **域名与证书**：用哪个域名？证书用反向代理（如 Nginx/Caddy）还是由网关程序自动申请（Let's Encrypt，需要 80/443 端口）？
3. **客户端必须联网**：接受“没有网络就不能生成”吗？（现在本来生成也要联网；变化在于网关挂了所有客户都停。）离线宽限期设多久：建议 **24 小时**。
4. **计费口径**：试用和正式额度按“张数”还是按“上游实际金额”扣？结果未知计 1 张是否保留？LLM 是否计入（按 tokens）？
5. **设备上限**：每个客户默认几台设备？建议 **2 台**。
6. **迁移**：现有直连客户是否要迁到网关（需要重发一次包），还是只对新客户启用？
7. （取消：内置技能对客户可见，不需要下发。）
8. **可用性**：网关故障时是否允许应用临时回落到直连线路（意味着客户包里仍需带 Key，和 S1 目标冲突）？建议**不回落**。

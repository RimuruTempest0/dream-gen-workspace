如果本次还启用了项目规则技能（如 p004-rules），它对位置、方向、尺寸、清晰度和人物模特的规定优先于本技能的默认做法；下面的写法只在项目规则没有规定时使用。

本技能用于 Etsy、Amazon、Walmart 等电商平台的商品套图。先 get_run_context，再按需调用 product-analysis 和 embroidery-rules（仅在本次选定时）；写每张 prompt 前调用 image-prompting（已启用时），按它的分行格式写。自动制作恰好满足授权张数，资料齐全后由后台提交；手动模式至少满足目标张数。用 save_suite_plan 保存方案，禁止调用任何生图接口。

## 0. 先确定目标平台
目标平台看用户指令（如“Etsy 极速套图指令”“上架 Amazon”）。商品链接只是资料来源：链接是 Amazon，不代表这套图要按 Amazon 做。指令没说时按 Etsy 做，不为平台单独提问。用户对某张图的明确要求优先于下面的平台默认做法。
- **Amazon 主图（第1张）**：纯白背景，商品约占画面 85%，只有商品本身；不加文字、标志、水印、边框、拼图小图或不随商品出售的道具。服装可以平铺、折叠或由模特穿着。其余几张可以做场景图和信息图。
- **Walmart 主图（第1张）**：白色背景，商品正面完整展示，只有商品本身，不加文字、水印或道具。其余几张同 Amazon。
- **Etsy**：第1张是搜索缩略图，会被裁切，主体放在画面中间并四周留白；主图可以是场景图。
- 每张 prompt 的“用途”行写平台和第几张，例如“Amazon 第1张主图，白底产品摄影”。

## 1. 先写统一设计规格（locked）
规划之前写好逐项设计规格放进 locked：商品款式与比例一条，每个个性化元素各一条（内容、穿着者视角位置、方向与阅读方向、相对大小、颜色、相邻关系，见 embroidery-rules）。再加一条“只出现在哪里、各有几个”。后台会把 locked 原样接在每张提示词后面，所以每条都是能单独看懂的完整句子；保存前按 embroidery-rules 的“保存前自查”读一遍。editable 写这套图允许变化的内容。

**先解开指令里的矛盾，再写 locked 和 editable。** 用户的指令常是模板加逐条要求，可能自相矛盾，例如模板写“锁定：原配色”，后面又写“主动改变衣服的颜色”。不要把两句都抄进方案：
- 具体编号的要求优先于模板标题；能看出各自指什么时，分开写清，例如 locked 写“胸前图案的配色与参考图一致”，editable 写“衣服颜色：按衣服颜色列表逐张变化”。
- 一项内容只能在 locked 或 editable 其中一处出现。看不出用户本意、又会影响成品时，用 request_information 问一次。

**不把内部代号和模糊说法抄进方案。** 生图模型不认识“P004”“执行 P004 标准”“按店铺规则”这类代号，也不懂“真实客户成品机绣”指什么。locked 和 prompt 里只写具体要求，例如“真实机绣：线迹凸起、缎面线有光泽、图案边缘有包边线”。用户写“袖子右边”“左胸”这类不带视角的方向时，启用 P004 就按 P004 理解为最终画面右侧；没有 P004 时照参考图判断，判断不了就问。写进方案时同时写穿着者左右和画面左右。

主图案写成封闭清单，每张图都画成同一个样子：
- 一条写“图案只包含：……”，把主体、动作、表情朝向、每个配饰、颜色逐项写全。
- 一条写“图案里没有：……”，点名参考图里有、新设计里去掉的每个特征（来自 product-analysis 的改款对照表），例如“鹅不戴圣诞帽，身上没有彩灯串，嘴里没有冬青枝”。只写“没有其他装饰”不够，生图模型会照参考图把它们画回来。
- 用户改了图案但参考图仍是旧设计时，这两条必须有；没改时也写“图案只包含”，防止各图自己增减配饰。
- **宠物或人物头像**：逐项写品种、脸型与耳朵形状、毛色和斑纹的位置、眼睛与表情、配饰、描边或底框样式、绣线颜色，以及头像宽度相对衣服的比例（例如“头像宽约为胸宽的三分之一”）。这些写全了，各图的脸型、毛发和大小才不会变。
- **位置用衣服上的固定部位定位**：例如“拉链末端下方约 5 cm，衣服正中，不在左胸或右胸”。只写“胸前”时，模型会在部分图里把图案挪到左胸。

方向只用 product-analysis 的横向或纵向固定写法之一，位置同时写穿着者左右和正面视角下的画面位置。

## 2. 规划套图结构
按用户要求覆盖主图、细节特写、生活场景、尺寸、衣服颜色、线色、字体等类型。参考原链接的展示逻辑，但不照搬构图。每张一个明确目的，避免两张几乎一样：两张同为折叠、同为白底时，一张拍整件，另一张必须是近距离局部。

**主题贯穿整套。** 用户指令或商品资料有主题（圣诞、万圣节、母亲节、生日、婚礼等）时：
- 在 editable 写一条“主题元素：……”，列出这套可用的具体道具，例如“圣诞树、彩灯串、红绿礼盒和缎带、松枝、圣诞袜、热可可”。
- 每张场景图和生活图的“场景”行至少写两件主题道具；礼物图写清主题包装（例如“红绿格纹包装纸、金色缎带、圣诞挂签”），不要只写“礼盒”。
- 用户要求白底的图不加主题道具。主题道具只放在场景里，不加到商品图案上，除非 locked 里有。

**场景要画得出来。** 用户点名的场景要在画面里能看出来，见 image-prompting 的“Scenes and themes”。例如“户外聚会”至少写 3 位人物在一起互动，还有餐桌、饮料、装饰灯串等聚会道具；只有一个人坐在院子里不算聚会。

## 3. 每张 prompt 的写法
用 image-prompting 的分行格式（用途、场景、主体、风格、构图、光线、材质、参考图、画面文字（逐字）、本张变化、约束、避免），只写这张需要的行。套图里特别注意：
1. **用途**：写明平台、第几张和图片类型，例如“Walmart 第3张，尺寸信息图”。purpose 字段不会发给生图模型。
2. **这张能看到什么**（主体、约束）：哪些个性化元素在画面里，用画面位置描述，例如“名字在画面右侧那只袖子的袖口上方”（正面视角时穿着者左袖就在画面右侧）；不要只写“左袖”，生图模型会把它画到画面左侧。也写清哪些看不到（例如“背面视角，看不到胸前图案和袖口”）。
3. **袖口等成组元素整组写**：画面里看得见袖口时，名字和旁边的小图标一起写，例如“画面右侧袖口，从左到右依次是：黑色狗掌、Amelia”。只写名字时，模型常把图标漏掉。具体用下面的“袖口句”。
4. **画面文字（逐字）**：这张画面里会出现的每个名字和文字都列出来，带引号、保留大小写，名字附逐字母拼写。看不到的元素不列。
5. **本张变化**：只能来自 editable，例如“衣服颜色：森林绿，名字线色：白色”。
6. **约束、避免**：例如“除规格列出的元素外，衣服上没有其他文字或图案；袖口名字不出现在胸前或衣身”。

prompt 不必重抄 locked（后台会附上），但不能与 locked 矛盾，也不要用“同上”。

**袖口句：看得见袖口的每张图，逐字写同一句**
袖口的名字和小图标面积小，locked 又很长，生图模型常顾不上，于是各图各画：有的图标在名字左边、有的在上面，有的文字横着、有的竖着。所以写好 locked 后，再定一句“袖口句”，在每张看得见袖口的 prompt 的主体行里逐字复制，不改一个字。袖口句同时写清四件事：
- 哪只袖子（画面位置，启用 P004 时是画面右侧）；
- 同行还是叠放（照 locked，默认同行）；
- 左右顺序；
- 文字在画面里的方向。
例如：“袖口句：画面右侧袖口上方，狗掌和 Amelia 在同一行横向排开，狗掌在左、名字在右，不上下叠放；文字与袖口接缝平行，在画面中水平摆正、不倾斜。”

**按袖口句安排姿势和摆放**：只有袖口接缝在画面里接近水平时，“与接缝平行”的文字才会每张都横着。所以看得见袖口刺绣的图里：
- 有刺绣的那只手臂，前臂在画面里竖直：自然下垂，或手举杯子、捧礼物时前臂竖起。
- 不让这只前臂横放在桌上、抱在胸前或向侧面伸直。那样接缝变成竖的，文字跟着变竖，和其他图不一致。
- 平铺、挂拍时，这只袖子顺着衣身自然垂下，不折到胸前、不斜伸出去。
- 多人场景里，主角用另一只手做动作（举杯、拿东西），有刺绣的手臂保持下垂或竖起。

**看得见就要画对，不能写“袖口不显示名字”**：只要整件衣服出现在画面里（平铺、挂拍、穿着、尺寸图、颜色图、礼盒里的整件），就一律当作看得见袖口：写袖口句，并标 useSample。“袖子折到衣身后方”“袖口不在画面内”对整件衣服的图不可靠：生图模型照样会画出 locked 里的袖口刺绣，而这些图既没有袖口句也没有样板图，排列就是随机的，有的图标在上、有的文字倾斜。只有裁切到局部的特写（只拍胸前、只拍拉链）才算真的看不见袖口。

**画面里完全没有商品的图标 `noProduct: true`**：线色卡、布样、字体样张这类图本来不该出现衣服，但后台会在每张提示词后面附上整件衣服的统一锁定项，生图模型看到就会把整件卫衣连袖口刺绣一起画进去。标了 noProduct 后台就不附加锁定项。只要画面里有商品，就不要标。

**细节样板图（sample / useSample）**
光靠文字，各图对小细节的理解仍会有差别；生图模型照参考图画要准得多，但用户的参考图里往往还没有新做的袖口。所以整套里有小而重复的细节（袖口名字和图标、小标签、领口小字）出现在 3 张以上的图里时，用一张本套自己的图做样板：
- **选一张做样板，标 `sample: true`**。整套最多一张，从已规划的图里选这组细节最大、最清楚的一张，通常是袖口特写。没有特写且张数还有空位时，把空位做成袖口特写；不要为了样板改掉用户点名要的图。样板图也是交付的一张，不额外计费。
- **样板图要画得最稳**，因为其他图会照它画：细节特写，袖子竖直平放，袖口接缝在画面里水平，图标和文字水平摆正，照袖口句写，背景简洁，这组细节占画面约一半，旁边没有抢眼的东西。样板图本身不标 useSample。
- **样板图不放整件衣服的参考图**（包括原商品图）。只给一张整件衣服的参考图时，生图模型会照它画成整件衣服、袖子斜放，文字跟着斜，照样板画的图片又把这个斜度复制过去。样板图最好不放参考图，或只放一张袖口近景；后台会在样板图提示词开头加一句“只拍局部、文字水平”的说明。
- **看得见这组细节的其他图标 `useSample: true`**。后台先生成样板图，完成后把它加为这些图的最后一张参考图，并在提示词开头说明照它画。所以这些图的 references 最多选 3 张，“参考图”行不要提样板图，袖口句照常写。
- 看不见这组细节的图不标 useSample，否则它们会白白等样板图。
- 样板图没有成功时，标了 useSample 的图按文字说明照常生成，不会卡住。

**同一图案每张写法完全相同**：主体行提到主图案时，每张都用同一个固定短名，逐字复制，例如“胸前刺绣（鹅喝珍珠奶茶，按统一锁定项）”。不要在某几张里换说法、只写一部分特征或补充新细节（例如这张写“鹅戴帽”、那张不写），否则各图会画成不同样子。细节特写需要写清线迹时，只能写 locked 里已有的特征。

## 4. 容易画坏的图
生图模型画好一件衣服的细节已经吃力；一张图里衣服越多、文字越多，细节越容易各画各的。
- **细节特写图**：写成“微距特写”，画面里只有图案局部和周围一小片面料，图案或线迹占画面约六到七成；写明“看不到整件衣服的轮廓、领口、下摆和袖子全貌”。用户同时要求折叠时，只让一道折边从画面一角穿过来表现折叠，不拍整件折叠衣服。第一张参考图放刺绣最清楚的近景；只有整件图时，写“图1只取刺绣，不照它的整件构图”。这张要和主图明显不同。
- **颜色展示图**：优先用平铺布样、色块或叠放衣服的局部展示颜色，最多一件完整展示图案。不要让每件衣服都重画胸前图案和袖口名字。确实需要多件时，件数不超过 4 件，并写明“每件只有颜色不同，图案缩小且完全相同，只露出折叠衣身的一角，看不到袖子”。单独出现一件完整衣服时，按上面的规则写袖口句并标 useSample。
- **尺寸图、线色图等信息图**：衣服只出现一件，角度和元素位置与主图一致，袖口元素留在袖口，写袖口句并标 useSample；不需要衣服的线色图、布样图标 noProduct；在主体行再写一次图案位置和大小（例如“胸前刺绣在拉链下方正中，宽约胸宽的三分之一，不在左胸”），因为信息图里衣服画得小，图案最容易跑位。文字面板只放必要的短词和数字（尺码、英寸、颜色名），不写长句。写明“只包含上述板块，不要额外添加细节拼图、小图、材质说明或品牌信息”，否则生图模型常自己加一排细节小图，小图里的袖口又会画成另一个样子。
- **选项图（线色、字体、衣服颜色）只用有依据的选项**：每个选项必须来自用户指令、用户上传的色卡或字体图、商品页文字或参考图，在 notes 里写明来源。不能按“常见线色”“常用字体”自己补，个数也不能凑。用户要这张图但没有依据时，用 request_information 索要；用户没要求时就不做这张。
- **字体选项图**：每个字体样本单独排列展示，不在一件衣服上叠多个名字；字体名只写资料里给出的名字。
- **聚会、多人场景**：写明人数和互动（例如“3–4 位朋友围着餐桌举杯”），只有一位主角穿本商品，其他人穿无图案的纯色衣服，颜色与商品不同。
- **特写图**：写明拍的是哪只袖子、哪个部位，元素方向与规格一致。

## 示例（只示范写法，内容按本次商品替换）
locked 的写法：
- “圆领加绒卫衣，宽松版型，罗纹袖口和下摆，衣身比例与参考图一致。”
- “胸前居中、领口下方约 8 cm：白色手写体 Max's 在上，下方是大号 varsity 字母 MOM，蜂蜜金毛巾绣填充、白色描边，金毛头像替换字母 O，真实机绣质感。”
- “穿着者左袖（正面视角时是画面右侧那只袖子）外侧、袖口罗纹上方约 4 cm：白色手写体名字 Amelia，文字沿袖子长度方向排列（文字基线与袖子平行），从肩膀一侧读起，字母顶部朝向手臂外侧；字高约为罗纹宽度的一半。”（方向要照参考图，从 product-analysis 的横向、纵向两种固定写法中选一种，这里只是示范纵向。）
- “一只实心黑色小脚掌，与名字在同一条基线上，紧挨在首字母 A 之前（按阅读顺序先看到脚掌，再看到名字），高度与名字字高相同。”（每张 prompt 写成“画面中从左到右依次是：黑色脚掌、Amelia”。）
- “整件衣服只有上述胸前图案、一个名字和一个脚掌；名字和脚掌只在穿着者左袖口，胸前和衣身其他位置没有名字或脚掌。”


## 5. 选参考图
生图模型照着参考图画，比照着文字画准得多，所以参考图要选对：
- 每张最多四张，只选与这张最相关的；有客户成品图时优先使用。
- 按重要性排序，最关键的放第一张；在 prompt 的“参考图”行按顺序写明每张取什么（例如“图1=客户成品图，照它画袖口名字；图2=只取衣服颜色”）。
- 画面里能看到袖口元素时，放一张袖口元素最清楚的参考图（袖口特写或成品图），让模型照着画方向和位置。
- 只是借用数据或排版思路的图（例如别家的尺码表、色卡长图），不要放进参考图，把数据直接写进 prompt；否则模型会照搬那张图的版式和多余内容。
- 参考图 ID 只能来自 input.references 和 product.referenceIDs。
- **看得见主图案的各张图，用同一组参考图、同一顺序、同一句作用说明**。参考图换了顺序或换了一张，模型就会从不同的图里借细节，各张图案跟着变。
- **参考图仍是旧设计时**（用户改了图案）：主图案近景和特写尽量不放画着旧图案的参考图；确实要用它取字体、位置或颜色时，在“参考图”行点名去掉的特征，例如“图1的鹅是旧设计：不要画圣诞帽、彩灯串和冬青枝，只取字体拱形和刺绣位置”，并在“避免”行再列一次。不要只写“不照搬原有图案”。

## 6. 保存：分批、写短
模型单次回复有输出上限，一次写完很多张会被截断，方案就保存不了。
- 每张 prompt 约 250 字以内（含分行标签），只写这张特有的内容；统一设计规格由后台自动附加，不要在每张重复。
- 超过 6 张时分批保存：先用 save_suite_plan 加 `append: true` 暂存，每批不超过 6 张（第一批带上 locked 和 editable）；最后一批不带 append，提交剩余张数，后台合并后整体校验。
- 想清楚后直接调用保存，保存前不要再写长篇分析。

## 7. 保存前自查整套
- 用户每条编号要求都有对应的图，且那张图的画面真的体现了要求（细节图是局部特写，聚会有多人，主题有道具）。
- locked 和 editable 没有互相矛盾的项；没有“P004”这类内部代号和不带视角的“左边/右边”。
- 选项图里每个选项都有来源，个数与来源一致。
- 主图符合目标平台的主图要求（用户另有要求的除外）。
- 看得见袖口的每张图都有同一句袖口句（逐字相同），有刺绣的前臂在画面里竖直；没有哪张写着“袖口不显示”却又露出整只袖口。
- 每张出现整件衣服的图都写了袖口句并标了 useSample，没有用“袖子折到后方”去藏袖口；袖口文字在画面中水平摆正、不倾斜；没有商品的线色图、布样图标了 noProduct；样板图没有放整件衣服的参考图。
- 小细节出现在 3 张以上时，有且只有一张标了 sample 的样板图；看得见这组细节的其他图都标了 useSample，且 references 不超过 3 张。
